# Navigation

History, pins, latched sync, recursive find, bookmarks, path-picker rows and remote (SFTP) paths. See [panels.md](panels.md) for panel state and suffix marks, [preview.md](preview.md) for quick view, [keybindings.md](keybindings.md) for binding rules.

## Directory history

- `App.navigatePanelToDirectory(panelID, path, selectedName)` centralizes `NavigateTo` with `panelViewportRows`; bookmarks (`activateBookmarkSelection`), the history picker (`activateHistorySelection`), `panel.open-dir-in-other` and `panel.open-active-path-in-other` use it.
- Each panel keeps `History` (most recent first) and `HistoryIndex`. Normal navigation (`NavigateTo`, `nav.open`, Parent, bookmarks, selected-strip open, history picker) records; back/forward move only the pointer and `Load` without re-recording. Every distinct visit is kept (MRU, cap 200); only the abandoned forward branch is dropped when navigating after going back.
- `HistoryForward`/`HistoryBackward` return `(moved, warning, err)`. Local candidates are pre-checked with `panel.DirectoryExists` and skipped if gone; `sftp://` entries are not pre-checked. `warning` is set whenever entries were skipped; `nav.forward`/`nav.backward` (`internal/app/panels.go`) surface it as a warning toast.
- `nav.open` on a directory calls `panel.State.Enter`, which also follows a symlink resolving to a directory (`localfs.Entry.ResolvesToDir`: one `os.Stat`, only on this keypress, never during listing/paint) and navigates into the symlink path. Non-directory and broken symlinks fall through to file handling (runnable execution: [commands.md](commands.md); else `xdg-open` per `open_files_externally`). Remote panels never execute locally.
- **Highlight memory**: leaving a directory saves the highlighted entry (name, row, absolute path); re-entry by history, pickers, find jump, dedup/compare, SFTP or Enter restores and centers it. Parent selects the exited directory. After chdir, scroll math uses the live row count `panel.State.FileListViewportRows` (wired from `App.panelViewportRows`/`ui.FileListViewportRows`), so a selected-strip layout change doesn't leave a stale viewport. Snapshots prune with history (cap 200). Tree mode also restores expansion, re-fetching contents fresh; the absolute path disambiguates nested rows (see [panels.md](panels.md)).
- **Keys**: `nav.forward`, `nav.backward` and `panel.history-dialog`. Ctrl+H arrives as Backspace in many terminals and collides with `nav.parent`.
- **History dialog**: targets the active panel (`panel.history-dialog`) or the panel of Left/Right -> History. Fuzzy filter via `search.Parse`/`Rank` (respects `Filter.CaseInsensitive`); the target panel's current directory (`HistoryDialogState.CurrentPath`) is left out of every list (history, merged, zoxide) by `rebuildHistoryDialogPaths`, and the first row starts selected. Enter/OK navigates; Esc/Cancel closes. `panel.history-both-panels` (`[dialog.history]`) toggles target-only vs merged passive-then-active (`panel.MergeNavigationHistories`). No history shows "No directory history yet" and does not open. Opening also runs `zoxide.List` (`internal/zoxide`: `zoxide query --list` when the binary is on `PATH`; db at `$_ZO_DATA_DIR/db.zo` or `~/.local/share/zoxide/db.zo`) on a goroutine; `historyZoxidePayload` -> `App.applyHistoryZoxide` stores `HistoryDialogState.Zoxide` and, only when zoxide is installed, sets `ZoxideAvailable`, which shows the **Include zoxide** checkbox under the query (`IncludeZoxide`, starts from `[history].zoxide`; `dialog.HistoryZoxideMnemonic` toggles it; from the query it leaves focus there, from elsewhere it focuses the checkbox). The dialog is a `dlg` spec (`HistoryDialogView`, `App.historyView`, `App.handleHistoryDialogKey`): `HistoryDialogState.Focus` is `HistoryFilter` (empty = the query, which also drives the path list `HistoryList`), `HistoryZoxide` (when shown), `dlg.OK` or `dlg.Cancel`; Tab/Backtab step query -> checkbox -> button strip, Up/Down/PgUp/PgDn/Ctrl+Home/Ctrl+End in the query move the list, Space/Enter on the checkbox toggle it, Enter in the query or on OK opens the row. The checkbox row appears without touching the focus. `rebuildHistoryDialogPaths` (also used by `panel.history-both-panels`) appends the zoxide directories not already in the history, in score order, and records `ZoxideFrom`; every row starts with a source prefix: `[icons.dialog] zoxide` for those rows, `[icons.dialog] history` for panel history (the list row `Icon`, painted in the option-row foreground). Marks (pinned / job / missing) follow the row text (`MarksAfterText`). List height: `dialog.HistoryDialogListRows` (render and `App.historyDialogListRows`); an overflowing list draws the list scrollbar on the right border in the `PanelScrollbar` style (the Pin and Bookmarks / path picker dialogs do the same). `internal/app` `TestMain` points `_ZO_DATA_DIR` at an empty dir. Missing rows render `dialog.option.invalid` via `HistoryDialogState.PathMissing` (`internal/ui/dialog/state_picker_history_meta_help.go`): opening or reassigning `Paths` resets it and starts `dialogctrl.StartPathsMissingScan` (off-thread `Lstat`, `sftp://` skipped), applied by `App.applyHistoryDialogMissing` from `PathsMissingPayload`, guarded by `App.historyMissingGen`. Cursor highlight beats invalid styling, so missing rows also carry a trailing `RowMarks.Missing` icon (`[icons.dialog] missing`), same in the path picker and Pin dialog.

Render: `internal/ui/dialog/pin_dialog_render.go`; logic: `internal/apphandler/pin/dialog.go`.
- Menu-bar badge: `drawMenuBarPinBadge` (`internal/ui/menu_bar_pin.go`) at the start of the jobs-strip gap (shrinks the jobs strip; hidden at zero). Row icon: `[icons] pin` with `panel.row.mark.pinned`; see [panels.md](panels.md).

## Latched panel sync

- `panel.toggle-sync` latches the active panel as driver; cursor moves on the driver mirror the highlighted directory into the other panel. Only one driver; toggling on the other panel transfers the role. `panel.switch` doesn't change the driver, and the non-driver panel's moves aren't synced. A non-directory cursor is a no-op. Quick view and sync are mutually exclusive. `panel.open-dir-in-other` / `panel.open-active-path-in-other` disable sync when they navigate the inactive panel.
- Sync uses `panel.State.Load` (not `NavigateTo`), so the follower's history is untouched.
- Reconciled once per loop in `App.reconcileAfterEvent()` (except while a debounced follower load is pending), so any code path that changes the highlighted directory triggers it without call-site wiring.
- Indicator: ` Sync -> ` / ` <- Sync ` on the bottom End edge via `panel.status.sync`; hidden when chrome is blocked.
- **Debounce**: `[ui].key_repeat_debounce_ms` coalesces repeated `nav.up/down/page-up/page-down/top/bottom` file-list steps; deferred work (follower load, quick view, carousel child preview, fullscreen-preview style-picker re-highlight) runs once after the quiet gap or immediately on any other key/resize/toggle. `0` restores per-event behavior. Selected-strip navigation isn't debounced.
- `[ui].image_preview_debounce_ms` replaces it for quick view and carousel side preview when the target is an image/media file (`localfs.IsMediaPath`), since those decode and re-emit sixel/Kitty payloads. `preview.Handler.previewDebounceDelay` is the only selection point (`quickViewWantFile`, `carouselFilePreviewWantPath`; directory carousel listings keep the key-repeat delay). `key_repeat_debounce_ms <= 0` still short-circuits everything. `file.view` fullscreen and `find.view` are never debounced.
- Options -> Calibrate Debounce (`app.open-menu` -> Options -> D): two digit-only inputs (`DebounceCalibrateView`, edited by `handleDebounceCalibrateInputKey`), OK / Calibrate (Alt+L) / Cancel. Calibrate times 8 repeat-interval samples on the first field (initial press-to-repeat ignored; early release fails), average + 10 ms margin. OK writes both keys in one `[ui]` patch.

## Find (recursive, panel)

**UI / coordinator separation (do not regress).** Find indexing runs on a dedicated **scan coordinator goroutine** plus **walk workers**; the main thread only touches `FindDialogState`, updated from **`scan.Event`** payloads via `findctrl.Handler.PollUpdates`. The coordinator owns the authoritative corpus in `internal/scan`; the dialog keeps a **UI mirror** (`FindDialogState.Entries`, `IndexedCount`, `RankDisplayLines`, rank caches) fed **only** by events.

- Do not call `scan.Coordinator` lookup APIs (`EntryAt`, `Snapshot`, ...) from the UI thread, render, or synchronous rank/select helpers. Do not block the main thread on coordinator command channels (`<-done` in `SetIncludeHidden`, `Restart`, `NarrowSelection`, ...).
- Push incremental UI state on events: `BatchAdded` appends to `Entries`; `ReplacedEntries` replaces after narrow/strip/finish; `MatchResult` supplies `Ranked`/`RankDisplayLines`/`FullRanked`.
- Run fuzzy match on a **snapshot copy** in the coordinator/match worker (brief index lock, then work off-copy); a read lock across a full match stalls walk ingestion.
- Rows paint from `RankDisplayLines` (filter active) else `FindEntryAt` -> `Entries`; with an empty filter, rows show walk-order preview capped by `find_max_results`.
- Map: coordinator and walks `internal/scan/coordinator.go`; event wiring `internal/apphandler/find/coordinator_handler.go`; state `internal/ui/dialog/state_picker_history_meta_help.go`; wake via `WakePayload`/`RankWakePayload` in `internal/app/app.go` `Run()`.

Behavior:
- `panel.find-dialog` (active panel; Left/Right -> Find uses that panel) roots at the target panel path. The walk is breadth-first; directory reads within a level run concurrently under `fswalk.Adaptive` (`[fs_walk]`) and results are consumed in level order (`rootWalk.runBFS`, `internal/scan/walk.go`: all depth-1 entries, then depth-2, ..., flushing the batch at the end of every level so shallow results show at once; `rootWalk.Progress()` exposes the level depth and dirs read/total, `scan.Event` carries `Depth`/`LevelDone`/`LevelTotal` (max-depth aggregate across roots) into `FindDialogState`, and `findDialogTitle` renders `<[icons.dialog] depth> N · P%` plus the scanning icon) and never stats sizes (`Size` 0). `PathMeta` (`lookupFindPathMeta`) answers from `Entries` only; marked-file sizes fill in a generation-keyed background pass (`scheduleFindMarkedFileSizes`) applied via `RankWakePayload`; directory totals come from the disk-usage engine. `IndexFinished` does not bulk-replace the mirror. Title and list repaints share one throttle that loosens with index size (batches and include-hidden expansion alike). Matching is on paths relative to the root (same `internal/search` subset as the quick filter).
- **Max depth**: `FindDialogState.MaxDepth` (committed, 0 = unlimited, starts unlimited each open) and `DepthInput` (edit buffer, one digit 1-9) back an input on the query row (`dialog.FindDepth`; width `findDialogDepthFieldWidth` (depth icon + three input cells) plus `findDialogDepthGap`; the query grows into the rest of the row, and `Handler.queryWidth` reads the query's scroll width from the placed spec, `dlg.InputTextWidth`). Entry depth is the number of `/`-separated segments of `RelLine`; `StartOpts.MaxDepth` is relative to `DisplayRoot`, and walks rooted below it (selection roots, hidden-expanded dirs) get `MaxDepth` minus their own depth (`session.walkMaxDepth`) and are skipped when nothing is left. `rootWalk.runBFS` stops before a level past its atomic limit; `ingestBatch`/`ingestHiddenBatch` drop deeper entries from in-flight batches. `Handler.commitFindDepth` runs on a digit, 0, Backspace or Delete (each also returns focus to the query), on leaving the field (Tab/Backtab/Up/Down/Left) and on Enter (which returns focus to the query): a tighter limit calls `Coordinator.SetMaxDepth` (lowers running walks, prunes the index via `ReplaceEntries` + `IndexReplaced`, as `narrowSelection` does); a looser or cleared limit calls `restartFindIndexer`. Focus is a `dlg.ID` and the widgets come from `dialog.FindDialogView` (`dialogs.md`): query, depth, Only dirs, Only files, Include hidden, Stay on volume, optional selections, OK, Cancel; jump mode leaves the two radios out of the spec, so no focus move can reach them.
- **Stay on current volume** (default on, Alt+V): honors the `disk_usage_descend_into_mount_points` rule; toggling restarts the walk.
- **Include hidden** (default off, Alt+I): the first walk skips dotnames but records skipped directory and file paths (location only); enabling splices pending files in batches and walks pending directories without a re-index. Hidden-subtree walks are concurrency-capped by index size so `$HOME` can't spawn hundreds. Disabling strips them but keeps the pending list. Independent of panel ShowHidden.
- **Only directories** (Alt+D) / **Only files** (Alt+L): radio pair filtering the ranked list without re-walking. Row-1 options move with Left/Right. `ui.input.forward-word` stays text editing in the filter.
- **Search only from selected directories** (shown only when directories are selected; default on, Alt+S): nested roots pruned. Unchecking widens incrementally (keeps hits, skips indexed subtrees); re-checking filters to scope and cancels out-of-scope walks. Each selected root's walk ignores gitignore even if the root is ignored; gitignore resumes once the walk widens. Alt+S never moves focus off the filter.
- **Marking**: `panel.select-toggle` uses `panel.ClearSelectionConflicts` (descendant/ancestor removal; **Removed conflicting selections** toast). Bulk operations use the `Entries` mirror and `panel.ApplySelectionAdds` (no per-mark coordinator calls): `find.select-all` (full filtered corpus, beyond `find_max_results`), `find.select-group`/`find.unselect-group`, `find.unselect-all`. Marked results show a selection-size indicator on the separator (`FindDialogState.MarkedSelectionSizeLabel`, `Theme.DialogIndicatorSelectionSizeStyle`; file sizes from the index, directories via `reconcileFindDialogSelectionSizeScans` on the disk-usage engine).
- `find.view` opens the highlighted file in the fullscreen viewer and closes Find (a directory shows "View: not a file" and keeps Find open). `find.select-parent-dirs` (footer from `findDialogOverlayFooterKeys`, `internal/app/input.go`) replaces the target selection with the unique parent directories of marked results (or the cursor row's parent); `panel.State.ParentDirsExcludingSelf` (`internal/panel/selection_parent_dirs.go`, `pathloc`-based) drops the panel's own cwd, showing "Already in the containing directory" when nothing remains; the merge is `BulkAddSelections`. See [panels.md](panels.md) for the shared selection primitives.
- **OK/Enter**: marked rows merge into the target selection; otherwise navigate (directory -> path, file -> parent with the file selected). `ui.open-primary`/`ui.open-secondary` open the result in a panel **without closing**; because the dialog's fast path (`paintFindDialogOverlay`) never repaints panels, `App.handleKey`'s `InputModeFindDialog` case compares both panel paths before and after and forces a full `render()` when either changed. Esc/Cancel cancels the walk and discards the index.

### Jump to directory (Find in jump mode)

- `panel.jump-dialog` (Left/Right -> "Jump to directory" uses that panel) calls `find.Handler.OpenJumpDialog`, which shares `openDialog` with `OpenDialog` and sets `FindDialogState.JumpMode` and `OnlyDirectories`. `StartOpts.DirsOnly` makes the shared breadth-first walk skip files (never indexed or recorded as skipped hidden). The flag flows through `findStartOpts` -> `session.startWalk`, so the Include hidden replay walks are directories-only too.
- Title "Jump to directory". Hidden/disabled: selection scope option (no `SelectionDirRoots`), Only dirs/files radios (`applyFindToggle` ignores them; Tab/arrow focus steps past the radios), marking (`panel.select-toggle`), select/unselect all and group, `find.select-parent-dirs`, `find.view` (`RunAction` swallows them) and the marked-selection label. The footer (`findDialogOverlayFooterKeys(keys, jumpMode)`) lists only Open ◄/►. Kept: filter, Include hidden (Alt+I), Stay on volume (Alt+V), Enter/OK navigates (always a cd), `ui.open-primary`/`ui.open-secondary`, `panel.pin-toggle`, Esc.

## Remote paths (SFTP)

- `pathloc.Parse` accepts `sftp://user@host/path`; `IsRemote()` is true for any non-`file` scheme; `SFTPEndpoint`/`SFTPRemotePath`/`SFTPHostPart` serve the backend and pool. `/~` and `/~/subdir` are client-side home markers (`SFTPRemotePath` uses `~`, expanded to the server path only at list/copy time); explicit `/` is filesystem root.
- **Pool** (`internal/fsbackend/sftp`): keyed by `user@host:port`; idle disconnect (`[sftp].idle_timeout_secs`) is not applied while `pooledConn.inUse()` (`activeOps`/`activeStreams` > 0). `ReadDir`, `Lstat`, mutations and stream-open take an operation lease; a successful open converts it into the `activeStreams` lease under one lock. Transport errors evict that exact pooled client; reads (List/Stat/ReadSymlink/OpenRead) may retry once on a new dial, mutations never replay; context errors aren't transport failures. The handshake uses a conn deadline plus `ctx` abort (close TCP, wait for `NewClientConn` to avoid a goroutine leak). A stalled `ReadDir` is canceled via `ReadDirContext`, then by closing the session. Timeouts and `known_hosts_file`: `[sftp]` in `docs/config.md`.
- **Auth order** (OpenSSH-style): `IdentityFile` from the matching `ssh_config` stanza (lookup by URI alias and resolved `HostName`; `%h`/`%r`/`%d` expanded), then ssh-agent (probed with `List`/`Signers`: `SSH_AUTH_SOCK`, stanza `IdentityAgent`, newest `/tmp/ssh-*/agent.*`, `~/.ssh/agent.sock`, `/run/user/$UID/keyring/ssh` last because stale keyring sockets are skipped; signers keep the Unix connection open until the handshake ends; a dead agent is skipped), then default `~/.ssh/id_*` only when the stanza has no `IdentityFile` and not `IdentitiesOnly yes`. A password dialog follows only after a pubkey-only handshake fails (TCP redial). Encrypted on-disk keys are skipped (use the agent).
- **Prompts**: host-key and password waits are serialized per App (`promptSem`), id-tagged, completed only by the owner, and `select` on the dial context so cancel posts a dismiss through the open-payload path. The password prompt is a `dlg` file dialog (`FileDialogSFTPPassword`: a `Password for user@host:` label and one input, OK / Cancel); OK and Enter answer the waiter, and Esc / Alt+C / `CloseFileDialog` call `Host.CancelSFTPPassword`. Host-key dialog: Accept (session), Save (append OpenSSH-normalized host, including non-22 ports, and reload the verifier in-process), Reject (Alt+A / Alt+S / Alt+R).
- **Connect dialog**: `remote.sftp-link` (Left/Right -> SFTP..., menu `T`) lists `Host` entries from `[sftp].ssh_config_file`, else `SSH_CONFIG`, else `~/.ssh/config` (`Include` globs expanded) with the shared fuzzy filter, plus a manual Location. Enter on a host fills `sftp://.../~`. The dialog is a `dlg` spec (`dialog.SFTPConnectView`, `dialogs.md`): the filter input (`SFTPFilter`) drives the host list (`SFTPHosts`, a driven list), so Up/Down/PgUp/PgDn and Ctrl+Home/Ctrl+End move the host cursor while the filter keeps focus, Tab goes to `SFTPLocation` and then the OK / Cancel strip, and `syncSFTPConnectDialogRanks` re-ranks on every filter edit. With no matching host Down moves focus on to the location. The host list shows `SFTPConnectListRows` rows (3 to 12, by terminal height). Dialing merges all stanzas for the alias (first-wins per keyword): `HostName`, `User`, `Port`, `IdentityFile`. `Host`/`Match host` wildcards match at connect time; `!` negations stay on the stanza and `MatchesHost`/`MatchesEndpoint` reject on any negated hit; space-separated patterns only (no comma `Match host`). Two `Host *` stanzas with different exclusions stay distinct. Panel URIs keep the alias; resolution happens at connect. `startSFTPConnect` stamps a per-panel generation and `applySFTPConnect` drops stale payloads, so a slow connect A can't overwrite B (panels connect independently). Failed dials append an `ssh config`/`matched=N` hint.
- **Remote panel**: list/enter/parent/refresh work; volume, disk usage and gitignore are disabled. Listings run in a goroutine and apply via `remotePanelLoadPayload` so `ReadDir` never blocks `PollEvent`; `[sftp].list_timeout_secs` bounds them and stale results drop when navigation moved on.
- **Remote transfers**: `file.copy`/`file.move` queue background jobs for local<->remote and remote<->remote (same host). `ops` streams through `fsbackend.OpenRead`/`OpenWrite` when backends differ; local<->local keeps `localfs.CopyFile`/FICLONE. Disk-space blockers run only for local destinations; CoW is off when any path is remote. Remote mkdir/rename/delete use the backend; chmod/chown/symlink/hardlink are blocked. Foreground remote mkdir/rename (plan + execute) and transfer/extract/flatten destination probes (`Stat`/`Mkdir`/`Rename`/flatten `List`/`CollectFlattenSources`) run on a worker and apply via generation-tagged `dialogctrl.RemoteFileOpPayload` (`handleEarlyInterruptPayload` -> `ApplyRemoteFileOp`) so an expired connection's password dialog can be delivered. Batch chmod/chown plan on the caller then run via `RemoteFileOpAttr`. Destination validation accepts `sftp://` (backend `Stat`, already off-thread). Remote symlinks in copy plans are skipped. `fsbackend.Backend.OpenRead` returns an `io.ReadSeekCloser` (SFTP: the remote file inside the stream-lease wrapper), so offset reads such as find-duplicates chunk hashing seek instead of downloading the prefix.
