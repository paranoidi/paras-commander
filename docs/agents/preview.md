# File preview and quick view

User-facing behavior lives in `docs/` (see `docs/graphics.md` for images). This file records code pointers, invariants and gotchas. The reasoning behind the terminal-graphics design is in [terminal-graphics.md](terminal-graphics.md).

Related: [panels.md](panels.md) (async navigation, scroll indicators), [navigation.md](navigation.md) (Pin dialog, Calibrate Debounce), [keybindings.md](keybindings.md), [theming.md](theming.md).

## Preview gate

- `localfs.CheckFilePreviewable` classifies by extension without sniffing: `ErrFilePreviewImage` (`localfs.IsImagePath`), `ErrFilePreviewAudioVideo` (`localfs.IsAudioVideoPath`), `ErrFilePreviewArchive` (`archive.ListableName`). Otherwise it stats and reads `PreviewSniffBytes`; a NUL byte yields a one-line message, no subprocess. The check is NUL-only, so legacy-codepage text stays previewable. Every surface (`file.view` / quick view / carousel / CLI single-file open) accepts all three typed errors.
- Zero-byte files are skipped by inactive-column quick view only (`quickViewWantEmpty`); explicit `file.view` still opens them. `quickViewWantFile` classifies a selected-strip highlight from `SelectedDirPaths`, then listing type/size; an off-listing strip row counts as a file without `Stat` on the UI goroutine.
- The gate (`dispatchFilePreviewCheck`) runs off the UI goroutine on every surface: quick view (`dispatchQuickViewFilePreview`), carousel (`dispatchCarouselFilePreview`), fullscreen (`OpenFullscreenFilePreviewAt`, reached from `file.view`, `find.view` and the Pin dialog's `pin.view` via `ViewSelected`). The caller opens the **Pending** placeholder synchronously, then the background dispatch resolves to a real run or an in-pane message. The only synchronous gate is CLI startup (`internal/app/startup_paths.go`), before the event loop exists.
- Each surface has its own run-generation counter (`filePreviewRunGen`, `fullscreenFilePreviewRunGen`, `carouselFilePreviewRunGen`) so a slow superseded check cannot clobber newer content. `beginPreviewRun` bumps the generation *before* canceling the previous run; close, empty-file, reload and style refresh use `cancelPreviewRun` the same way.

## Quick view

- **Directory overlay**: a directory highlight (file-list cursor or strip row) loads into a transient `Model.QuickViewDirOverlay` painted on the inactive column, resolved via `syncFollowTargetPath` (no history). If the inactive panel already lists that directory the overlay clones the live listing and cursor; otherwise it loads through async `panel.State.Load` (`LoadWithViewport`, same timeout race and `panel.PathProbes` as normal navigation, see [panels.md](panels.md)). The restore cursor is computed up front by `panel.PreviewCursorRecall` so the async load lands on the right entry. There is no synchronous first frame; highlighting a directory never blocks the UI.
- **Stale-while-revalidate**: `initQuickViewDirOverlayFromFollower` keeps the previous overlay rows (`CloneListingFrom`) painted while the new listing loads; the inactive title's end label shows `ListingPendingPath`. A failed/timed-out load clears the held rows (`applyPanelAsyncLoad`, overlay branch).
- **Slow indicator**: every dispatch (`applyQuickViewPreviewNow`, `dispatchQuickViewDirPreview`, async overlay load) arms `Handler.quickViewSlow` (`sched.Debouncer`, delay `panel.LoadingIndicatorDelay`, shared with the panels' working icon). On fire, `QuickViewSlowPayload` -> `ApplyQuickViewSlow` sets `Model.QuickViewSlowPath` and, for an overlay, drops the held stale rows. `Model.QuickViewSlowRowPath(panelID)` gates on the load still pending, so the indicator self-clears; the driver row painter receives it as `PanelContext.WorkingRowPath` (set at all three `PanelContext` construction sites: `drawBrowserPanel` and both `paintBrowserPanelsInScope` sides). Synchronous outcomes call `clearQuickViewSlowIndicator`.
- The inactive panel's real path, cursor, selection and open indicator stay unchanged until quick view is disabled. `FilePreview` stays closed for a directory overlay. After filesystem mutations `dialogctrl.Handler.RefreshBothPanels` (`internal/apphandler/dialog/file_ops.go`) re-syncs quick view to the driver's highlight.
- **Mutual exclusion**: enabling quick view while panel sync is latched disables sync (warn toast), and vice versa. Only one bottom indicator shows.
- **Driver indicators**: the driver panel's bottom border shows ` Quick view -> ` / ` <- Quick view ` (`panel.status.quick_view`) even when focus is on the other panel. While `Model.QuickViewDisplayActive()`, the cursor row paints a one-cell arrow (U+E0B0 right / U+E0B2 left) over the border facing the preview. `quickViewIndicatorSide` (`internal/ui/render.go`) decides the side from the swap-aware rect X positions (not logical Primary/Secondary). The icon colour is the cursor row's resolved background as foreground; there is no theme key.
  - Wiring: `PanelContext.QuickViewIndicator`/`QuickViewIndicatorRight`, drawn by `drawPanelQuickViewIndicator` at the end of `drawPanel`, *after* `drawPanelListScrollbar` (the scrollbar repaints that border column). Both `PanelContext` builders must set it: `drawBrowserView`/`drawBrowserPanel` and `paintBrowserPanelsInScope` (`render_disk_usage_partial.go`, also used by `PaintBrowserListNavPanelOnly` for the single-panel nav repaint under key repeat). Missing the second makes the arrow vanish only while a key is held.
- **Title row**: in quick view the inactive title keeps the real inactive path at the start and shows the previewed filename/directory basename at the end; free-space stats are hidden.
- **Debounce**: `[ui].key_repeat_debounce_ms` coalesces file-list highlight changes (file-list `nav.*` keys also arm input-path coalesce); `0` runs immediately. *Heavy* targets (media via `localfs.IsMediaPath`, or a path matched by a `[[preview.commands]]` rule via `previewrun.MatchAnyCommandRule`) use `[ui].media_preview_debounce_ms` instead. Text files always use the key-repeat value. `Handler.debounceDelay` is the single picker; `Handler.mediaPreviewDebounce` decides heavy vs. not. The `preview.theme-picker` re-highlight always uses the media delay; `file.view` open is never debounced. Both values are edited in Options -> Calibrate Debounce.
  - Opening from closed is special on quick view and carousel: `Handler.patchFilePreviewPending` paints the Pending title synchronously while the body still waits out the debounce (`ReconcileQuickViewPreview` / `ReconcileCarouselFilePreview` fall back to immediate apply when the delay is `0`).
- **Focus**: with quick view latched, `panel.switch` only swaps the active panel and the inactive preview hides until focus returns to the driver. With quick view off, `panel.switch` cycles file list -> selected strip -> inactive preview, then back to the active list; arrows/paging scroll `FilePreview.Scroll` while the preview has focus. While quick view shows a scrollable preview, `file.quick-view.preview-page-up/down` page it (a directory overlay is paged instead, without moving the driver's highlight; with nothing scrollable they page the active list).
- **Zoom**: while `FilePreview.Open` or quick view paints, `panel.toggle-zoom-active-panel` is a no-op and layout is an even 50/50 split so width matches argv expansion (`App.layoutForTerminalSize`, `Model.PanelZoomEnabled`). The same split applies at/above `[ui].zoom_active_panel_disabled_above_width` (when > 0).

## Preview state, paint and commands

- **State ownership**: `Model.FilePreview` / `Model.FullscreenFilePreview` belong to `internal/apphandler/preview` and are mutated under the shared `App.commandsMu` (`Deps.Mu`, same lock as `Model.CommandsList`) so `App.render`'s whole-`Model` snapshot copy stays race-free. `renderBrowserListNavUpdate` and `paintDiskUsageBrowserUpdate` take the same `RLock` copy. `App.render` calls `previewCtrl.SnapshotPreviewDrawStates()` to fill `FilePreviewDraw` / `FullscreenFilePreviewDraw`.
- **Clamp via wake**: a finished run posts `PreviewClampPayload` instead of clamping scroll itself, because clamping reads layout only the main goroutine may touch (`App.handlePreviewInterruptPayload` -> `ApplyPreviewClamp`, then render). `RenderWakePayload` is the data-free repaint wake.
- **Stale-while-revalidate**: while a new run is pending/running, the draw snapshot keeps the previous completed body and shows the new filename with a `...` suffix; only the first preview on an empty pane shows Loading. Carousel child preview uses the same hold.
- **Paint**: the inactive column uses `drawFilePreviewPanel`; fullscreen uses it over `MergeTwinPanelRects` (`ui.ViewFilePreview`). In internal mode, border/box-drawing cells tint from the active Chroma style's `Background` via `chromaformat.FrameStyleFromChroma` (`Model.PreviewChromaStyle` snapshot in `App.render`); inner surface, title text and padding stay on app-theme chrome. Blocked chrome (menu/modal) and external mode use theme frame colours only. Scroll indicator: see [panels.md](panels.md).
- **Command**: `cmdrun.BuildFilePreviewArgv` expands `%w` (inactive-column inner width; full twin width for fullscreen) and optional `%f`. When the template starts with `bat`/`batcat` it resolves `bat`, `batcat`, `cat` on PATH in order (Debian ships `batcat`); `cat` drops bat-specific flags. Runs via `cmdrun.Run` under `App.commandsCtx`. External mode (`bat`/`cat`) does its own byte handling.
- **Legacy encoding**: internal mode (`runInternal` / `runMarkdown`, `internal/preview/run.go`) passes bytes through `decodeSource`: valid UTF-8 as-is, otherwise a total Windows-1252 transcode. This is a fixed single-encoding guess, not charset detection.
- **Resize re-render**: wrap and table layout are baked into cells at the requested `TextWidth`, so `*tcell.EventResize` -> `previewCtrl.RefreshPreviewsAfterResize` re-runs any open target whose new width differs from `previewLastWidth[target]` (recorded by `previewRequest`). Image targets also re-run on height-only changes. `refreshPreviewTargetAfterResize` first clears an image target's payload/dims/protocol and hold copy and sets Phase back to Pending, so the old-size payload never flashes at the new placement. Non-image content keeps the hold.

## Fullscreen view (`file.view`)

- **Chrome**: `Model.MenuBarLayoutReserved()` is false for `ViewFilePreview`: no menu strip, pulldowns, jobs bar or permission tail, and the partial menu painters (`DrawMenuBarJobsGapOnly`, `DrawMenuBarPermissionTailOnly`, `DrawMenuBarSpinnerOnly`) are no-ops. Row 0 is the preview's own borderless filename row (`previewpanel.Draw` `Borderless` branch) on the Chroma background. The activity spinner is the only menu element kept, drawn by `drawFullscreenPreviewSpinner` (`internal/ui/file_preview_render.go`) in the Chroma `LiteralNumber` colour (fallback `menu.spinner` fg), hidden while the `preview.theme-picker` picker is open. `app.open-menu` is rebound to `preview.theme-picker` in `[preview]`; Alt+letter menu shortcuts do nothing until Esc. Footer: `menu.FunctionKeysFilePreviewView(rawMarkdown bool)`; F3 is not shown (it toggles leader-menu chord hints).
- The scrollbar always paints on the rail column's own background (`uiscrollbar.Draw` takes it from `FrameStyle`) for every caller.
- **Keys**: overlay actions (`preview.close`, `preview.scroll-down`/`preview.scroll-up`, `preview.half-page-down`/`preview.half-page-up`, `preview.page-down`/`preview.page-up`, `preview.top`/`preview.bottom`) are handled in `tryFilePreviewAction`. As a standalone viewer (`pc <file>`, `App.launchedFileViewer`, set in `applyStartPaths`) `preview.close` quits the app; Esc still closes.
- **Close funnel**: every close path (Esc/`preview.close`, `file.edit` return, deleting the previewed file) goes through `preview.Handler.CloseFilePreviewFullscreen`, whose last step calls `Host.FilePreviewFullscreenClosed()` so a caller that hid its dialog can restore it (only the Pin dialog's `pin.view` today).
- **Search (`/`)**: `preview.search-start` opens `Model.FullscreenFilePreviewSearchField`; each keystroke re-runs `previewpanel.State.FindMatches` (case-insensitive literal, non-overlapping) via `RecomputeSearch`. Enter accepts, Esc cancels; `preview.search-next/prev` wrap through `Search.Matches`. All jumps use `scrollFilePreviewToSearchMatch` (`internal/apphandler/preview/search.go`), which centers the match via `geom.ScrollOffset` (clamped at file ends). Diff hunk jumps pin the line to the top instead.
- **Reload / raw toggle**: `preview.reload` re-runs from disk via `refreshFullscreenFilePreview` (the helper shared with the raw toggle and theme picker) keeping scroll, raw state and search. `preview.toggle-raw` flips `Model.FullscreenFilePreviewRawMarkdown` and refreshes; `Request.RawMarkdown` skips `runMarkdown`. Scroll resets to 0. No-op unless the path is `preview.IsMarkdownPath` and the result is not `IsDiff` (`toggleFilePreviewRawMarkdown`, `view.go`). The flag resets to rendered on each new fullscreen open and never applies to quick view/carousel. The footer `preview.toggle-raw` hint is dynamic ("Raw"/"Render").
- **Leader menu (`:`)**: `preview.menu` opens the leader strip scoped to `keymap.Bundle.PreviewMenuEntries()` (`[preview_menu]`, see `docs/config.md`), dispatched via `previewCtrl.TryFilePreviewMenuAction` (`internal/app/preview_menu.go`). F3 toggles `[ui].leader_menu_show_direct_keys` (`handleLeaderMenuKey`); direct-key hints come from the `[preview]` overlay (`App.keys.FilePreview.MenuBindingLabel`).
- **Image fullscreen no-ops**: `preview.theme-picker` and `preview.search-start` do nothing while `FullscreenFilePreview.ImagePayload != ""`.

## Git diff preview

- All three targets route through `preview.runGitDiff`, which picks diff vs. plain content from `Cell.Effective()`. Staged-only (`Unstaged==NotModified`) uses `--cached`, otherwise `HEAD`; `-U` is `config.DefaultPreviewGitDiffContextLines` so the whole file shows with markers. Stream size is capped by `cmdrun.MaxStreamBytes`.
- For `NotModified`/`New`/`Ignored` (or an empty diff) `preview.gitDiffFallback` shows plain content and sets `Result.StatusText` / `StatusThemeKey` (from `gitstatus.Status.Label()` / `.ThemeKey()`). Only the fullscreen (`Borderless`) title renders `<filename> (<StatusText>)`, coloured by `theme.Theme.PanelGitStyle`.
- Internal mode feeds `git diff --no-color` to Chroma's `diff` lexer; external mode passes `--color=always` ANSI through.
- `previewpanel.State.DiffHunkLines` holds the 0-based source line of the *first `+`/`-` line* of each contiguous change run (not `@@` headers; large `-U` yields one `@@`), built by `preview.parseDiffChangeChunkLines` (external path strips CSI first). `preview.diff-next-hunk/prev-hunk` (in `[main]`, so fullscreen preview and quick view share them) no-op when `IsDiff==false`, else toast "No more changes" / "No previous changes" (`hunkNavigate`). Offsets come from `State.SourceLineToScrollOffset`.
- Wiring: `previewRequest` sets `GitDiff=true` whenever `gitStatus != nil`; `runGitDiff` alone decides diff vs. fallback. `gitStatusForPath` uses panel `GitByPath[path]`, else a cache peek then synchronous `ResolveGitStatus` / `StatusesForListing` (covers CLI `pc <file>` before the async listing lands). `internal/preview` imports `internal/gitstatus` (no cycle).

## External preview commands (`[[preview.commands]]`)

- **Config**: `config.PreviewConfig.Commands []PreviewCommandRule` (`{When []string, Command string}`) and `ShellPatterns` (`filepath.Match` vs. regexp for `f`/`d` predicates). `validatePreview` (`internal/config/config.go`) silently drops a rule with an empty or unparsable (`cmdrun.PreviewCommandArgv`) command. `When` syntax is not validated at load (`internal/entrymatch` imports `internal/config` transitively; an invalid regex is a runtime non-match).
- **Matching**: `preview.RunRules(ctx, Request) (Result, bool)` and `preview.MatchAnyCommandRule` (`internal/preview/rules.go`) reuse `entrymatch.EvalWhenAny`, the same predicate language as `[[entry]]` in `meta.toml`. Rules are tried top to bottom; exit 0 returns that output as the Result. Non-zero exit, launch error or non-matching `When` continues; nothing matched returns `matched=false` and the caller falls back to its default (external `Mode`/`Command`, internal Chroma/media, or the directory overlay). Rules run `cmdrun.PreviewCommandArgv` + `cmdrun.Run`, not `BuildFilePreviewArgv` (no bat substitution).
- **Dispatch point**: `Handler.runPreview` (`internal/apphandler/preview/preview.go`) calls `previewrun.RunRules` right after its gen-check preamble, *before* the `req.Media` branch: one insertion point for quick view, fullscreen preview and carousel child-file preview. User rules also win over built-in archive listing, Chroma, media and git-diff. `Request.IsDir` / `previewpanel.State.IsDir` (via `previewRequest`'s `isDir`) tell matcher and refresh paths the target is a directory.
- **Directories in quick view**: `applyQuickViewPreviewNow`'s `quickViewWantDir` case first calls `MatchAnyCommandRule` on the path (`Host.SyncFollowTargetPath`); on a possible match `dispatchQuickViewDirPreview` opens Pending (`IsDir=true`) and runs `runDirPreviewRules` in a goroutine. If every rule declines, it posts `QuickViewDirRuleDeclinedPayload{gen}` (`Run()` forwards to `Handler.ApplyQuickViewDirRuleDeclined`, gen-guarded), which closes the file-preview state and falls back to `quickViewFollowDirectory()`. The round-trip exists because overlay population touches panel/host state unsafe from the goroutine. `refreshInactiveFilePreview` re-opens via `dispatchQuickViewDirPreview` when `st.IsDir`.
- **Directories in fullscreen preview**: `OpenFilePreviewFullscreen` (`view.go`) checks `MatchAnyCommandRule` first, then `OpenFullscreenFilePreviewAt`, which stats once to set `isDir` and uses the directory itself as `WorkDir` (so `eza --tree .` needs no `%f`). Fullscreen has no overlay fallback: if all rules decline, the internal path errors with `EISDIR` shown as an in-pane message (accepted, `ponytail:` marked).
- **Out of scope**: carousel parent/child directory columns (`dispatchCarouselParentSnapshot` / `dispatchCarouselChildSnapshot`) do not use `runPreview` and ignore these rules; only carousel child-*file* preview does.
- **Graphics output detection**: `sniffGraphicsProtocol` checks the first `graphicsSniffWindow` bytes of stdout for a Sixel DCS (`\x1bP`) or Kitty APC (`\x1b_G`) *anywhere* in the window (chafa/img2sixel emit cursor-visibility CSI first). `splitGraphicsPayload` separates the graphics chunk (introducer through `\x1b\\`, plus immediately trailing CSI noise via `stripLeadingCSISequences`) from real trailing text (e.g. caption lines). Without the split, trailing text bytes would land in `ImagePayload` and be written straight to the tty at the wrong place. `ImagePayload` gets only the chunk; trailing text goes to `Result.CombinedText` and `ImagePxH` is pre-shrunk by `req.ImageCellPxH` times the reserved caption rows (one separator plus one per newline). That must match `drawImageBody`'s own split (`internal/ui/previewpanel/draw_image.go`). With no trailing text `ImagePxH` stays `req.ImageMaxPxH`. Rendering reuses the built-in image overlay machinery (`reconcileImageBeforeShow`, `LockRegion`, raw tty write, tmux passthrough). Non-graphics output is combined with stderr like the default external path (`combineStdoutStderr`).
- **Stream cap**: `runRuleCommand` captures at `config.DefaultPreviewCommandsMaxStreamBytes`, above `cmdrun.MaxStreamBytes`, because fullscreen graphics can be several MB. A truncated capture counts as a decline: an unterminated DCS/APC corrupts the terminal.
- **PTY execution (Linux)**: `runRuleCommandCapture` (`internal/preview/rules_pty_linux.go`) gives the command a real pty (`github.com/creack/pty`). The pair is opened with `pty.Open` and the master set raw (`term.MakeRaw`) *before* `cmd.Start`, so replies are not echoed into the capture and ONLCR does not rewrite `\n`. Reason: some tools (observed: `movie-info`) send DA1/CPR queries and silently fall back to text if unanswered, which `cmdrun.Run`'s disconnected pipes guarantee. `terminalQueryScanner` (`internal/preview/pty_query.go`, handles queries split across reads) strips exactly DA1 and CPR and replies: DA1 carries param 4 (Sixel) when the resolved protocol (`ResolveImageProtocol(req.Preview, os.Getenv)`, gated on `req.Preview.Images`) is Sixel, else no sixel param; CPR always `\x1b[1;1R` (row measurement by CPR delta is wrong, accepted). **No DA1 signal exists for Kitty**, so DA1-only tools emit images only when the protocol resolves to Sixel. PTY merges stderr into stdout (`Stderr` empty). Non-Linux (`rules_pty_other.go`) uses plain `cmdrun.Run`.
  - Capture does not block on `ptmx.Read` to EOF: the primary is waited in a goroutine, the master is read via nonblocking `unix.Poll` + `SetNonblock`, and after exit/cancel the remainder drains for `ptySlaveDrain`. Closing the master while a Go `Read` is blocked deadlocks, so close-to-interrupt is never used.

## Markdown rendering (internal mode)

- **Gate**: `preview.Run`'s `default:` branch (reached only when `GitDiff` is false) calls `runMarkdown` when `preview.IsMarkdownPath(req.Path) && !req.RawMarkdown` (`markdownExtensions` in `internal/preview/run.go` is the single source). Dirty markdown stays on the diff path. External mode is untouched (point `[preview].command` at `glow`). `runMarkdown` forces `GutterWidth: 0` (no line numbers).
- **Renderer**: `mdformat.Render(source, Options{Path, StyleName, BaseStyle, ContentWidth})` parses with goldmark + GFM table extension (built once via `sync.OnceValue`) and walks the AST into `[]previewpanel.AnsiCell`.
- **Styling** reuses the active Chroma style's generic tokens, no new theme keys: heading `GenericHeading` (bold), strong `GenericStrong` (bold), emphasis `GenericEmph` (italic), inline code `LiteralString`, blockquote/rule `Comment`, links/images `NameAttribute` (underline, destination dimmed in parens). `chromaformat.StyleEntryToTcell` is shared so both packages convert styles identically.
- **Tables**: glow-style (bold header, `│` separators, `─┼─` rule, `Comment` style). Column width is the widest cell in runes; when too wide, the widest column shrinks a rune at a time (minimum 5) and cells word-wrap via `wrapCells`, padding shorter cells so rows stay rectangular. Alignment comes from the delimiter row. Rows are written through `renderer.writeLine`, not `emitWrapped` (the table wraps per column).
- **Fenced code**: recurses into `chromaformat.Highlight` with `Options.Language` (`lexers.Get(lang)`, then path match, then plain text), indented 2 spaces and hard-wrapped downstream (`WrapAnsiCells`).
- **Lists/quotes**: bullets `• `, ordered `N. `; nesting through recursive `firstPrefix`/`contPrefix` threading; blockquote lines (including continuations and blanks) prefix `▌ `.
- **Wrap**: `mdformat/wrap.go`'s `wrapCells` is the styled analogue of `internal/ui/wrap_words.go`'s `WrapWordsToWidth`; hard breaks become an explicit `'\n'` cell.

## Image previews (what and where)

Protocol choice, tmux transports, placeholder gating and the failure history are in [terminal-graphics.md](terminal-graphics.md); this section maps the code.

- **Invariant: re-transmit only on resize.** Re-sending an unchanged image payload is correct only after `EventResize` (`resetImageOverlayForResize` / `RefreshPreviewsAfterResize`). Any other repeat is a bug to root-cause, not to paper over with a keep-alive (terminal-graphics.md lesson 11).
- **Eligibility**: `localfs.IsImagePath` includes `localfs.imageMagickExtensions` (e.g. `.psd`), formats the stdlib cannot decode; adding another (`.heic`, `.avif`) is one map entry.
- **ImageMagick fallback**: for `localfs.IsImageMagickPath`, `DecodeStillMaxEdgePNG` (`internal/preview/raster.go`) skips the stdlib decode and runs `<magick|convert> path[0] png:-` (`convertToPNGViaImageMagick`, first found via `LookPath`), then joins the common `fitImage`/`png.Encode` tail. `runImageCtx` skips its `image.DecodeConfig` pre-check for these. The caption uses the original extension as the format label. Neither binary on PATH yields `ErrImageMagickRequired`, shown like any preview error (`Result.ErrorMsg` -> `Theme.MessageError`).
- **Protocol resolution** (`preview.ResolveImageProtocol`, `internal/preview/image_protocol.go`, takes the whole `config.PreviewConfig`): explicit `image_protocol` wins; for `auto` an explicit `"yes"` on exactly one of `terminal_sixel`/`terminal_kitty` decides, a `"no"` on the guessed protocol falls through to the other, else the heuristic: Kitty when `TERM_PROGRAM` is `kitty`/`ghostty`/`wezterm` or `TERM` is `xterm-kitty`/contains `ghostty`, otherwise Sixel, replaced by Überzug++ when Sixel is only that fallback (`terminal_sixel` not `yes`) and `ueberzugAvailable`. Under tmux the heuristic reads `client_termtype` (see terminal-graphics.md). No async capability query. `[preview].images` off yields metadata only.
- **`preview.CapabilityUncertain(cfg, environ)`** drives the discoverability hint: true when the resolved protocol's tri-state is still `"auto"` and detection cannot confirm it. Sixel is never heuristically confirmed; Kitty is, except the tmux placeholder sub-decision. An explicit non-`auto` `image_protocol` always answers false.
- **Pipeline**: `previewRequest` -> `runPreview` -> `preview.Run`. For images it sets `Image`, `ImageMaxPxW/H` (cells x `previewpanel.CellPixelDims`, 10x20 fallback), `ImageProtocol` (`None` when `screen.Tty()` is unavailable, so Draw never blanks for an unemittable payload), `ImageInTmux` (`$TMUX`), `ImageUnicodePlaceholder = Protocol==Kitty && TmuxSupportsKittyUnicodePlaceholders(...)`, `ImageCapabilityUncertain`, the prefetch `Cache`, and forces git-diff off.
  - `runImageCtx` (`internal/preview/image.go`) loads a max-edge-clamped PNG (`DecodeStillMaxEdgePNG`/cache). Its returned `meta` string *is* the caption (`ImageCaption`), cached with the still. The pixel-height budget is shrunk by the caption's wrapped rows (`ImageRenderBudgetPxH`; unchanged for an empty caption); if one cell row no longer fits, the result is text-only. Otherwise `fitImage` (never upscales) and one encode: Sixel via `go-sixel`, Kitty PNG -> base64 chunked APC, or Überzug++ (PNG written to a temp file, payload = its path). Result: `ImagePayload` + px dims + protocol + `CombinedText: caption` + `ImageFirst: true` (image above caption).
  - Text-only fallbacks (too large / images off / no protocol) floor the metadata level at `basic` (`boostedMetadataLevel`) so the pane is not blank; a rendered image at `off` shows no caption.
  - Edge clamp: `preview.EffectiveStillMaxEdge(cfg, protocol, inTmux)` (`internal/preview/maxedge.go`): Sixel under tmux uses `tmux_sixel_max_edge_px`, everything else `image_max_edge_px` (0 = native resolution). Video grids always need a positive edge: `VideoThumbMaxEdge(cfg)` falls back to the tmux Sixel default; prefetch and `mediaThumbWarm` call the same helper so cache keys agree.
  - Over `config.DefaultPreviewImageMaxDecodeMegapixels`, or on encode failure: metadata-only (`"... / too large"`) via `SourceExternalANSI`.
  - Kitty first-chunk params: `a=T,f=100,i=1,C=1,q=2`, or `a=T,f=100,i=1,q=2,U=1` (no `C=1`) for placeholder mode (`U=1` registers data for placeholder display instead of drawing at the cursor).
- **Sixel under tmux, payload safety**: tmux <= 3.5a drops any single escape sequence over ~1 MB (terminal-graphics.md lesson 5). Sixel is one unchunked DCS, Kitty is chunked, so only Sixel is guarded: the tmux max-edge clamp above, `encodeImagePayload` capping the palette at `config.DefaultPreviewTmuxSixelColors` when `ImageInTmux`, and `runImage` falling back to `"... / too large for tmux"` once the payload reaches `config.DefaultPreviewTmuxSixelMaxBytes`. Kitty and non-tmux Sixel get the general clamp.
- **State/draw**: `previewpanel.State.ImagePayload/ImagePxW/ImagePxH/ImageProtocol/ImageUnicodePlaceholder/ImageCapabilityUncertain`; `MergeDrawWithHold` (`internal/ui/previewpanel/hold.go`) copies all of them. `Draw` (`draw.go`) branches on `st.ImageUnicodePlaceholder` alone, decided once in `previewRequest` and carried Result -> State, never re-derived from the environment (`TestDrawImagePlacementModeFollowsStateFlagNotEnvironment`; terminal-graphics.md lesson 7).
  - **Cursor-relative** (default, also all Sixel): blanks the body, records one `ImagePlacement{X,Y,MaxCols,MaxRows,PxW,PxH,Payload,Path,Protocol}`, no scrollbar. `TakeFrameImage` is read-and-clear.
  - **Unicode placeholder**: `drawUnicodePlaceholderImage` (`internal/ui/previewpanel/unicode_placeholder.go`) writes `ceil(px/cell)` rows x cols (clamped to the content area and `MaxUnicodePlaceholderGridSize`, the diacritic table size) of U+10EEEE plus `numberToDiacritic` marks (copied verbatim from kitty's `tools/utils/images/rowcolumn_diacritics.go`) encoding row, column and the image id's high byte; the cell foreground carries the id's low 24 bits (`UnicodePlaceholderColor`, truecolor). It records `ImagePlacement{Payload, Path, Protocol, UnicodePlaceholder: true}`. `ImagePlacement` does not carry `CapabilityUncertain`; `Draw` paints that indicator from `State` directly.
- **Sixel transport under tmux**: `preview.TmuxSupportsNativeSixel(os.Getenv)` is true when tmux's `#{client_termfeatures}` contains `sixel` and `#{image_support}` is not `"0"` (both cached per process; empty `image_support` means a tmux too old to report it, so the features rule alone applies). True -> payload goes out bare and tmux stores and re-renders it. False -> DCS-passthrough wrap. There is no setting: passthrough Sixel cannot survive tmux's per-line repaint (lesson 19). Kitty is always passthrough-wrapped (tmux never parses APC). Users of terminals tmux does not know add `terminal-features ',term:sixel'`. Decision users: `emitImageAfterShow`, `writeImagePayload`, `resetImageOverlayForResize` (`internal/app/image_overlay.go`) and the resize-refresh skip in `internal/apphandler/preview/preview.go`. Under tmux the emit is never wrapped in synchronized output (`\x1b[?2026h/l`) on either branch; outside tmux it is.
- **`TmuxSupportsNativeSixel` detection**: queries `client_termfeatures` rather than tmux's DA1 reply, because DA1's sixel bit only reflects whether tmux was compiled with sixel, not whether the attached terminal can display it (lesson 9). `preview.WarmTmuxCaches(os.Getenv)` (called from `Run(LaunchConfig)` in `internal/app/app.go` before the screen exists) fills the `sync.OnceValue` caches for `client_termfeatures` and `client_termtype` in goroutines, so the first image never blocks the render goroutine on a subprocess. It is deliberately not called from `NewWithOptions`: most `internal/app` unit tests use it directly and would leak a real `tmux` result into the process-wide cache.
- **TTY emission, cursor-relative** (`reconcileImageBeforeShow` / `emitImageAfterShow`, `internal/app/image_overlay.go`): before `Show`, unlock the old region and lock the new span (`ceil(px/cell)` via `CellPixelDims`). Skip re-emit entirely when path, payload, protocol, position and span are unchanged. Whenever a Kitty placement is torn down (cleared, moved, or replaced, even at the same geometry) queue `writeKittyDelete` before the next transmit (the spec requires delete-before-retransmit; WezTerm renders each skipped-delete replacement as a slideshow, lesson 1). The `Show()` hash-cache skip is forced when the placement changes.
  - Outside tmux, and for bare native Sixel under tmux (`bareNativeSixel := protocol == Sixel && TmuxSupportsNativeSixel`, computed once per emit): `\x1b[?2026h` (outside tmux only) + save cursor + CUP + payload via `writeImagePayload` + restore. tmux treats a bare sixel DCS as pane content, so no ceremony is needed.
  - Other tmux emission (Kitty, passthrough Sixel): no synchronized output; save cursor, CUP + show-cursor (`\x1b[?25h`) written three times, ~1 ms sleep, wrapped payload, hide cursor + restore. tmux syncs the *outer* cursor only when the pane cursor is visible and from its own event loop, while passthrough bypasses that loop (lesson 8; mirrors yazi's `Emulator::move_lock`).
  - `writeImagePayload` / `writeKittyDelete` wrap in `splitTerminatedSequences` + `tmuxPassthroughWrap` (`\x1bPtmux;<ESC-doubled>\x1b\\`, needs `allow-passthrough on`) whenever `$TMUX` is set and the bare-Sixel case does not apply. Each Kitty chunk is wrapped on its own (several ST-terminated sequences in one envelope garble); a Sixel payload splits into one piece.
  - Menus/modals treat the plan as nil (image clears; state keeps the payload so close re-emits). `EventResize` and `withTerminalReleased` call `resetImageOverlay`.
  - **Überzug++** (`ImageProtocolUeberzug`): `emitImageAfterShow` skips the tty and calls `ueberzugDaemon.show(x, y, cols, rows, path)`; `remove` is sent when the placement is torn down without an Überzug++ replacement and from `resetImageOverlay`. `withTerminalReleased` and both `RunVisible` call sites reset the overlay first so the window does not float over the editor/shell.
- **TTY emission, Unicode placeholder** (`reconcilePlaceholderImage`): only tracks whether `ImagePlacement.Payload` changed and (re)transmits, deleting the previous transmission under the fixed id first, synchronously *before* `Show()` (the terminal must know the data before the cells reference it). No `LockRegion`. It returns whether it transmitted/deleted and `reconcileImageBeforeShow` reports that as `forceShow`, because placeholder cells encode only row/column/fixed `KittyGraphicsImageID`, so two images at the same grid size are identical screen content and the hash cache would otherwise swallow the redraw (lesson 15, `TestReconcileImageBeforeShowForcesShowOnPlaceholderPayloadChange`). Reached only when `TmuxSupportsKittyUnicodePlaceholders` confirms placeholder support, independent of how Kitty was selected (a forced `image_protocol=kitty` says nothing about the terminal).
- **Panel indicators** (both on the border row, boxed panels only: `!Embedded && !Borderless`, since embedded/borderless previews have no free border row):
  - Bottom-right `paintImageProtocolIndicator` (`internal/ui/previewpanel/draw.go`): shown only for Sixel, the protocol with a known display gap. ` Sixel ` (`Theme.PanelStatusImageSixel`) or ` Sixel+Tmux ` (`Theme.PanelStatusImageSixelTmux`, red by default) from `State.ImageInTmux`, threaded Request -> Result -> State like the placeholder flag. Tests: `TestDrawImageProtocolIndicator{SixelPlain,SixelTmux,KittyOmitted}`.
  - Bottom-left `paintCapabilityUncertainIndicator`: plain-border hint (the `preview.settings-dialog` chord) whenever `State.ImageCapabilityUncertain`. Independent of the Sixel label; both can show.
- **Preview settings dialog** (`preview.settings-dialog`, or Options -> Preview settings): `internal/app/dialog_preview_settings.go`, state `dialog.PreviewSettingsDialogState` (`internal/ui/dialog/state_message_theme_config.go`), widget spec `dialog.PreviewSettingsDialogView` (`preview_settings_dialog_view.go`, a `dlg` dialog; render `dialog.DrawPreviewSettingsDialog`). Three capability rows (Sixel, Kitty, Placeholder), each a label cell followed by auto / yes / no radios on one row and one Tab stop; Left/Right stay within the row and Up/Down keep the column, Down from the last row enters the protocol group and Up from there lands on the last capability radio. Then 4 protocol radios (Auto, Sixel, Kitty, Überzug++), 4 image-metadata radios, the video-metadata checkbox and OK/Cancel. OK persists six `[preview]` keys (`terminal_sixel`, `terminal_kitty`, `terminal_kitty_placeholder`, `image_protocol`, `image_metadata`, `video_metadata`) immediately via `persistPartial` (`config.WriteMergedPartial`, like every settings dialog). Checking placeholder implies Kitty supported; unchecking Kitty unchecks placeholder (`PreviewSettingsDialogState.SetKitty` / `SetKittyPlaceholder`, shared by the mnemonic, Space and Enter paths and F5). The capability row labels carry no mnemonic widget: the Alt letters of the three rows cycle the row's value and focus the new radio (`cyclePreviewSettingsCapability`, before the engine). F5 "Auto detect" (`autoDetectPreviewSettingsDialog`, also before the engine) re-seeds only the capability radios from `preview.DetectTerminalCapabilities(os.Getenv)`; it guesses placeholder support only for Kitty/Ghostty (`kittyOrGhosttyConfirmedByEnv`), so it can never check the box for WezTerm.

## Image metadata (EXIF captions)

- `preview.ImageCaption(path, format, w, h, size, level)` (`internal/preview/exif.go`) builds the base "FORMAT image / W x H px / size" line plus EXIF at `[preview].image_metadata` (`off`, `basic`, `essentials` default, `full`; field sets in `docs/config.md`). EXIF is read in-process via `github.com/bep/imagemeta` (`decodeExifTags`; JPEG/TIFF/PNG/WebP chosen from the extension), limited to a fixed `ShouldHandleTag` allowlist with a 2 s timeout. A missing/corrupt blob returns no EXIF lines and falls back to the base line; nothing shells out.
- **Orientation**: `DecodeStillMaxEdgePNG` (stdlib branch only) applies `exifOrientation(path)` -> `applyExifOrientation` (`exif.go`, `orient.go`) after the max-edge clamp, independent of the metadata level. `exifOrientation` is a separate `decodeExifTags` call scoped to tag 0x0112 (it does not widen `exifWantedTags`) and returns 1 on any failure. Orientations 5-8 swap width/height. The caption's "W x H px" reports the stored pre-rotation dimensions.
- `[preview].video_metadata` is the matching switch for the ffprobe line under video grids.

## Media preview (ffprobe + video thumbnails)

- `localfs.IsAudioVideoPath` -> `ErrFilePreviewAudioVideo`; handled like images on all surfaces, git-diff off. Audio shows metadata text only.
- **Pipeline**: `previewRequest` sets `Media=true`, the pixel budget, `ImageCellPxH`, protocol from `ResolveVideoThumbProtocol` (`images` off or no TTY -> `None`, else `ResolveImageProtocol`), and `Cache` when prefetch is on. `runMedia` / `RunMediaMeta` + `RunMediaThumbs` (`internal/preview/media.go`) call `ffprobe`/`ffmpeg` via `os/exec` (`ffmpeg_exec.go`), capturing through `cmdrun.CappedWriter` (1 MiB JSON, 8 MiB PNG; oversize returns `ffprobe metadata too large` / `ffmpeg frame too large`). `ffmpegFramePNG` scales during extraction when `maxEdge >= 1` (`buildVideoThumbGrid` passes `max(maxW, maxH)`). Caps are package constants.
- `BuildVideoThumbMaxEdgePNG` / cache loads a grid, `fitImage` fits it to the remaining cell budget, `encodeImagePayload` encodes; success carries `ImageFirst: true`. Disk cache: `$XDG_CACHE_HOME/pc/video-thumbs/`, capped by `[preview].video_thumb_cache_max_mb`.
- `Generating thumbnails...` shows only when the grid is not warm (`MediaCache.HasVideo`); `preview.JoinMediaText(meta, status)` separates meta and status with a blank row and skips the separator when `meta == ""`.
- `!VideoMetadata`: `RunMediaMeta` blanks its `CombinedText` and the stashed `MediaThumbWork.meta` once thumbnail work will happen (a video with no thumbnail work keeps metadata), and both runners reserve 0 caption rows (`metaRows`) for empty meta.
- **Draw**: grid above (`ImageFirst`), one blank row, metadata caption directly under it (same layout `drawImageBody` uses for still-image captions).

## Preview prefetch (background warm cache)

- **Settings**: `[preview].prefetch` (also requires `[preview].images`), `prefetch_workers`, `prefetch_memory_max_mb` (byte-budget LRU); defaults in `docs/config.md`. Runs only while quick view is latched or the active panel is in carousel mode, unless `prefetch_always`. Leaving those surfaces clears the pending queue (in-flight jobs finish).
- **Engine config reconciliation**: `ensurePrefetch` derives the config from live settings every call (`prefetchEngineConfig`, `internal/apphandler/preview/prefetch.go`) and *restarts* the engine when it differs from the running one's (`prefetch.Config` is comparable for this; `OnChange` is a `NewEngine` parameter). Both max-edge values and the metadata level are frozen per engine while the preview settings dialog changes them in place. A stale max-edge makes prefetch warm one `LoadStill` key while the foreground asks for another, so every image re-decodes (loading icon flashing on an entry tinted warm). A stale `ImageMetadata` serves a caption baked at the old level, since the still tier's cached `meta` is the caption. `prefetch.RenderBox` also carries `TextWidth`/`CellPxH` (from `activeRenderBox`) so `Engine.runJob`'s `KindImage` case shrinks `box.MaxPxH` with `ImageRenderBudgetPxH` before `Cache.LoadRender`, and `isImageWarm` peeks the cached caption via `Cache.StillMeta(path, mtime, size, maxEdge)` and applies the same shrink, so warm checks match the foreground request. The restart drops the memory cache (keys changed anyway) and `stopPrefetch` clears the skip guard (`prefetchLastSurfaceActive/Path/Cursor/EntryCount`).
- **Scheduling**: `SchedulePrefetchFromActivePanel` runs from `App.reconcileAfterEvent` (same chokepoint as quick-view reconcile). `ScheduleFromListing` / `IsEntryWarm` / `SchedulePrefetchFromActivePanel` never `Stat` on the caller; missing mtime/size is resolved in the worker. The queue is rebuilt from the active listing, nearest `|index - cursor|` first. Still decode and video-grid generation share `MediaCache` with `runPreview` (singleflight per key).
- **Marks**: in-flight paths are in `Model.PreviewPrefetchLoading`; with icons on, the file icon becomes `[icons.filelist] preview_loading` tinted `panel.icon.folder.scanning`. Warm/cold tint (`panel.icon.preview.warm`/`.cold`, image and video entries only) comes from `Model.PreviewPrefetchWarm`. All three row painters (plain, tree, carousel columns) get both via the single `panelIconStripContextFor` constructor (`internal/ui/panel_icon_strip.go`); the maps hold only the active panel's prefetch window, so other rows do not match.

## Archives

- `archive.ListableName` covers multi-member formats (`.tar`, `.tar.gz`/`.tgz`, `.tar.bz2`/`.tbz2`, `.tar.xz`, `.tar.zst`, `.zip`/`.jar`, `.rar`, `.7z`). Single-stream `.gz`/`.bz2`/`.xz`/`.Z` are not listable and take the NUL sniff.
- `preview.Run` dispatches a listable format (`archive.FormatForName` / `Format.Listable`) to `runArchiveList` (`internal/preview/run_archive.go`) *before* the `GitDiff` branch and before `mode=external`. It uses the extract dialog's toolchain (`archive.ProbeToolchain`, per-process `sync.OnceValue`) and one `cmdrun.Run` per format (`archive.ListArgv`: `tar -tf`, `unzip -Z1`, `unrar lb --`, `7z l -ba -slt`); a missing tool names the required binary. `archive.ParseListing` extracts member paths (7z: `Path = ` lines; others: trimmed lines, trailing `/` = directory).
- Rendering: a path trie (`archiveRoots` / `archiveBuild`) flattened with `treeflat.Flatten` into a fully expanded static tree, painted as `AnsiCell`s with `panellist.TreeConnectorPrefix` and `theme.Theme.PanelRowTreeConnector` (from `Request.Theme`, set from `Host.Styles()`). Directories are bold and sort first; both groups alphabetical. A truncated listing appends `[listing truncated]`.

## Preview syntax themes (Chroma)

- Preview syntax highlighting (`[preview].style`, Chroma) is independent of UI themes: never put Chroma styles in `themes/*.toml` (see [theming.md](theming.md)).
- Internal mode (`[preview].mode = "internal"`) highlights with embedded Chroma XML styles (`internal/preview/chromastyles`, `chromaformat.Highlight`). Custom `*.xml` styles in `config.Paths.PreviewStylesDir` (`$XDG_CONFIG_HOME/pc/themes/preview/`) load at startup via `chromastyles.LoadFromDir` before config validation; a custom `<style name>` matching a built-in overrides it for highlighting and frame tint. Invalid files are skipped with a startup warning toast; the name `default` is reserved.
- **Picker**: `preview.theme-picker` opens an inline list from `chromastyles.Choices()`; navigation live-previews, Enter persists `[preview].style`, Esc reverts.
- External mode: `[preview].command` does highlighting; `style` then only tints the frame.
