# Panels

File-list panels: listing loads, refresh, formats, chrome, carousel, tree layout, filters, disk usage, git column, selections. Package layout: `architecture.md`; dialog standards: `dialogs.md`. Related: `preview.md` (quick view, prefetch), `jobs.md`, `navigation.md` (history, bookmarks, pin, SFTP), `file-operations.md`, `keybindings.md`, `menus.md`, `theming.md`, `views.md`.

## Listing load (async)

- Every directory load, including each panel's first listing at startup, goes through `panel.State.load`, which schedules the fetch off the UI thread (`ScheduleAsyncLoad` -> `asyncLoadScheduler` / `raceAsyncListingFetch`, `internal/app/panel_async_load.go`) racing a `[sftp].list_timeout_secs` give-up timer. Local paths use it too: autofs/network mounts stall `ReadDir` just like SFTP. `ListingPending` is set and `Path`/`Entries` keep showing the old listing until the result applies.
- `ListingPendingPath` names the target being loaded; the renderer uses it to find the row in the old listing (cursor position is unreliable while the user keeps moving).
- **Working indicator**: if still pending after `panel.LoadingIndicatorDelay` (`internal/panel/state.go`, the single source for every slow-row indicator, shared with quick view's `QuickViewSlowPath`), `ShowLoadingIcon` is set and that row gets the `icons.working` suffix (`Theme.IconFilelistWorking`, colour `panel.icon.folder.scanning`). The timer is armed via `State.OnAsyncLoadPending` -> `App.armDirLoadingIndicatorTimer`, epoch-guarded so a superseded load cannot arm a stale icon; `applyPanelAsyncLoad` clears pending state and invalidates the timer. `ShowLoadingIcon` on either panel also feeds `App.menuBarSpinnerBusy`, which covers jumps (bookmark/history/pin) to a path that is not a row in the old listing.
- **Probes ride the fetch**: `raceAsyncListingFetch(withProbes=true)` runs `panel.ProbeListingPath` on the fetch goroutine (`statfs` free/total, `diskusage.PathDevice`, `gitignore.ValidWorkTreeRoot`; each a round trip on a network mount). Results reach `State.ApplyListingWithProbes`, so applying a listing on the UI goroutine touches no filesystem. Carousel side-column callers pass `false`. Heavy volume probes are skipped when a job saturates the volume (`App.probeListingPath` mirrors `suppressHeavyPathProbes`). `ApplyListing` (nil probes) probes synchronously for the non-async `load` path used by tests.
- Same-directory `Refresh` while a same-dir load is pending supersedes it (generation bump); a pending load to a different directory is left alone.
- **Startup**: `panel.NewDeferred` parses the path and applies defaults with no I/O; `App.loadStartupPanelListings` runs right after the first `render()` so the first frame is on screen before any `ReadDir`. It skips a panel whose listing is already pending (chooser `-select` / start-path navigation). Because `Path` is set up front, the first listing is a same-directory reload; `ApplyListing` gates its newly-appeared-file diff on `hadPriorListing` (`listingApplied || len(Entries) > 0`), otherwise every startup file would get the new-file icon.
- **Tests**: build apps with `newTestApp(t, screen, opts)` (`internal/app/test_helpers.go`); it lands listings via `settleStartupPanelListings` (targets `ListingPendingPath`, bumps `panelAsyncLoadGen`). Only tests asserting that `NewWithOptions` fails call the constructor directly. `TestMain` (`internal/app/main_test.go`) stubs every subprocess launcher seam (`externalEditorRunner`, `userMenuInteractiveRunner`, `userMenuDetachRunner`, `runDetachedXDGOpen`); tests that observe a launch install their own stub and restore it. `NewWithOptions` copies the package-level `externalEditorRunner`, `sftpTouchConn` and `os.Getenv` into per-App fields (`App.runExternalEditor`, `App.sftp.touchConn`, `App.getenv`); a test that needs a different one sets the field on its own app instead of swapping the global, which keeps it safe under `t.Parallel`. The dialog handler reads `App.getenv` through `dialog.Deps.Getenv` (a closure, so overriding the field after construction takes effect); bookmark loading takes it as the `environ` argument of `bookmarks.ResolveFile`/`ResolveGTKFile`/`LoadAll`, which is how bookmark tests point `XDG_CONFIG_HOME` at a fixture without `t.Setenv`. Wall-clock perf budgets are multiplied by `raceSlowdown` (build-tagged).
- Local `ListDir` skips names that vanish between `ReadDir` and `Info`.
- **Refresh to an existing ancestor**: `RefreshOrNavigateToExistingAncestor` never `Stat`s on the event loop; it schedules a refresh with `ClimbToExistingAncestor`. `FetchListing` lists the path first and only a failed list walks parents off-thread; `ApplyListingWithProbes` highlights the first missing child. A newer navigation wins over a stale climb.

## Periodic refresh

- Root `refresh_interval_ms` (0 disables) drives a ticker (`internal/app/panel_periodic_refresh.go`) that re-reads both panels while `ViewBrowser` and no modal is open. Reads use the seam `fetchListingForPanelRefresh` (default `panel.FetchListing`) and `fsbackend.EntriesListingEqual`; the main loop applies via `State.ApplyPeriodicRefresh` only when content changed, preserving highlight by name (else next surviving neighbour, else prior index), multi-select, and the highlight's viewport row (recentre only when it was centred or `[ui.scroll].mode = "center"`).
- Skips: zero paths, `ListingPending`, in-flight reads per panel (`panelRefreshInFlight`), results whose captured `ListingEpoch` no longer matches, and contended volumes (see "Background I/O yields to jobs").
- **Slow-refresh back-off**: `App.panelRefreshNotBefore` holds the earliest next start (unix nanos). `schedulePanelListingRefresh` checks it before the in-flight compare-and-swap; the goroutine's deferred cleanup records `start + config.DefaultPanelRefreshSlowBackoffFactor * elapsed` (errors/timeouts count their full elapsed time). Spacing is start-to-start, so fast local refreshes are unaffected. The deadline is deliberately not reset on navigation (it would race the goroutine's own deferred write).
- A change only inside an already-expanded tree subdirectory does not trip the differ (it diffs the top-level listing); it surfaces on the next reload or manual expand.
- **Volume free space**: after each load the panel samples free/total for the mount (`internal/fsvol`) and paints it on the top interior row (`panel.{active,inactive}.disk_usage_overview`); hidden when narrow or the query fails. It refreshes on debounced job progress and on `panel.refresh` (active panel full reload, other panel volume-only).
- **Disk-usage change feed** (ADR 0023): `diskusage.Engine` is the `fschange.Sink` for every local filesystem change made by jobs and dialogs. `Engine.Apply` only queues a batch; `applyLoop` (`internal/diskusage/apply.go`) applies everything queued in one pass under `e.mu`, in order. Renames and removals collect into a `sweepGroup` that is flushed before any change overlapping a path in it, and only a group holding a directory sweeps the cache (`rebaseKeys`). File-only groups move keys directly. Per kind: **Renamed** carries cached sizes, file counts and exclusion marks (and descendants') to the new path and drops stale keys under it (a replaced tree). Ancestors follow: the old path's lose the size, the new path's gain it less any replaced tree's. A rename whose source is uncached (an arrival) counts as a creation (file) or a dirty path (directory), applied after the rest of its batch. **Removed** subtracts from cached ancestors and drops the subtree. **Created** adds a file's bytes (less an overwritten file's cached size) and +1 file to cached ancestors. Under a scanned directory the path gets its own entry, and so do intermediate directories that appeared unreported; a cached directory is left alone. **Dirty** drops the path and, when something above it is cached, queues a refresh scan (`queueRefresh`: one job per path, `sourcePanel` `anyPanel`, so it is pending in both panels, with a `FromRoot` volume gate built from `SetRefreshIgnore`, which `App.applyDiskUsageConfig` calls at startup and on config reload). The dropped path stays in `refreshPending` until a walk settles it: whichever walk (refresh or listing) next merges a root at or above it moves that root's cached ancestors by its change in total as the root's key is merged (`addRefreshedLocked`); a pending path is not queued twice, and one that no longer exists is cleared. Changes overlapping an active walk root set `touchedWalkRoots`; `walkAndMerge` walks the root again (up to `maxTouchedRewalks`) instead of merging pre-change sizes. Ancestor adjustments accumulate per ancestor before applying, stop climbing at an excluded ancestor (walks never counted below it), and clamp at zero. Listing walks themselves never adjust ancestors. Row bars and size cells of non-directories always use the listed `entry.Size` (`panellist.EntryUsageBytes`, shared by the panel and carousel painters), never the path-keyed cache.
- **Title path shortening**: `~/` under the home dir; when too wide, parent directories shrink to first letters outward until the basename fits.

## Folder colours

- `internal/foldercolor` mirrors Nemo's folder-color-switcher colours. `Store` holds an `atomic.Pointer` snapshot (absolute dir path -> `tcell.Color`, plus each dir's icon basename and the colours of the current icon-theme style). `Lookup` is a lock-free map read used at paint time; `Reload`, `Refresh` and `WatchIconTheme` do file I/O and run only on background goroutines. The panels never read the metadata files while painting.
- **Source**: the GVfs trees `home`, `root` and the device trees `uuid-*` / `label-*` under `~/.local/share/gvfs-metadata` (big-endian tree decoded in `metatree.go`: header, attribute stringv, 16-byte DirEnts, `metadata::custom-icon` / `custom-icon-name` values) plus each tree's journal `<tree>-<random_tag %08x>.log`, replayed on top (SET / UNSET / COPY / REMOVE entries; a journal whose `random_tag` differs from the tree's is ignored). `palette.go` maps `/usr/share/folder-color-switcher/colors.d/*.json` theme dirs (`Mint-Y-Red`) and colour names (`folder-red`) to hex. 
- **Trees**: gvfs stores a path under `home` (relative to `$HOME`) when it is under `$HOME` on the same device, else under the tree of the mounted block device (`uuid-<ID_FS_UUID_ENC>`, else `label-<ID_FS_LABEL_ENC>`; path relative to the mount point, prefixed with the mountinfo root when that is not `/`), else under `root` (absolute path). `mounts.go` reverses this: `mountCache.deviceMounts` parses `/proc/self/mountinfo` (octal-unescaped fields, mount points other than `/`), and matches each mount's `major:minor` to the `/dev/disk/by-uuid` then `by-label` links (udev names them with the `_ENC` strings; `devNumOf` reads the link target's rdev), stopping once every mounted device is named. The result is cached on the raw mount table, so an unchanged table costs one procfs read. Anonymous devices (tmpfs, btrfs subvolumes) have no link and live in `root`. A tree is read only while its filesystem is mounted, once per tree even when mounted twice; entries outside a mount's root are skipped. `Store.load` reads all trees in parallel (plus the icon theme via `gsettings get` only while no watcher runs), then applies `root`, then device trees, then `home`; the later tree wins for the same path. The network and device backends (`mtp:`, `google-drive:`, `network:`, `admin:`) are not read. The signature also covers the mount list, so (un)plugging a drive reloads.
- **Refresh**: `App.runFolderColorRefresh` (`internal/app/folder_color_menu.go`, started from `App.Run`) reloads once, then every `config.FolderColorRefreshInterval` calls `Refresh`, which builds the signature (per tree: tree stat, plus one open per journal for its fstat and header entry count; plus the mounted device trees) and reloads with that same mount scan and signature when it differs. Every reload posts `folderColorsPayload`, which repaints. The icon theme is followed by `Store.WatchIconTheme`: one long-lived `gsettings monitor org.cinnamon.desktop.interface icon-theme` child (started by `runFolderColorRefresh`, killed through its context when the loop stops), one initial `gsettings get`, and on each change line `setTheme` republishes the snapshot with the new style's `choices`; `folderColorsPayload` is posted only when those choices actually differ, so the startup read that matches the first load costs no repaint. While it runs, `load` uses the cached theme and forks nothing; if `gsettings` is missing or the monitor exits, `load` reads the theme itself. the palette (`colors.d`) is re-parsed only when that directory's mtime changes (`paletteCache`).
- **Writing**: `Store.Apply` shells out to `gio set ... metadata::custom-icon <file:// URI>` (`gio set -t unset` to clear; the database belongs to `gvfsd-metadata`, never written directly), keeps the current icon basename (e.g. `folder-documents`), and re-touches the directory with its own times so Nemo repaints. The icon URI is resolved once per basename, then the per-directory `gio` calls run concurrently (at most `runtime.NumCPU()` in flight). `applyFolderColor` runs it off the UI thread, then reloads and posts the payload; errors travel in `folderColorsPayload.err`.
- **Rendering**: `ui.Model.FolderColor` (set to `Store.Lookup`) feeds `PanelContext.FolderColor` through `Model.folderColorFor`, which is nil for remote panels. `panelRowStyle`, and `resolveCarouselColumnEntry` for all three carousel columns (`panelcarousel.BodyParams.FolderColor`, from the same `PanelContext.FolderColor`), take the base style from `theme.PanelListingFolderStyle`, which tints a directory's foreground before the selected/cursor styles: selected and `ChromeBlocked` rows keep their own colours, and a cursor row keeps the tint only when its theme cursor style leaves fg unset (`PanelListingCursorStyle` keeps the base foreground then). The default folder icon follows the row foreground; status icons (open, mount, scanning, excluded) keep theme colours.
- Action `panel.folder-color-menu`: `menus.md`. End-user doc: `docs/folder-colors.md`.

## In-memory listing mutations

Synchronous rename/mkdir/duplicate/mass-rename patch `State.Entries` on the UI thread (`RenameEntry`, `InsertEntry`, `InsertEntries`; `internal/panel/listing_patch.go`) before `RefreshBothPanels`. `InsertEntries` skips foreign-parent/duplicate paths and rebuilds index/sort/filter once; `InsertEntry` delegates to it. Each mutation and each `ApplyListing` bumps `ListingEpoch`; same-directory async/periodic applies with a stale epoch are dropped so an older `ReadDir` cannot overwrite newer rows. Background jobs do not patch listings at enqueue; rows show job suffix icons (`jobs.md`) and change when the terminal `ApplyRefreshes` reload lands.

## Listing format and chrome

- `State.ListFormat`: `mtime` (name + Meta + size + modified), `perm` (... + permissions), `brief` (... + size; extra width goes to name). Root `default_listing_format` seeds both panels. `panel.cycle-listing-format` cycles the active panel; Left/Right menu -> Listing format opens `panel.listing-format-dialog`. Both are blocked in carousel mode. Header sort arrows follow sort mode (brief + sort by modified arrows the Size column; perm arrows Permissions).
- `[ui].shrunken_shows_name_only`: a panel whose list row text width is strictly below `config.ShrunkenListingRowTextWidthThreshold` draws only the name column (Meta, git, size, mtime hidden). `ListFormat` and sort are unchanged; the single-line header uses `panelListHeaderTitleWithSortArrow` so the sort arrow stays visible.
- **Zoom**: `panel.toggle-zoom-active-panel` flips the visible zoom split for this session only (cleared on Configuration OK); it is a no-op with a message while quick view / file preview is active or when the terminal is not narrower than `zoom_active_panel_disabled_above_width` (when > 0). Width shares and the wide-terminal limit are TOML-only. Config keys are in `docs/config.md`.
- **Scroll indicators**: `[ui].panel_scrollbar` (`thumb`/`bar`/`none`, icon `[icons.scrollbar] thumb`) and `panel_scrollbar_inactive` draw on the right border of main lists, the selected strip and carousel columns (own offset each); hidden when all rows fit. Theme `panel.scrollbar.track|thumb`. Implementation `internal/uiscrollbar`, wired from `drawPanel`, `drawSelectedStrip`, `panelcarousel.DrawBody`. `scroll_edge_margin` is TOML-only.
- **Preview scroll indicators**: `previewpanel.Draw` (`internal/ui/previewpanel/draw.go`) paints the same indicator for boxed side/quick-view preview, carousel child preview and fullscreen preview (`file.view`), on whichever border/margin column the mode already has. Plain fullscreen gets a static 1-column right gutter (`fullscreenPreviewTextWidth()` subtracts 1). The carousel child rect stops one column short of the panel border, so its call site passes `DrawParams.ScrollGutterX` (+`HasScrollGutterX`) to land on the real border column. Rail colour (`DrawParams.ScrollbarRailStyle`, from `drawFilePreviewPanel`): fullscreen uses the Chroma style's Comment token colour; carousel uses the panel's own non-Chroma border colour; boxed preview needs no override. Thumb/track colour follows `Theme.PanelScrollbarStyles(active, blocked)` driven by `PreviewFocused || Embedded`.
- **Shared row helpers** (`internal/panellist/size.go`): `SizeCells`, `FormatByteSizeCompact`/`FormatHumanScaled`, `FormatListedSize(entry, disk)` against a `ByteSizer` (`ui.DiskUsagePainter` and `panelcarousel.DiskUsageSource` both satisfy it), and `JoinRow(...)` for the `name  meta size` layout. `ui.formatEntry`/`panelListHeader` and `panelcarousel.formatBriefRow`/`briefHeader` call these; keep one copy.
- Code pointers: `internal/ui/panel_render.go` (`panelListReservedAfterName`, `formatListedPerm`, `formatEntry`), `State.ListColumnTitles` (`internal/panel/sort.go`), `internal/ui/dialog/listing_format_dialog_render.go`, `config_dialog_render.go`, `internal/app/dialog_settings.go`.
- **Configuration dialog footer**: F9 Edit config opens `config.toml` in `$EDITOR`; if the file is missing a Yes/No overlay (`ConfigDialogState.EditStubConfirm`) offers `config.WriteDefaultStub`. After editing, `config.LoadFromPaths` reloads `App.config` and rebuilds the dialog fields (`editConfigTOMLFromDialog`, `createAndEditConfigStub`). F8 Reset to defaults (shown only when `config.toml` exists, `App.configFileExists`) confirms via `ResetDefaultsConfirm`, deletes the file, reloads, updates the status-command ticker and reopens the dialog (`resetConfigToDefaults`). Both confirmations are overlays inside the same dialog, not separate modals.
- **Menu-bar spinner**: `App.menuBarSpinnerBusy` (`internal/app/disk_usage.go`) is true during a disk-usage scan, unfinished jobs, run-for-each batches (`commandsBatchesInflight`) or a pending navigation load with `ShowLoadingIcon`. It drives the `spinnerTickPayload` heartbeat, which the jobs light-bar also rides (`architecture.md`). `menuBarOtherActivity` is every source except file-operation jobs. What paints is `menuBarSpinnerVisible`: busy minus the job term when `[jobs].progress_lightbar` is on and `Model.MenuBarJobs.HasProgress`.

## Bottom indicators and row marks

- **Registry**: `internal/ui/panel_bottom_indicators.go` orders segments by edge + priority and truncates lowest-priority first. Start edge: cross-directory Selected when the strip is hidden. Physical-left: dotfiles-hidden icon (`DotfilesHiddenActive`), Gitignore, stash count, entry-filter chip (`PanelBottomIndicatorEntryFilter`, `Order: 4`, theme `panel.status.entry_filter`). End edge (corner-most first): job-write icon (`ui.PanelInsideJobWriteTree`, `Theme.PanelJobMarkStyle(status, true)`), Tree chip (`PanelBottomIndicatorTree`, `Order: 1`, label ` Tree `, style via the `default:` case), other-panel path (`panel.status.other_panel`, dropped first), latched Sync / Quick view (mutually exclusive). Theme keys `panel.status.{selected,dotfiles_hidden,gitignore,stash,other_panel,sync,quick_view}`.
- **Truncated cursor name**: on the active panel only, when the cursor name is clipped, the full name is drawn centred on the bottom interior row via `TextOverlay` if it fits between indicators (`panelBottomCenterOverlaySpan`, `internal/ui/panel_bottom_cursor_name.go`); also for the carousel centre column. Inactive panels omit it.
- **Hide inactive panel**: `panel.toggle-hide-inactive` gives the active panel full width; `panel.switch` while hidden shows and activates the other. Enabling hide turns off latched sync and quick view. The hidden path shows in the End edge. The flag persists across Jobs/Commands/Messages, but those views always use a normal split and keep Shift+Tab as reverse pane focus (handled before the global keymap).
- **No-permission mark** (`[icons.filelist] no_permission`, `Theme.IconFilelistNoPermission`, `panel.row.mark.no_permission`): read straight off `localfs.Entry.AccessDenied`, computed once per listing in `internal/localfs/entry.go` (`entryAccessDenied`; `access_unix.go` / `access_other.go`) with a real `unix.Access` check, not mode bits, because POSIX ACLs (e.g. `/media/<user>`) grant access that mode bits hide. Entries reach `panel.State` through `fsbackend.Entry` (`ToPanelEntry`/`FromPanelEntry` in `internal/fsbackend/entries.go`, `localEntryToBackend` in `internal/fsbackend/file/file.go`); **a field added to `localfs.Entry` must be mirrored at all three conversion points or it is silently dropped.**
- **Suffix marks** share `internal/panellist/indicators.go`: `SuffixDecorationLen`, `EntryDisplayRunes`, `SuffixSpanStyle`, `ListingSuffixSpans`. Order is job, queued, operation, then new/renamed/subtree/pin. A new `RowSuffix` flag must be handled in all four; `ListingSuffixSpans` has an early-return guard that must include every active flag.
- **Name shortening** (`internal/panellist/shorten.go`): `EntryDisplayRunes` keeps the prefix cell and symlink `@` and fits the name with `shortenName`. `planShorten` builds one width-independent step list per name (abbreviate to `shortenSoftAbbrev`, drop inner words as one centre-out gap, abbreviate to `shortenMinAbbrev`, drop the last word, shorten the first word); a width applies steps until the name fits, so narrower is always a subset of wider. A word's first abbreviation removes `shortenMinCut` runes; words with digits are only dropped; a short extension (files only, `shortenMaxExt`) is kept unless it leaves under `shortenMinAbbrev` cells; a final right cut covers what the steps cannot. `DisplayRune.Cut` marks an abbreviated word's last rune and each `…`; `ListingCutSpans` recolours those cells with `theme.CutMarkStyle` (ANSI 0–7 ↔ 8–15, bold ANSI → 0–7 without bold, RGB lightened/darkened, default foreground toggles bold) from the cell's own style. Panel (`drawPanelRow`) and carousel (`drawCarouselColumn`) append the cut spans after match spans, so fuzzy-match highlights win.
- **Pinned mark**: `RowSuffix.Pinned`, icon `Theme.IconPin` (`[icons] pin`, same as the menubar badge), style `panel.row.mark.pinned`. `drawPanelRow` reads `PanelDisplayConfig.PinnedPaths`, rebuilt each render via `ui.PinnedPathSet(model.PinnedItems)` and shared by both sides (`drawBrowserView`, `paintBrowserPanelsInScope`). It is not cached on `Model` because `PinnedItems` is mutated from two places (`pin/toggle.go` `Toggle`, `pin/dialog.go` `RemoveSelected`).
- **Other-panel match mark**: `RowSuffix.OtherMatch` / `OtherMatchCursor`, icon `Theme.IconFilelistOtherMatch` (`[icons.filelist] other_match`), styles `panel.row.mark.other_match` (bright_black) and `.cursor` (cyan; both optional in themes with built-in fallbacks). Gated by `[ui].other_panel_match_marks` (`Model.OtherPanelMatchMarks`). `otherPanelMatchNames` (`internal/ui/pin.go`) builds, per render (O(n)) for both panels, the name set of rows directly in the other panel's match dir (`otherMatchDir`: in tree layout the cursor row's folder when it is an expanded directory, else the cursor row's parent; otherwise the panel path), only when the two match dirs differ; tree layout reads visible rows (children live only there), flat layout reads `Entries`. The cursor variant is the active cursor's name in both panels; `drawPanelRow` skips `..`, rows not directly in the panel's own match dir (`PanelDisplayConfig.OtherMatchDir`), and rows carrying the active job icon (`JobSuffix.JobIcon`: a source or destination tree a job is working on, where the match is the transfer itself); queued rows keep the mark. Because the cyan mark follows the active cursor, `PaintBrowserListNavPanelOnly` repaints both panels while the option is on. `ListingSuffixSpans` takes an `onBar` predicate (nil in the carousel); when the plain or cursor mark lands on a disk-usage bar cell (`panel.usage.normal` has the same bright_black background) its foreground is forced to black.
- **Marks in dialogs/views** (Find, History, path picker, Dedup, Compare): `dialog.RowMarks` (alias of `dlg.RowMarks`) / `RowMarksFunc` (`internal/ui/dialog/row_marks.go`) are dependency-free data and a closure type (the reverse import would cycle). `dlg.RowMarksWidth` reserves 2 cells per mark; `dlg.DrawRowMarksSuffix` paints job, pin, then missing (`Missing` + `Cursor`: `Theme.IconDialogMissing`, colored by `Theme.DialogMissingIconForeground` — `dialog.option.invalid`, or `dialog.option.active` on the cursor row; set by History, path picker and Pin rows from `PathMissing`). `internal/ui/row_marks.go` `rowMarksResolver(pinnedItems, jobMarks)` supplies the lookup. Each site reserves `dlg.RowMarksWidth` from its text budget; the path picker reserves one uniform column sized to the widest row (`pathPickerRowMarksWidth`); dedup paints marks before the subtree icon (a row's path is `AbsKey` for files, `EffectiveDisplayRoot()` + `DirRel` for dirs); compare resolves marks per side. Find threads it through `PaintFindDialog` (`find_dialog_paint.go`) for partial repaints.

## Hidden files and git

- **Git-aware hiding**: with `respect_gitignore` (default on) and `show_hidden` false, listings hide paths matched by nested `.gitignore` and `.git/info/exclude`; `panel.toggle-hidden` shows dotfiles and ignored entries together. `ShowHidden` lives on each `State` but `toggleHiddenGlobal` (`internal/app/panel_visibility.go`) sets both: it is one global setting. Outside a work tree only dotfiles are affected; copy/move/delete and disk scans see the real filesystem. `GitignoreActive` shows the Gitignore indicator.
- `panel.open-dir-in-other` and `panel.open-active-path-in-other` copy the active panel's `ShowHidden` to the inactive panel before loading (`internal/app/input.go`); otherwise a directory under a gitignored ancestor would load empty.
- **Git status column** (local panels in a work tree): 2-cell status + gap before the icon strip. Header icon `[icons] git`; theme `panel.git.*`; cursor row uses the filename foreground. Detection is `gitignore.WorkTreeRoot` (independent of `respect_gitignore`). Status comes from one cached `git status --porcelain=1 --ignored` per listing directory (`internal/gitstatus`) on a background goroutine; until then it shows `- -`. **The query is scoped with a trailing `-- <listDir>` pathspec when the dir is a strict subdirectory** (`defaultGitCommand`, `internal/gitstatus/query.go`): unscoped `--ignored` enumerates every ignored file repo-wide, a measured cost on big `node_modules`/network repos. SFTP panels omit the column; name-only layout hides it.
- `prepareGitColumn` (from `ApplyListing`) fetches the cwd listing; `ApplyTreeChildLoad` calls `scheduleTreeChildGitStatus` (`internal/panel/tree_load.go`) with the same guards (skip remote, `!GitColumnActive`, nil `ScheduleGitStatus`) and reuses `State.gitWorkRoot`. `applyGitStatusLoad` (`internal/app/git_panel.go`) separates cwd-level dispatches (gated by `gitStatusLoadGen[panelID]`, newer supersedes older) from tree-child ones (bypass the counter; accepted when `GitColumnActive` and `isWithinDir(listDir, host)`), and merges into `GitByPath`, a global path-keyed cache read by `panelGitCell`.
- **`nav.open`** (Enter / Right): enters directories; on local panels runnable files (`localfs.PathLooksRunnable`: `+x` plus shebang/ELF) run via `cmdrun.Run` into the Commands view when `run_executables_on_enter`; other files open with `xdg-open` when `open_files_externally`. `App.openFileExternally` is the single entry point (also dedup tree/browse panes): an `exec.ErrNotFound` from `runDetachedXDGOpen` falls back to `OpenFullscreenFilePreviewAt`, whose async gate reports unpreviewable files in the pane.

## Meta columns

- `meta.toml` entries run a shell script with `%f` (`cmdrun.BuildInvocation`) filtered by `when` (`internal/entrymatch`, `internal/metacmds`; directories use `dirs`; legacy `extensions` keys are ignored). `runCommand` in `internal/apphandler/meta` runs `sh -c`. A failed command leaves the row empty and shows one critical toast `meta: command failed to execute` per meta run, not per file.
- `internal/apphandler/meta` (`a.metaCtrl`) owns the picker dialog, per-panel worker pool, result cache and the F9 edit-config flow. Private `Handler` state: active names, per-panel cancel funcs and generations, a `sched.Debouncer` for render flush, `loadGen`/`loadPending`, the cache. `ui.Model.MetaResults`/`MetaDialog` hold render-visible state. `scheduleRenderDebounced` is first-arm-wins; the timer callback only posts `RenderFlushPayload`. `ReconcileForPanel` and `ActivateSelection` never read `meta.toml` on the event loop (placeholder columns, then `startAsyncLoad`); `HandleLoad` requires matching `loadGen`, panel path and `ActiveNames`. Editor reload (`rerunSinglePanel`/`OpenFileEditor`) loads synchronously after the terminal is released. ## Carousel (parent | current | child)

- `State.CarouselMode`: when on and the panel is wide enough (`config.MinCarouselColumnWidth` per column, `MinCarouselPanelInnerWidth`), the list shows three columns in one frame. Side panes are read-only; navigation, fuzzy filter and group select act on the centre column. An active carousel panel always uses zoom layout (ignoring `zoom_active_panel`, `panel.toggle-zoom-active-panel` and the wide-terminal limit) and widens its share to fit. Toggle: `panel.toggle-carousel` or Left/Right menu -> Carousel view. Stored `ListFormat` is untouched. Tree mode and carousel are mutually exclusive (see Tree).
- **Column split**: `[carousel].split` and `[carousel].show_size` (defaults in `docs/config.md`). Tokens: fixed cells, `N%` of width remaining after fixed columns, `*` flex, fit-to-content `<N`, `<N%`, `<<N`, `<<N%` (min of measured content and cap). Plain `<` measures the longest name (`maxFitEntryTextLen`); `<<` sets `IgnoreOutlier` and uses `fitListingTextLen` (peels a lone outlier; n>=10 also caps at the 90th percentile). Measured fit widths add a fixed `fitSuffixReserve` (`config.CarouselFitSuffixSlots` × `panellist.SuffixSlotCells`) after the longest name so up to three row suffix indicators (subtree selection, pin, job marks, ...) never truncate it; it is fixed rather than measured from live suffixes, which would make the column width flicker. **Fit is valid only for parent (0) and centre (1)**: the child can show a file preview, so a fit token there is rejected at parse (`internal/panelcarousel/split.go`) and validation (`internal/config/carousel.go`) time and falls back to the default split.
- **Geometry is measured once per render pass** by `panelcarousel.MeasureFitColumnWidths` (`row.go`, scans the full listing so width does not jitter while scrolling) and threaded as `measuredFitWidth [3]int` into `SplitColumns`, `ChildPreviewPaintRect`, `DrawBody` (`BodyParams.MeasuredFitWidth`) and `CenterNameWidth` from `drawPanelCarousel` so all agree. Unmeasured callers (`Layout.Resolve`, `MinInnerWidth`, `ChildColumnWidth`) fall back to the cap. A parent whose cached snapshot is stale is still measured from that stale snapshot: skipping it would resolve the column at its cap and balloon the layout for a frame. The embedded file preview's wrap width (`carouselChildPreviewLayoutMetrics`, `internal/apphandler/preview/carousel_file.go`) mirrors this computation, including `ui.CarouselMeta(...).Width`.
- **Content**: icon + name (+ size per `show_size`) on every column; Meta only on the centre column, laid out once per pass by `ui.CarouselMeta` (`meta_layout.go`) into `panelcarousel.Meta{Width, Header, Row}`; no git/mtime/perm. Disk-usage bars still paint. Row formatting delegates to `panellist.JoinRow`; `nameWidthForColumn` and fuzzy highlight spans (`match.go`) shrink by `2 + metaW`. Row icons use `panelIconStripContextFor` (`internal/ui/panel_icon_strip.go`), the one constructor for panel row painters (preview prefetch loading mark: `preview.md`).
- **Autohide**: `[carousel].autohide_inactive_panel` hides the inactive panel whenever the active one is in carousel mode, derived per frame by `App.carouselAutohideInactivePanel` (`internal/app/render.go`) and OR'd into `Model.HideInactivePanel` on the render snapshot, never into the persisted flag (so manual `panel.toggle-hide-inactive` is unaffected). `panel.switch` shows the other panel; if it is not itself a carousel both stay visible. Does not engage with sync follow or quick view. `carouselFilePreviewEligible` (`preview/carousel_file.go`) needs the same OR, because `panelcarousel.FilePreviewEligible` treats a hidden inactive panel as full width.
- **Snapshots are pure cache reads.** `panel.SnapshotParent`/`SnapshotChild` (`internal/panel/preview_listing.go`) read only `State.CarouselSideCache`; painting never blocks on I/O. They return the last cached snapshot even when stale (so navigation does not flash the column) and are blank only when structurally empty (parent: no path / at root; child: cursor not on a directory, or outside coalesce) or never fetched. `CarouselParentCacheValid`/`CarouselChildCacheValid` (`carousel_child_cache.go`) decide whether to dispatch, not what to paint. Fetches run via `scheduleCarouselParentSnapshot`/`scheduleCarouselChildSnapshot` (`internal/app/carousel_async.go`, same `raceAsyncListingFetch` race), apply in `applyCarouselSnapshot` / `BuildListingSnapshotFromEntries`, and repaint through `App.renderAfterAsyncApply` (single-panel partial repaint, `renderBrowserListNavUpdate`).
- **Dispatch** (`preview.Handler.ReconcileCarouselSidePreview`, every Run-loop event, both panels) is driven by cache validity, not by input events, so any cache invalidation (chdir default highlight, history cursor restore, filter/sort reorder, deletion) re-triggers a fetch. `carouselSideState` records the in-flight target per column; `carouselSideDispatch.shouldFetch` is the gate. A failed fetch (error or list timeout) must call `Handler.NoteCarouselSnapshotFailed` (from `applyCarouselSnapshot`), otherwise neither dispatch condition is ever satisfied again and the parent paints stale. A per-column `carouselRetryGate` (`carousel.go`) applies `carouselRetryCooldown` to a failed target only (keyed by target, so other directories dispatch immediately). The child column yields to the nav-coalesce debounce (`[ui].key_repeat_debounce_ms`, or `image_preview_debounce_ms` for image/media), repainting the last cached preview (`CarouselChildPreviewCoalesce`); chdir clears the child cache (`ApplyListing`).
- **Deferred paint on folder change**: with a fit-to-content parent, geometry comes from the parent listing, so painting when the centre load lands would lay out against the previous directory then relayout. `App.renderAfterAsyncApply` holds the repaint while `carouselParentPaintPending` (carousel on, not at root, parent cache invalid for the cwd); the parent snapshot's arrival releases it. Release is guaranteed: `raceAsyncListingFetch` always posts a result (timeouts included), `carouselSnapshotPayload` renders on arrival regardless, and `armCarouselPaintDeferTimer` force-releases after `carouselPaintDeferMaxMS` (`carousel_async.go`; arm/epoch pattern like `armDirLoadingIndicatorTimer`). `applyCarouselSnapshotAndRender` ignores a landing child snapshot while the parent is pending, since a small child routinely beats a large parent and would reintroduce the relayout.
- **Two-pane layout**: when the centre listing has no child subdirectories and file preview is ineligible, or quick view is on, the child column is omitted and its width folds into the centre; child debounce is inactive.
- **Embedded file preview**: with the cursor on a file and the child column at least `config.MinCarouselFilePreviewColumnWidth` wide (or the inactive panel hidden), the rightmost column runs `[preview].command` (same gate/argv/ANSI path as quick view and fullscreen preview (`file.view`), `preview.md`) via `Model.CarouselFilePreview`; directories use `SnapshotChild`. No scrolling inside it (use `file.view`).
- Theme: `panel.carousel.inactive.row.cursor` (+ `.selected`); `panel.{active,inactive,blocked}.header.carousel` for parent/child headers.

Code: `internal/panel/tree_state.go`, `tree_load.go`; engine `internal/treeflat` (shared with Find-duplicates).
- `panel.toggle-tree` enables tree mode on first press and toggles expand/collapse on the cursor directory (`App.toggleTreeForPanel`, shared by `tryDispatchPanelLayout` and the scoped menu item, mnemonic `v`). - `VisibleEntryCount`/`VisibleEntry` branch on `ListLayout` (flat body `flatVisibleEntry`). Selection, group select, invert, fuzzy filter, sync and the disk-usage bar denominator (`state.VisibleEntries()` in `panelColumnLayout`) all use these tree-aware accessors. ### Tree keys

Eight actions (`internal/keymap/specs.go`, `HelpBrowser`, "Sort & display"), plus `panel.toggle-tree`:

| Action | Method | Auto-enables tree |
|---|---|---|
| `panel.tree-expand` | `ExpandTreeCursorRow` | yes |
| `panel.tree-collapse` | `CollapseTreeCursorRow` | no |
| `panel.tree-collapse-all` | `CollapseAllTree` | no |
| `panel.tree-collapse-all-full` | `CollapseAllTreeFully` | no |
| `panel.tree-expand-all-shallow` | `ExpandAllTreeShallow` | yes |
| `panel.tree-expand-all-full` | `ExpandAllTreeFully` | yes |
| `panel.tree-prev-sibling-dir` | `JumpTreeSiblingDir(-1)` | no |
| `panel.tree-next-sibling-dir` | `JumpTreeSiblingDir(+1)` | no |

Directory history back/forward is `nav.backward`/`nav.forward`; the history dialog uses a separate chord. Dispatch is `tryDispatchPanelLayout`; app wrappers (`expandTreeForPanel`, `collapseAllTreeForPanel`, ... in `internal/app/panels.go`) auto-enable then call the method and show "Tree view is not available in carousel view" when blocked. Dedup has its own `[dedup]` overlay (`internal/keymap/dedup_overlay.go`), a separate context from `[main]` that also accepts plain Left/Right.

- **Collapse** (`CollapseTreeCursorRow`): collapses an expanded cursor directory in place; otherwise walks back through `treeRows` to the nearest row with smaller `Depth` (the parent, guaranteed by `Flatten`'s pre-order), collapses it and moves the cursor there unless already depth 0 (same walk as `dedup.Handler.CollapseOrParent`, which only jumps).
- **Expand** (`ExpandTreeCursorRow`): expands a collapsed directory; on an already-expanded directory each further press deepens that subtree by one frontier level (`deepenTreeUnderCursor` / `expandSubtreeOneLevel`), cursor stays, files no-op, using quiet `setTreeNodeExpanded` so fetches coalesce.
- **Sibling jump**: scans visible rows at the subject's depth (cursor directory, or its parent when on a file), skipping files and children, no wrap.
- **Expand all shallow** deepens one absolute level per press up to `panel.MaxExpandAllShallowDepth`; beyond that `ErrExpandAllDepthLimit` (info toast). **Expand all full** arms `treeExpandAllAuto`; `driveExpandAllTreeAuto` loops the per-level step and `finishTreeChildLoadApply` re-invokes it as each level's loads land. Breadth is capped by `panel.MaxExpandAllTotalRows`: `driveExpandAllTreeAuto` checks `len(treeRows)` before each level and clears the cascade with `ErrExpandAllRowLimit` (a level already in flight may overshoot). `finishTreeChildLoadApply` rebuilds `treeRows` as a level's last fetch lands, before that check, otherwise the count is a level stale. The row-limit toast only shows when the first synchronous level trips it; the cascade stops either way.
- **Collapse-all is not the inverse of expand**: expand uses one shared absolute depth (`treeExpandAllDepth`), collapse peels each branch's own frontier (`collapseExpandedLeaves`: an expanded directory with no expanded directory child; recurses first, so a node with an open descendant stays this round). Absolute-depth collapse looks dead on uneven trees (it spends a press on the deepest branch only). Under an active entry filter `collapseExpandedLeaves` skips branches the filter does not match; **`expandAllTreeDirsAtDepth` must not be filter-aware**: a directory's `GitByPath` cell arrives via `scheduleTreeChildGitStatus`, independent of the listing fetch the cascade gates on, so a filter-aware expand reads a zero cell and cuts the cascade short (`TestExpandAllTreeFullyOutrunsLaggingGitStatus`). Because of that asymmetry the counter can strand above zero, so `CollapseAllTree` snaps it to 0 when `anyExpandedInFilterScope` finds nothing expanded; with the counter already 0 (or `TreeExpanded` out of sync) it falls back to `CollapseAllTreeFully`, which clears everything. `CollapseAllTree` also disarms `treeExpandAllAuto` first so a running cascade does not re-expand.
- `State.TreeExpandAllDepth()`/`TreeExpandAllCascading()` are read-only exports; every expand/collapse-all key shows a "Depth: N/5" toast (`showTreeExpandAllDepthToast`). For the full cascade, `applyTreeChildResults` re-fires it when `TreeExpandAllCascading()` flips true->false, so the count visibly climbs.
- **Cursor anchoring during a cascade**: `ExpandAllTreeFully` captures `treeCursorID` once, and every level reuses it (re-deriving from the numeric cursor would walk the selection as rows insert; a manual single-level press does re-derive). Every redraw during a cascade reattaches by `treeCursorID` (`PeekTreeRows`, and the dispatch branch of `finishTreeChildLoadApply`, both via `reattachTreeCursorByID` after `rebuildTreeRows`), otherwise the displayed row jumps. `Move`/`Top`/`Bottom` and `JumpTreeSiblingDir` call `syncTreeCursorIDToCursor` so a deliberate user move sticks.
- **Abandoning loads**: `CollapseAllTree`/`CollapseAllTreeFully` call `abandonTreeChildLoads` (recursively clear `TreeEntry.Loading`, reset `treeExpandQuiet`, call `State.CancelTreeChildLoads`). Clearing `Loading` makes `ApplyTreeChildLoad` reject late results, which would otherwise re-set `TreeExpanded`. `ApplyListing` calls it before re-rooting and `SetListLayout` when leaving tree mode.

### Tree recall across navigation

Every directory change funnels through `State.load` -> `ApplyListing`, so any navigation path remembers the directory's expanded set, expand-all depth and highlighted entry; returning restores all three (in memory, session only). This extends `HistoryCursorByPath map[string]historyCursorSnapshot` (`rememberCursorForPath`, `resolveLoadCursor`/`recalledCursorFor`, capped at `maxNavHistory`, pruned by `pruneHistoryCursors`); in tree mode the snapshot also holds `CursorPath` (absolute path, since `Cursor` indexes `treeRows` and names can repeat across nested dirs), a clone of `TreeExpanded` and `TreeExpandAllDepth`. `treeExpandAllAuto` is reset (never restored) wherever the depth is reset or restored, so an orphaned cascade cannot misfire later.

- `ApplyListing` re-roots `TreeRoots` fresh from the new listing first (cached subtrees are never reused). Same-directory reload keeps the live `TreeExpanded`; navigation clones the recalled set (empty on a first visit). `restoreTreeExpansions` then walks the whole fresh tree once per navigation, sending every remembered directory through `setTreeNodeExpanded` (no `ReadDir` on the UI goroutine). With `ScheduleTreeChildLoad` wired, the first paint shows it collapsed-but-loading; `ApplyTreeChildLoad` expands it and calls the subtree-scoped `restoreTreeExpansionsIn` to cascade. Without a scheduler (tests) loading is synchronous and nested levels restore in one call. A failed load drops its id from `TreeExpanded`; a remembered directory missing from the fresh tree is never visited and its flag is inert.
- **Cursor recall order**: `SelectVisibleEntry(EntryName)` or clamped `indexFallback`, then a tree-only override `selectVisibleEntryByPath(snap.CursorPath)` (no-op on miss). Same-directory reload reattaches by node ID captured before the reload (`priorTreeCursorID`), which name-only recall cannot do for same-named entries under different parents. `treeCursorID` is also set from `CursorPath` so a later async cascade reattaches when the row appears.

### Tree async child loading

- `State.ScheduleTreeChildLoad` (`TreeChildLoadScheduler`, `internal/panel/tree_load.go`; nil = synchronous, like `RemoteLoadScheduler`) is wired in `wireTreeChildLoaders` (`internal/app/tree_load.go`) to `panel.FetchListing` + `ListingRefreshSnapshot` with `ListTimeout = SFTP.ListTimeoutSecs`. All tree listings (periodic refresh, expand/expand-all, `prefetchTreeChildren` on re-entry) go through the app-wide `treeListQueue` (`internal/app/tree_list_queue.go`): `config.DefaultTreeListWorkers` workers started on demand, priority user > caret > visible > offscreen, FIFO within; jobs check their ctx first.
- **Periodic tree refresh**: `State.TreeRefreshPlan` re-lists the caret parent/row first, then parents of on-screen rows, then `config.DefaultTreeRefreshOffscreenDirsPerTick` off-screen dirs round-robin (`treeRefreshRR`), so off-screen changes can lag (upgrade: fs watching). When the root or a re-listed dir changed, the payload carries every loaded dir's children (baseline overlaid by fresh results) so the re-root reattaches from memory; only the fresh subset (`TreeFetched`) feeds disk scans.
- **Results are queued, not posted one-per-fetch.** tcell's event channel is a fixed 10-slot buffer shared with key input, and `PostEvent` drops when full; one blocking `PostEventWait` per fetch saturated it and dropped keystrokes. `App.treeChildResults` (`treeChildResultQueue`) is a mutex-guarded slice plus a `posted` flag; only the goroutine flipping `posted` false->true calls `PostEventWait(treeChildResultsReadyPayload{})` (blocking is safe, at most one caller). The wake carries no data; `applyTreeChildResults` drains the whole queue per wake (`drain` resets `posted`), so at most one tree-load event is ever pending.
- Each drained result calls `ApplyTreeChildLoad`; if none triggered a redraw, `PeekTreeRows` runs once per batch (a `rebuildTreeRows` that skips `treeExpandQuiet`/cascade bookkeeping but reattaches by `treeCursorID`). **At most one progress render per drained batch, never time-interval based**: an interval re-ran many times inside one long drain and starved `PollEvent`. Batches self-pace because a new wake cannot post until the drain finishes.
- `ApplyTreeChildLoad` calls the **subtree-scoped** `restoreTreeExpansionsIn`; the whole-tree variant per completion made a cascade O(n^2) and stalled one drain for seconds.
- `setTreeNodeExpanded` (shared by all expand/collapse methods) marks the node `Loading`, rebuilds `treeRows` so the icon shows `TreeEntry.Loading` -> `FolderIconScanning`, dispatches and returns. `TreeExpanded[id]` is set only when `ApplyTreeChildLoad` succeeds, so the row stays collapsed-but-loading. Stale results are dropped by a per-node check (`findTreeNode` nil or `!Loading`); no generation counter is needed. Failure sets `LoadErr`, leaves `Children` nil so a later expand re-dispatches; expanding a `Loading` node is a no-op. No placeholder child row is synthesised (`Flatten` reveals children only when non-nil). Cursor reattaches to `treeCursorID` when set, else the loaded `dirID`, never overwriting an existing anchor.
- **Quiet batching**: with `treeExpandQuiet > 0`, applies before the last in a level return false (no render). `ExpandAllTreeShallow` rebuilds `treeRows` unconditionally after dispatching a level so Loading icons show immediately; the level-terminal apply always reports a redraw, and inside a full cascade every level-terminal apply does.
- `applyTreeChildResults` also feeds disk usage: directories on local panels not cached or pending are collected into one `Engine.StartScanFromListing` per drain (after `filterJobContendedPaths`), so expanded-directory sizes use the same cache as selection-size and explicit scans.

## Entry-visibility filters

- `internal/panel/entry_filter.go`: `EntryFilter{ID, Label, Match(entry, *State), Applicable(*State)}` (nil `Applicable` = always). `State.ActiveEntryFilter` holds at most one filter; installing another replaces it. `SetEntryFilter` falls back to none if `Applicable` already fails, rebuilds the filtered index and clamps the cursor; `ClearEntryFilter` = `SetEntryFilter(nil)`; `RefreshEntryFilter` re-evaluates after dependent data (async git status) changes; `ClearFilterIfInapplicable` runs in `ApplyListing` right after `prepareGitColumn`, so leaving a repo drops a git filter.
- `rebuildEntryFilter` walks the unfiltered space (`Entries` flat, `treeRows` tree) into `filteredIdx`; in tree mode a passing row also makes its ancestor rows visible (one pre-order pass with a per-depth ancestor stack), so a nested match keeps its path. It runs first in `rebuildFilter` (the fuzzy ranking reads through `VisibleEntry*`). `rebuildTreeRows` always calls `rebuildFilter` so `filteredIdx` never goes stale. `VisibleEntryCount` is `len(filteredIdx)` when active; `VisibleEntry` and `TreeRowShape` map display index to raw via `translateVisibleIndex`. **In tree mode `s.Cursor` is a filtered display position, not a `treeRows` index: tree cursor operations must go through `rawIndexForCursor`/`cursorForRawIndex`**, or they act on the wrong node.
- Connectors (`├─`/`└─`/`│`) come from `Flatten` over the raw child list; filtering can hide siblings, so `recomputeFilteredTreeConnectors` re-derives `LastChild`/`AncestorHasNext` into `filteredTreeShape`, and `TreeRowShape` returns that while a filter is active.
- **Git filters** (`internal/panel/git_filter.go`; menu `internal/app/git_filter_menu.go`, `menus.md`): `GitStagedFilter`, `GitUnstagedFilter`, `GitTrackedFilter`, `GitUntrackedFilter`, all `Applicable` = `GitColumnActive`, reading `GitByPath`. `applyGitStatusLoad` calls `RefreshEntryFilter` after merging results. Tree-child arrivals are coalesced via `State.gitStatusChildPending` (incremented in `scheduleTreeChildGitStatus`, reset in `prepareGitColumn` so stale fetches cannot strand it, decremented by `NoteTreeChildGitStatusApplied`, which reports reaching zero); the refresh runs only then, because per-arrival refresh (O(visible tree)) plus render made filtered expand-all flicker.
- **Pattern filter** (`internal/panel/pattern_filter.go`): `PatternFilter(spec FilterSpec, meta)` compiles via `panel.NewGroupMatcher` (the group-select matcher), label `Filter: <pattern>`, filters directories like files, always applicable (survives `cd`/refresh). `State.CountPatternMatches` gives the dialog a plain (files, dirs) total over visible entries (unlike `CountGroupMatches`, which counts only selection-state flips). The Filter dialog (`internal/ui/dialog/state_filter.go`, `filter_dialog_view.go`, `filter_hint.go`, `filter_dialog_render.go`; `internal/apphandler/dialog/filter.go`) is a `dlg` dialog (`FilterDialogView`, spec shared with Select group in `pattern_dialog_view.go`) and mirrors Select group (same radios and type checkboxes, Files/Dirs only, Case sensitive; plus Invert) but always targets the active panel. Files only and Directories only are checkboxes; checking one unchecks the other. With Directories only selected, the type checkboxes are `Disabled` items (`dialog.PatternTypesDisabled`: drawn dimmed, not focusable, mnemonics inert), `patternToggles.apply` refuses them, and `FilterTypesRegexp` returns nil. Confirming an empty pattern clears the filter (the only way); reopening starts empty. User docs: `docs/panel-filter.md`. Twin of Select group: mirror changes (`dialogs.md`, Twin dialogs).
- **Quick filter**: engine `internal/quickfilter` + `internal/search` (fzf subset, basename-focused); panel-local (Dedup panes and the Commands list reuse it via `handleListFilterKey`); Esc cancels; cycling uses visible order unless ranked cycling is configured. While active, any chord resolving in the global keymap dismisses the filter (`CancelFilter`) and runs, except a fixed set in `App.quickFilterRetainsKey`/`shouldHandleFilterKey` (`internal/app/app_input.go`): unbound printables, Backspace (editing/non-empty query), Enter on empty overlay, Up/Down/Insert.
- **Sort dialog**: `panel.sort-dialog`: panel-local mode, reverse, dirs-first, optional disk-usage idle ordering (`internal/ui/sort_dialog_render.go`). Applying with the disk-usage box on over an analysed, fully cached listing switches to disk-total ordering at once (`State.activateDiskTotalsSortIfCached`, shared with listing apply); otherwise the idle timer applies it after the next scan.

## Disk usage (`internal/diskusage`)

- `disk_usage_descend_into_mount_points` (default off): walks compare each directory's device id to the panel cwd's cached `st_dev` (set after each load) and do not cross devices. Scanning from inside a remote mount still walks it fully, since rows share the cwd device. `[adaptive_io]` (`initial_workers`, `max_workers`, `adapt_interval_ms`; `docs/config.md`) tunes adaptive concurrency for disk-usage walks, find indexing and find-duplicates reads.
- Cache updates apply in chunks per walked subtree so the UI can read between them. While busy, repaints are debounced and limited to scan-scope panels plus the spinner (`ui.PaintDiskUsageBrowserPanelsOnly` / `App.paintDiskUsageBrowserUpdate`); job finished forces a full refresh.
- `~/.goduignore` basename rules and mount-boundary skips use a dedicated folder icon (U+F114); `panel.icon.folder.excluded` grey applies only while metering is shown. Painters read `IsKnownExcluded` only, never `DiskScanExcluded` (no `Stat` on paint); the engine classifies off-thread at session start and when the walk hits an ignored dir.
- `Engine.Abort`, `ClearCache`, generation bump and shutdown cancel the worker session context, which is passed into `WalkFolder` so a superseded scan stops descending; a walk finishing after cancel is dropped by generation.
- **Scan scope** is global: a scan records the listing path and its immediate children as roots. Row bars and idle disk-total sort apply on either panel while its cwd is the listing or inside a scanned child; navigating elsewhere turns both off until returning. `DiskUsagePanelID` only affects scan-folder tint on the queuing panel.
- **Origin total**: the explicit scan queues through `Engine.StartScanFromDirectory(origin, children, ...)`. The worker reads `origin` itself (`withUnlistedChildren`) and adds children the listing omitted (hidden dotfiles) as roots. When the job finishes in the same generation, `cacheOriginTotal` caches `origin` as the sum of its walked direct children, so the parent listing's size column shows it. `PendingForPanel` reports `origin` (exact match only) as pending while its job is queued or running.
- **Rename** remaps cached totals (`Engine.RemapPath`/`RemapPaths`, called from `apphandler/dialog` after `ops.ExecuteRename`/`ExecuteMassRename`) so idle sort keeps valid keys.
- `panel.disk-usage-clear` (`[main]`) aborts the scan, drops the cache and scope, clears idle sort on both panels and refreshes listings.

## Background I/O yields to an active job's volume

Git status, periodic refresh, disk-usage scans and preview prefetch each read the current mount on their own schedule. On slow network mounts (SMB/NFS or a `slowfs` mount, `slowfs/setup.sh`; mount it outside the repo) they compete with a copy/move job for the same latency budget, and the combined load makes the job and UI feel stuck (not a deadlock: `PollEvent` keeps returning). Each checks `App.pathVolumeContendsWithActiveJob` (`internal/app/volume.go`) at its **dispatch point** and skips *new* work when the path shares a local `st_dev` with an unfinished job's source or destination (`jobs.Job.VolumeDevs`, cached at enqueue):

- **Prefetch**: `SchedulePrefetchFromActivePanel` (`internal/apphandler/preview/prefetch.go`) returns early via `Host.PathVolumeContendsWithActiveJob`.
- **Git status**: `gitStatusScheduler` (`git_panel.go`) returns `false` ("didn't schedule"), leaving pending/generation bookkeeping untouched.
- **Periodic refresh**: `schedulePanelListingRefresh` returns before flipping `panelRefreshInFlight`.
- **Automatic disk-usage scans**: `applySelectionScanNeed` (`selection_size.go`) and `applyFindDialogSelectionScanNeed` (`find_dialog_selection_size.go`) filter through `App.filterJobContendedPaths` and skip if nothing survives. **Explicit requests are never gated**: the `u` scan (`startDiskUsageScanForPanel`) and the delete confirmation summary (`ApplyDeleteDialogScanNeed`, `apphandler/dialog/delete.go`). The delete summary uses `Engine.StartPriorityScan` (preempts the running scan job, bumps the generation, requeues its unfinished roots) and `Engine.InvalidateRoots` (O(roots), UI-safe, unlike an applied directory removal's full cache sweep). `EventJobFinished.QueueEmpty` gates the "Disk usage scan finished" toast.

Each retries on its own trigger, so skipping is self-healing. **Layering: `internal/jobs/volume.go` imports `internal/diskusage`, so `diskusage`/`gitstatus`/`preview/prefetch` must not import `internal/jobs`**; coordination lives in `internal/app` plus the two `Host` forwarders. Limits: in-flight work is never preempted (mid-walk preemption would need a "device busy" callback through `StartScanFromListing`); `ComputeVolumeDevs` skips remote endpoints, so SFTP-only transfers are not covered; per-subsystem throttles (e.g. `background-scan-throttle.md`) only account for other jobs.

## Selections

### Selection set

- **Range select**: `panel.select-range` first sets `State.RangeAnchor` (a path) to the cursor entry; the second press adds every visible entry between anchor and cursor via `AddSelection` (never toggles off), clears the anchor and toasts the count. An anchor that is no longer visible is replaced by the cursor entry. Leader key `k`, File menu `k`. While an anchor is pending the anchor row shows a suffix flag (`RowSuffix.RangeAnchor`, icon `Theme.IconFilelistRangeAnchor` = `[icons.filelist] range_anchor`, U+F11D, style `panel.row.mark.range_anchor`) and that panel's cursor row uses `panel.row.cursor.range` / `panel.row.cursor.range.selected` (yellow bg, all chrome states; `PanelListingCursorOpts.RangePending`, `panelCursorIconThemeKey`). All three style keys are optional with built-in fallbacks. The carousel does the same for its centre (active) column only: `drawCarouselColumn`/`resolveCarouselColumnEntry` set `RowSuffix.RangeAnchor` and `RangePending` when `c.Active`; the side columns never show the flag. The anchor lookup is `primitive.RangeAnchorIndex`, shared with Compare and Dedup, and the toasts come from `primitive.RangeMessage` via `App.announceRange`.
- Each panel keeps a selection set keyed by absolute path across directory changes. `panel.select-toggle`, group select and `AddSelection` use `panel.ClearSelectionConflicts`: adding a path removes selected strict descendants and selected directory ancestors; the toggle shows a warn toast "Removed conflicting selections". `BulkAddSelections` is the same conflict-aware merge for bulk paths.
- **Select / Unselect group** (`panel.select-group` / `panel.unselect-group`; Find dialog `find.select-group` / `find.unselect-group`): modal with mode radios Shell patterns (default, Alt+S), Regular expression (Alt+R), Simple substring (Alt+L); the same Videos/Pictures/Archives/Audio/Documents checkboxes as Filter (`dialog.FilterTypeLabels`/`FilterTypeMnemonics`, Alt+V/P/A/U/T, built by `dialog.FilterTypesRegexp` from `[filter.types]`, OR-joined and AND-ed with the pattern, basename only even with Match full path; ignored, and the checkboxes disabled, while Directories only is selected (`dialog.PatternTypesDisabled`, enforced by the `Disabled` items, `patternToggles.apply` and `FilterTypesRegexp`, so the find-context request carries no Types either); types alone with an empty pattern select by type, no pattern and no types selects nothing; no Invert); Files only (Alt+Y), Directories only (Alt+D), Case sensitive (Alt+E, honoured in regex mode too), Match full path (Alt+H, find and output contexts only). Matching is on basename. The `output` context (opened from the user-menu output dialog, see `commands.md`) matches the dialog's detected paths instead of panel entries, with the same `find.NewPathMatcher` predicate as find, and is an intentional extension Filter does not mirror. Matching goes through `panel.FilterSpec.MatchFunc` (`State.SelectGroup`/`UnselectGroup`/`CountGroupMatches` take a `FilterSpec`); the find context builds one predicate per request in `find.NewPathMatcher` (`GroupSelectRequest.Types`). Both dialogs are built by one function (`patternSpec`, `pattern_dialog_view.go`; `GroupSelectView` in `groupselect_dialog_view.go`), so focus, Tab stops, mnemonics and the `dialog.PatternDialogWidth` frame are shared; Up from the buttons lands on Match full path when it is shown and no meta row follows. `panel.NewGroupMatcher` compiles once per apply; an invalid pattern shows an inline hint and blocks OK with a critical toast. Layout: Pattern label (live preview right-aligned) -> input -> a reserved hint row (the dialog never grows). The preview (`<files> <file-icon> <folders> <folder-icon>`, `theme.Theme.IconFile`/`IconFolder`, zero segments omitted) is recomputed per keystroke by `App.updateGroupSelectPreview` (from `reconcileAfterEvent`) and counts only entries whose selection state would change, via `State.CountGroupMatches` or `find.Handler.CountGroupMatches`. The input renders in error style (`dialog.input.*.error`) when the pattern fails or matches nothing (`groupSelectPatternInvalid`, `internal/ui/dialog/groupselect_hint.go`). Twin of Filter: mirror changes (`dialogs.md`, Twin dialogs).
- **Selection count/size**: with a non-empty selection the UI shows `N item(s) (size)` in `panel.status.selection_size` with `[icons].working` while selected directories lack cached sizes. The byte total sums pruned roots (`panel.PruneNestedPaths`, O(n log n)). Placement: centred on the panel bottom border when the strip is hidden; right-aligned on the strip's bottom border when visible (use the padded-label helpers, see `dialogs.md`). A strip whose selections span several parents shows `theme.IconSelectedMultiLocation` (`[icons.selected] multi_location`) as an end label on its top border (`drawAuxPanelChrome`, `State.SelectedCommonRoot`). Background walks reuse `diskusage.StartScanFromListing` from `App.reconcileSelectionSizeScans` (no bars, no toasts; `DiskUsageShown` stays false; skipped when `SelectionHasDirs()` is false); remote panels show count + known file sizes.
- **Large selections**: single toggles patch derived state incrementally (`selection_derived_cache.go`: strip paths, pruned roots, subtree marks); bulk ops (`InvertSelection`, `SelectGroup`, stash restore) invalidate once. `SelectedDirPaths` and `listingByPath` give O(1) lookups; file-only adds skip conflict scans when no directory is selected; listed file bytes are cached in `selectionListedBytes`. Find OK uses `BulkAddSelections` with the dialog's `Entries` mirror and `PathMeta` (no per-path `Lstat`). Find marked-selection count/size uses the same pattern (`find_dialog_selection_cache.go`; `reconcileFindDialogSelectionSizeScans` exits early on unchanged `MarkedSelGen`).
- **Multi-directory transfer**: copy/move of a selection spanning several parents always shows the transfer dialog's multi-location Source/Result preview and preserves directory structure below the common root (`file-operations.md`). `panel.open-selected-root` navigates to that root (single-dir selection: its parent; none or already there: info toast). Shared computation `State.SelectedCommonRoot` (`internal/panel/selected_common_root.go`), used by `App.navigateToSelectedRoot` and `Handler.multiDirSelectionCommonRoot` (`apphandler/dialog/transfer.go`).

### Selected strip

- When a panel has selected paths outside the current directory it can render a Selected strip (`internal/ui/selected_strip_render.go`); rows are prefixed ` ○ ` in the selected foreground for files and directories alike.
- **Layout**: side-by-side orientation puts it under the list, capped by `[ui].selected_panel_max_rows` when unfocused and `selected_panel_active_percent` of column height when focused (height = `min(itemCount, cap)`); stacked orientation draws it to the right of the list using that percent of width. Split logic `geom.SplitPanelForSelected`. The inactive panel omits the strip (selections remain); `SelectedStripLayoutItemCount` (`internal/ui/selected_strip_layout.go`) is the single gate shared with viewport helpers, and the bottom-border Selected indicator covers the omitted case (icon-free). With the theme picker open the left column still splits so the preview matches.
- **Focus**: `panel.focus-selected`. `App.focusSelectedStrip` is the single entry point: if every selection is inside the cwd it sets `State.StripForced` (`SetStripForced`) to show the strip anyway; with no selection it shows a "No selected items" warning. `reconcileSelectedStripFocus` (first thing in `reconcileAfterEvent`, i.e. every `render()`) clears `StripForced` elsewhere and drops focus to the list when `ActiveSubFocus` is the strip but `SelectedStripCount()` is 0 (cancelling any strip filter). Mutation paths still reset focus inline (e.g. `selectParentDirs`, `panel.clear-selection`) because `ActiveSubFocus` must be correct right after `dispatch()` returns, not after the next render.
- **Strip filter**: printable keys / `panel.filter-open` edit `State.StripFilter`, fuzzy-matching basenames via `internal/search`; Up/Down cycle, Esc cancels, title shows `> query` (`fuzzy.input`/`fuzzy.input.nomatch`). Leaving focus, switching panels or clearing cancels it.
- **Keys while focused**: arrows/page/home/end navigate. `nav.open` (`navigateFromSelectedStrip`) opens the directory containing the highlighted path and puts the cursor on it (`pathloc.Path.Parent`/`Base`; strip visibility also uses `Parent`). `panel.select-toggle` deselects the row. `panel.clear-selection` clears all and returns to the list. `file.view`/`file.edit` use the list handlers on the highlighted row (directories warn as in the list; edit is local only). Latched-sync follow uses `State.StripNavTarget`, which reads listing / `SelectedDirPaths` metadata and never calls `os.Stat`/`filepath.Dir` (so `sftp://` stays backend-neutral): file rows mirror the parent, directory rows themselves, unknown types count as files. Other globally bound actions (`app.open-menu`...) are ignored until focus returns.
- **Vi-motion**: `panel.vi-motion-toggle` toggles it (with the strip filter active Esc only cancels the filter); border uses `panel.vimotion.frame`; j/k move, l opens (Enter), h is a no-op. `:` (`app.leader-menu`) opens the "Selected menu" from `leaderMenuViewSpecs[keymap.HelpSelectedStrip]` (View, Edit, unselect row, Select parent dirs `p`, Go to selected common root `r`, Clear selection, Copy, Move, Delete, Flatten, Run for each, Help, Quit), activating via `dispatchActionLikeKeyboardShortcut`; `tryDispatchSelectedStrip` forwards the menu, parent-dirs, selections-root, delete, flatten and run-for-each actions to `dispatch()`. With vi-motion on, plain letters fire that scope directly (`ActionForLeaderKeyInView(r, HelpSelectedStrip)`); other letters start the strip filter. `HelpSelectedStrip` is a leader-menu scope only, not an `app.show-help` view.
- **Footer** `menu.FunctionKeysSelectedStripView`: `app.show-help` Help, `app.user-menu` Parent dirs, `file.view` View, `file.edit` Edit, the live `panel.clear-selection` label + Unselect all, `app.quit` Quit; in vi-motion each shows its leader letter (`viMotionFooterKeys`).
- **Select parent dirs** (`panel.select-parent-dirs`): no default global chord. `app.user-menu` while the strip is focused invokes it: `tryDispatchSelectedStrip` (`internal/app/panels.go`) intercepts `keymap.ActionAppUserMenu` and calls `a.selectParentDirs()` (same reinterpretation pattern as other strip-resolved actions). Users may bind their own chord. It replaces the panel's whole selection with the unique immediate parent directories of every selected path: `State.SelectedParentDirs` -> `ParentDirsExcludingSelf(paths)` -> `panel.ParentDirsOf` (`internal/panel/selection_parent_dirs.go`), which uses `pathloc.Parse` + `.Parent()` (sorted, deduplicated; unparsable or root paths skipped; `pathloc`, not `filepath.Dir`, so `sftp://` works). **Every consumer applying a parent-dir set to a panel (the strip action and the Find dialog's `find.select-parent-dirs`, `navigation.md`) must go through `ParentDirsExcludingSelf`**, which drops the panel's own cwd (it is not a listed entry of itself). Result is applied with `BulkAddSelections`. Toasts: none selected -> "No selections"; only parent is the cwd -> "Already in the containing directory"; conflict removal -> "Removed conflicting selections" (warn); else "Selected N director{y,ies}".

### Selection stash

Each panel has one stash slot (`SelectionStashPaths`, `SelectionStashStripOrder`). `panel.stash-toggle` on the active panel: empty stash + selection -> save and clear selection (`StashSaveFromSelection`, which merges into a non-empty stash: the Compare selection guard uses that, see [views.md](views.md)); empty stash + no selection -> status message; stash + no selection -> restore and clear stash; stash + selection -> Stash restore dialog (Replace Alt+R, Merge Alt+M, Drop stash Alt+D, Drop all Alt+A, Cancel Alt+C / Esc keeps both stash and selection). Panels stash independently. Code `internal/app/stash.go`, `internal/ui/dialog/stash_restore_dialog_render.go`. Pinning (`panel.pin-toggle`, `navigation.md`) is a separate ad-hoc pin list.
