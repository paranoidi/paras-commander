# File operations

Foreground dialogs and their execution. Handlers live in `internal/apphandler/dialog` (`dialogctrl.Handler`); execution in `internal/ops`; queueing in [jobs.md](jobs.md). User-facing behavior: `docs/fileoperations.md`, `docs/mass-rename.md`, `docs/elevation.md`.

## Source resolution and snapshots

- Source rule: selected entries first, else the cursor entry. Single-entry dialogs use `ResolveSourceSingle` and reject a non-empty selection where it applies.
- Delete and rename operate on the **snapshot taken at open** (`DeleteEntries`, `RenameSource` from `OpenDeleteDialog`/`OpenRenameDialog`), not the later cursor. `[operations].confirm_delete=false` still snapshots, then enqueues without a dialog.
- Successful mutations refresh both panels and try to keep the cursor on the affected entry. Same-directory reloads (`panel.State.Refresh`, `ApplyPeriodicRefresh`, `ToggleHidden`) keep `ScrollOffset` when the highlight row index is unchanged. If the inactive panel's cwd was removed, `RefreshBothPanels` (`internal/apphandler/dialog/file_ops.go`) climbs it to the nearest existing ancestor in one step (`RefreshOrNavigateToExistingAncestor`). Rename/mkdir/mass-rename patch `Entries` in memory (see [panels.md](panels.md)); jobs do not. `RefreshBothPanels` re-runs quick view from each panel's `OnApplied`.

## Dialog input

- Form focus: `FileDialogFocusForm` builds one Tab segment per leading text input, an options segment for later radios/checkboxes, then buttons. Mkdir radios, rename/duplicate checkbox and run-for-each pool rows are their own groups.
- Input editing defaults live in `DefaultDialogInputOverlayKeys` (override under `[dialog.input]`): clear (`ui.input.kill-line`; `ui.input.kill-line-backward` also clears fuzzy rows), restore default (`ui.input.restore-default`), `ui.input.kill-word-backward`, word motion (`ui.input.backward-word` / `ui.input.forward-word`). Word boundaries: letters/digits/underscore (`internal/ui/lineedit`).
- Single entry points: `dialog.TryDialogInputFieldActions` and `dialog.HandleFileDialogFieldKey` (`internal/ui/dialog/dialog_field.go`) for `FileDialogField` rows (used by `apphandler/dialog` and the app-side SFTP-connect dialog). `App.handleScrollingQueryKey` (`internal/app/scrolling_query.go`) over `scrollquery.HandleKey` plus the `ScrollingQuery` type (`internal/ui/dialog/scrolling_query.go`) cover every fuzzy-filter row (path picker, Help, Find, History, SFTP connect, mass-rename pickers, run-for-each history, panel Filter / `panel.select-group` group select, `preview.theme-picker` style picker).
- Fuzzy-filter rows paint a leading search icon inside the row instead of a `Filter:` label row (`draw.ScrollingInputState.LeadingIcon`, `Theme.IconSearchIcon()`, `[icons.search] icon`, ASCII `/` fallback; painted by `draw.PaintScrollingInputContent`). Filter and group-select keep a blank spacer and right-aligned match count (`filterPreviewText`/`groupSelectPreviewText`); the style picker has no label row.
- Horizontal scrolling and `◀`/`▶` overflow icons: `EnsureScrollInputVisible` (`internal/ui/dialog/internal/draw/chrome.go`), `DrawScrollingDialogInput`, `drawInputField` (see [navigation.md](navigation.md)). `fileDialogWidth` floors at `PreferredFormDialogWidth` and sizes from labels/static messages/mkdir radios, never from field values, so the frame doesn't resize while typing.

## Rename and mass rename

- Rename and mass rename stay synchronous. Each success is recorded as a finished `rename` job so it appears in the jobs view and can be undone with `jobs.undo` (see [jobs.md](jobs.md), Undo).
- `file.rename`: no selection opens single **Rename** (same directory only; rejects path separators and non-UTF-8 results). **Focus after rename** (Alt+A, `[operations].rename_focus_after`) selects and centers the new name via `SelectVisibleEntryCentered`. `file.rename.open-sanitize` / `file.rename.open-slugify` / `file.rename.open-encoding` (`[dialog.rename]`) open Sanitize / Slugify / Encoding sub-dialogs; Encoding appears only when `filenameenc.DetectCandidates` finds legacy Japanese encodings and previews the decoded name.
- A non-empty selection in the current directory opens **Mass rename** (`ui.FileDialogMassRename`). Pure logic: `ops.MassRenameCompute` / `MassRenameComputeCapitalize` / `MassRenameRowErrors` / `MassRenameValidateRows` / `ExecuteMassRename` (`internal/ops/mass_rename.go`); duplicates, external collisions and illegal results are validated, and renames apply via a two-phase temp rename for dependency chains. OK stays focusable but Enter / `ui.input.dialog-ok` show a critical message while conflicts exist. Theme: `[dialog.massrename]` `dialog.massrename.*`; match-count icon `[icons.mass_rename] match`.
- Modes (radios 0-3, applied on focus, no confirm): Simple (literal replace per basename), Regex (Go `regexp`, `$n`/`${n}`, `\1`-`\9` aliases), External `$EDITOR` (`MassRenameModeUIExternalEditor`: temp file one name per line, `withTerminalReleased`, line count must match, result in `MassRenameExternalNames`, OK blocked until set, Enter relaunches), Capitalize (`MassRenameModeUICapitalize`: **Capitalize each word**, **Treat punctuation as separators** which auto-enables the former).
- **Focus index map** (`FocusedField`): radios `0`-`3` in every mode. Simple/Regex: Find/Pattern `4` (`MassRenameFindFieldFocus`), Replace `5`, Show only modified `6`, Strip spaces `7`, Case insensitive `8`, content ends `9`. External: modified `4`, strip `5`, ends `6`. Capitalize: modified `4`, strip `5`, capitalize-each-word `6`, punctuation `7`, ends `8`. OK/Apply/Cancel follow the content end (`MassRenameApplyFocusIndex`); three trailing buttons come from `FileDialogFocusForm` reusing `DialogTrailingButtonsForm` (same as the transfer dialog's OK / Add paused / Cancel). Tab groups: `massRenameMoveFocusKey` open-codes the segment rule because the fields come after the radios; each text input is its own stop. `MassRenamePreviewViewportRows(mode)` gives External/Capitalize a taller viewport.
- **Apply** (Alt+A, `ApplyMassRenameKeepOpen`) runs the same validate-and-execute pipeline without closing: refreshes panels, re-selects the batch under its new paths, refreshes `MassRenameSources`, clears the fields and `MassRenameExternalNames` (re-arming the External gate), recomputes the preview and refocuses `MassRenameFindFieldFocus`.
- **Saved patterns**: `[dialog.mass_rename]` `file.mass-rename.load-pattern`, `file.mass-rename.save-pattern`, `file.mass-rename.history`, `file.mass-rename.delete-pattern`. `FileDialogState.MassRenamePhase` (`internal/ui/dialog/state_file_dialog.go`) selects the screen of the one dialog: `Main`, `SavePrompt` (stashes Find/Replace in `MassRenameSavedFields`), `LoadPicker`, `HistoryPicker`, `OverwritePicker`. The pickers share `MassRenamePatternPickerState`, `drawMassRenamePatternPickerContent` and `Handler.handleMassRenamePickerKey`; `dialog.MassRenamePickerPhase` is the single predicate for them and `currentMassRenamePickerState` picks the backing state (history vs load/overwrite). Pickers preselect the last loaded/saved pattern (`massRenamePatternName`). `file.mass-rename.save-pattern` on the save prompt opens the Overwrite picker (a second action on the same chord in that overlay would fail `keymap.Build` chord uniqueness): `overwriteMassRenamePattern` -> `ops.UpsertMassRenamePattern`, keeping name and description unless Description was typed. Patterns live in `patterns.toml` (`[mass_rename].file`, else `<config dir>/patterns.toml`, `internal/ops/mass_rename_patterns.go`); history is session-only (`maxMassRenameHistory`).

## Mkdir, duplicate, attributes, extract

- **Mkdir** (`file.mkdir`): prefill from the cursor (files drop the last extension; directories and bare dot-names keep the name). After Create the active panel highlights the new directory (`SelectVisibleEntryInViewport`, honors `scroll_mode`). `file.mkdir-open-in-other` sets `MkdirOpenInInactive`: the inactive panel enters the new directory. With selections the dialog adds Create / Create and copy / Create and move radios (`MkdirShowActions`, `MkdirAction`; Alt+R / Alt+Y / Alt+M work while the name field is focused). With 2+ selections `file.mkdir.extract-common-name` (`[dialog.mkdir]`) prefills the longest common substring (`ui.ExtractLongestCommonName`). `executeMkdir` creates first, then queues `TypeCopy`/`TypeMove` via `Deps.Jobs`; copy/move variants clear selection, plain Create doesn't. Local mkdir is synchronous; remote runs on a worker and lands via generation-tagged `RemoteFileOpPayload` -> `ApplyRemoteFileOp` (so an SFTP password prompt can be delivered), taking copy/move sources from the listing snapshot (no Stat).
- **Duplicate** (`file.duplicate`): exactly one entry (file or directory); the destination is the exact copy target. Name field matches rename semantics (`file.rename.open-sanitize` / `file.rename.open-slugify`, **Focus after duplicate**, `rename_focus_after`) and queues a copy job via `ops.ValidateDuplicateSource`/`PlanDuplicate`; focus applies after the job completes and the entry exists.
- **chmod/chown/symlink/hardlink**: `PlanChown` trims both fields, rejects both-empty, and uses UID/GID `-1` for an omitted side. `executeChmod`/`executeChown` plan on the caller, then `startAttrOp` runs syscalls on a worker and completes via `RemoteFileOpAttr`. Symlink/hardlink use the plain file-dialog submit path. All four are blocked on remote panels.
- **Extract** (`file.extract`, File menu `x`): destination defaults to the passive panel; enqueues `TypeExtract`; the worker runs `internal/archive` + `ops.ExecuteExtract` through `cmdrun.Run` (no shell). Tools are found with `exec.LookPath`; unsupported/tool-less items are skipped at confirm time with a toast (that wording is only for those skips). Existing or batch-colliding stream outputs stay in the plan and use `ExtractPlan.Conflict` (set by `jobbridge.TransferFunc` to the jobs overwrite blocker). Container tools get keep-existing flags (`unzip -n`, 7z `-aos`, rar `-o-`, tar `-k`). Stream formats decompress to `dest/<basename-minus-suffix>`. A remote destination is probed on a worker (`RemoteFileOpPayload`); `drawMultiFieldDialog` paints `FileDialogState.Message` for skip warnings.
- **Delete dialog**: summary from `ui.PathsDeleteImpact`/`FormatDeleteImpactSummary` via the shared disk-usage engine (`ReconcileDeleteDialogScans`, `internal/apphandler/dialog/delete.go`, reusing a selection snapshot rather than `ops.ResolveSource` per reconcile). `OpenDeleteDialog` calls `diskusage.Engine.InvalidateSubtree` so earlier operations can't show stale totals; totals always descend into other mounts regardless of `disk_usage_descend_into_mount_points`. Rows are `DeleteListEntry` names (fitted by `FitPathForWidth` at paint), height capped at 80% of the terminal with `DeleteDialogMaxListRows`, with a list scrollbar on the right border when entries overflow (`ctx.ScrollbarStyle`); `DeleteLayoutMinWidth` is cached at open; updates repaint via `paintDeleteDialogOverlay`/`renderDeleteDialogUpdate` without a full `ui.Render`. Focused Yes uses `dialog.button.active_destructive`.

## Flatten

`file.flatten` (File menu `F`) needs a directories-only selection (mixed aborts with a toast before the dialog). Destination prefill follows `[operations].flatten_default_location`; options `flatten_recursive`, `flatten_remove_empty_dirs`. Destination footer: Bookmarks / History / Pinned / destination-panel shortcuts (see Path picker below and [navigation.md](navigation.md)). On OK, `confirmFlatten` validates synchronously (`ops.ValidateFlattenTarget`: roots non-empty, destination not strictly inside a root; the destination probe always goes through `RemoteFileOpPayload`) and enqueues `TypeFlatten` with nested roots pruned to minimal ones; the dialog walks nothing. The dialog is `FlattenView` (a `dlg.Spec`, see [dialogs.md](dialogs.md)): destination input, Recursive / Remove empty directories checkboxes, OK / Cancel; `Handler.HandleFlattenDialogKey` runs the completion dropdown and destination shortcuts first, then `dlg.HandleKey`, then the field editor, and `DrawFlattenDialog` paints the completion dropdown from the destination input's placed rect.

`ops.ExecuteFlatten` is a single streaming pass moving each entry through `moveOne` to `dest/<name>` (recursive descends; non-recursive moves immediate children, directories whole). Rules:
- Conflicts use the normal resolver; a skipped file keeps its directory.
- Non-recursive flatten expands same-name nesting (`aaa/aaa`) by processing the child's children.
- Files whose final path equals a flatten root are deferred to the end, parked as `<name>.flatten` (`.1.flatten`, ...), emptied directories removed, then renamed; if the final path still exists the job fails naming it.
- Remove-empty-dirs removes each directory right after its children when empty, roots included.
- No total is announced (jobs view shows `?`); `DoneFiles` counts moved items.

## Overwrite and directory mismatches

A conflict where exactly one side is a directory (real, or a symlink to one), or a directory meets a symlink to a directory, can only be skipped, renamed or canceled; nothing is merged through a symlink. `ops.FileConflictFacts.OverwriteUnsafe()` (`SourceTarget`/`DestTarget`, filled by `StatFileConflictFacts` and `statConflictFacts`) decides it, and `resolveConflict` converts any overwrite on a mismatch into skip. The copy plan's directory items (`copyDirItem`) hit the same path: skipping drops the subtree (`copyRunState.skippedDirs`), renaming re-roots it (`renamedDirs`). Dialog details and remembered-decision handling are in [jobs.md](jobs.md); rationale in ADR 0011 and 0019.

## Copy/move destination dialog

- Shared state and renderer: `dialog.TransferDialogState` / `DrawTransferDialog`. `file.move` always opens the destination dialog (even with one shared path and no selection); same-directory rename stays on `file.rename`. Destination is a path-picker `FileDialogField` prefilled with the passive panel path plus a trailing separator.
- Copy-only checkboxes: preserve permissions, preserve timestamps, dereference symlinks (Alt+R / Alt+T / Alt+D); preserve toggles are stored on `jobs.Job` at enqueue. Dereference is greyed out (focusable, inert) when source or destination is SFTP (`TransferDialogState.DereferenceUnsupported()`); semantics in [jobs.md](jobs.md).
- Buttons in both phases (destination and self-copy rename): OK, **Add paused** (Alt+P, enqueues `StatusPaused`), Cancel.
- Destination-row footer: Bookmarks, History, Pinned, and `ui.destination-active` / `ui.destination-inactive` (labelled "Active path" and "Inactive path"). The same action pair is bound in `[dialog.transfer]` and `[dialog.flatten]`.
- **Destination target highlight**: while the destination field is open and its text resolves to a panel's cwd, that panel's frame/title use `panel.target.frame` / `panel.target.title` for Copy, or `panel.target.warning.frame` / `panel.target.warning.title` for Move and Flatten (`PanelContext.IsTransferTarget` + `TransferTargetWarning` in `drawPanel`, fed by `Model.DestinationTargetWarning`). Computed on the same debounced tick as `DestPathInvalid` (`updateDestinationTargetPanels` via `pathpick.ResolveQuery`, `[ui].path_picker_validate_delay_ms`); both panels light up if both match. Reset on close and when a self-copy rename starts. Local paths only.
- **Focus transferred entry** (`[operations].focus_other_panel_after_transfer`): `AddTransferJob` arms the shared `pendingPanelFocus` (also used by duplicate focus-after; retried by `RefreshBothPanels`/`ReconcilePendingPanelFocus`) when the destination equals the inactive panel's cwd, with the top-level dest names and a snapshot of that panel's cursor path. After the terminal refresh it selects the first candidate via `SelectVisibleEntryInViewport` only if the panel is still there and the cursor hasn't moved.
- **Multi-location preview**: when the selection spans more than one parent, `App.openTransferDialog` (the single copy/move funnel) fills `TransferDialogState.CommonRoot`/`.Entries` and the same dialog gains a **Source:** header and **Result** preview (`MultiLocation()`; sizing via `transferMultiChromeRows`, `TransferListViewportRows`, `TransferListMaxRows`). It triggers regardless of the panel's current path. Width is computed from un-flattened labels so toggling **Flatten into destination** (Alt+I, last content row) never resizes. `App.multiDirSelectionCommonRoot` -> `panel.State.SelectedCommonRoot` (`pathloc.CommonAncestor`). Mixed-scheme or single-directory selections skip it. Sources are re-resolved from `SelectedPaths` at confirm. The span also drives the selected-strip icon ([panels.md](panels.md)).
- **Structure preservation**: destination names are batch-relative to the sources' deepest common parent (`ops.TransferNameRoot`/`TransferDestName`, `ResolveDestinationNamed`): `dir_a/f1`, `dir_a/f2`, `dir_b` copy to `dest/dir_a/f1`, ... unless Flatten-into-destination is checked. Move fast path creates missing parents (`ensureParentDirs`). `ops.SelfTargetCount(sources, destDir, flatDestNames)` stats `destDir` once (not per source); the flatten dialog uses it too. One source of truth for flat naming: `Job.FlatDestNames()` (`TypeFlatten || FlattenIntoDest`) feeds `ops.Options`/`PlanBuildOptions`/`ScanWalkHooks.FlatDestNames`; `TransferPreserve.FlattenIntoDest` carries the checkbox through `AddTransferJob`. Local destinations are probed on the UI goroutine at confirm; remote ones on a worker (`RemoteFileOpPayload`) so a password prompt can't deadlock confirm; `AddTransferJob` never Stats a remote destination. Tests: `internal/ops/transfer_structure_test.go`.
- **Self-copy/move**: if the resolved destination equals the source (`ops.ResolvedSameAsSource`) a single transfer switches to a **New name** step (`TransferPhaseSelfCopyRename`); reusing the original name errors. Multi-source self-overwrite is rejected with a warning. Copying into a strict subdirectory of a source is rejected at plan time (`ops.DestinationUnderSource` in `BuildPlanCtx`).
- **Dangling directories** (`[operations].remove_dangling_directories`): browser move/delete jobs get `Job.PromptDanglingDirs` at enqueue (`AddTransferJob`/`EnqueueDeleteJob` apply the config gate; callers pass `promptDangling`). On `EventCompleted`, `stashDanglingSourcesForCompletedJob` stashes `Sources` with no I/O; `ApplyRefreshes` drains it and `ops.DanglingDirsAfter` (`internal/ops/flatten.go`) climbs from each source's parent while entries are emptied directories, returning only the topmost of each chain. `Host.PromptDanglingDirDelete` either toasts "N empty directories left behind" (another modal open) or opens the delete dialog with `DeleteDanglingDirs` set, **Yes** default (already-empty dirs are low risk). `ExecuteDelete` checks `DeleteDanglingDirs` before the `ViewMode` branches and re-enqueues with `removeEmptyDirs=false, promptDangling=false` (no loop). Dedup deletes pass `promptDangling=false`: they have their own empty-dirs confirm (`openDedupEmptyDirsConfirm` via `Deps.Dedup`, see [views.md](views.md)). Test: `internal/ops/dangling_test.go`.

## Path picker validation and completion

- Path-picker hosts: bookmarks quick-cd, plus Bookmarks / History / Pinned / All apply-to-field pickers for transfer, flatten and any `PathPicker` file-dialog field (see [navigation.md](navigation.md)).
- History lists drop paths that no longer exist; bookmark rows show a missing indicator. Ghost completion is not cached: `pathpick.SuggestAtCursor` runs `os.ReadDir` on the resolved parent, and open fields re-sync after panel refresh and on each debounced validate tick. `EnsurePathInputScroll` keeps the caret visible after Tab/End.
- **Validation**: path-shaped text (absolute, contains a separator, leading `~` or `.`) is `Lstat`ed after an idle debounce (`[ui].path_picker_validate_delay_ms`); each keystroke restarts it, and `pathPickerValidateGen` / `transferDestValidateGen` (`internal/app`) discard stale `time.AfterFunc` callbacks. Plain fuzzy text skips `Lstat`. Missing paths use `dialog.input.active.error` / `dialog.input.inactive.error`.
- **Completion**: with the caret at end-of-line and path-shaped text, the ghost suffix is painted in `dialog.input.*.placeholder` (`QueryCompletionSuffix`/`DrawScrollingDialogInput`; destination field via `CompletionSuffix`/`drawInputField`). Tab accepts it (appending `/` for directories) instead of moving focus; with no suffix, Tab moves per the form. The destination field shares the same shape and debounce rules (`DestPathInvalid`, `DestPathCheckPending`).
