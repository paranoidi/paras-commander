# Keybindings and shortcut tables

How default shortcuts are declared, layered and validated. Add-a-shortcut procedure: `recipes/add-keybinding.md`. User-facing list: `docs/shortcuts.md`.

## Pieces

- Action ID consts: `internal/keymap/actions.go`.
- `DefaultActionSpecs()` (`internal/keymap/specs.go`): global `[main]` defaults plus help/menu metadata.
- Overlay default maps (`Default*OverlayKeys`) in `internal/keymap/*_overlay.go`, each with an allowed-identifier set (`AllowedIn*Overlay`) that validation enforces.
- `buildBundle` (`internal/keymap/load.go`) assembles `Bundle.Global`, `Jobs`, `Commands`, `Messages`, `Compare`, `Terminal`, and the dialog overlays (`DialogInput`, `RenameDialog`, `BookmarkDialog`, `FindDialog`, `HistoryDialog`, `MetaDialog`, `FlattenDialog`, `TransferDialog`, `RunForEachDialog`, `PinDialog`, `FilePreviewSearch`). There is no promotion or copying between maps. `keymap.Default` is `Build(DefaultActionKeys())` (global map only).
- **Theme picker**: `[dialog.theme]` (`theme_dialog_overlay.go`: `theme.toggle-auto-reload`, `theme.next-preview`, `theme.prev-preview`) is `Bundle.ThemeDialog`; `App.handleThemeDialogKey` looks the chord up before the widget engine. The footer entries come from `themeDialogOverlayFooterKeys` (`MenuBindingLabel`, so a rebound chord shows through and a footer click replays it); the hint carries the state ("Reload on" / "Preview 1/3"); the previous-page action is the Shift-alternative word ("Back") of the next-page entry, via `appendShiftTwinFooterKey`.
- **Columns dialog**: `[dialog.columns]` (`columns_dialog_overlay.go`: `panel.columns.save-profile`, `.load-profile`, `.delete-profile`, `.default-profile`, scoped to the dialog like `panel.history-both-panels`) is passed to `meta.Handler` as `Deps.KeysColumnsDialog`; `Handler.HandleDialogKey` looks the chord up before the widget engine, per phase. The action ids appear in the keybindings stub and in `specs.go`; the footer labels come from `MenuBindingLabel`, so a rebound chord shows through.
- `Map.ActionBindings` pre-seeds canonical TOML strings (`M-j`, `M-c`, ...) from specs and overlay defaults so menu hints stay in TOML form.
- **Preview search overlay**: `[preview_search]` (`file_preview_overlay.go`) is consulted only while a fullscreen-preview search query is being typed (`preview.Handler.handleFilePreviewSearchNavKey`), unlike `[preview]`, which is consulted before `[main]` unconditionally. `preview.search-next/prev` are bound in both tables deliberately (`n`/`N` in `[preview]`, arrows and `C-j`/`C-k` in `[preview_search]`).
- **Letter menus**: `keymap.letterMenus` (`menu_keys.go`) is the one list of single-letter menu tables (`[leader_key]`, `[copy_menu]`, `[preview_menu]`, `[fileindex_menu]`): each entry's defaults (from an `ActionSpec` letter field) and validator. `LoadFromPaths` layers each with `mergeMenuKeys`, `parseKeybindingsFile` returns them by table name, `buildBundle` validates each and fills the `Bundle` fields, and `validateKeybindingsTopLevel` accepts them through `isLetterMenuTable`. A new letter menu adds one entry plus its stub field.
- **Key display**: `keymap.FormatChord` (and `keymap.DisplayKey` for a TOML string) is the one formatter for every key hint: help (`helpkeys.JoinDisplay`), pulldown/leader menus and footers (`MenuBindingLabel`, `MenuBindingLabelPreferOverlay`). It emits the `keybindings.toml` notation (`C-f`, `M-i`, `M-I` for Alt+Shift+I, `C-M-d`, `S-Tab`, arrows as glyphs). `Binding.KeyStr` stays the raw TOML string because ordering and `PreferredKey` matching compare it against `ActionSpec.DefaultKeys`; convert only at the display edge. Hand-written key text in dialogs and docs uses the same notation.
- Table names: `internal/keymap/shortcut_tables.go` (single source, used by `keymap.overlayRegistry`); parsing: `shortcut_parse.go`.

## Layering and validation

- `keymap.LoadFromPaths` layers each table independently: defaults < `keybindings.toml`. Overlay maps resolve before the global map while their view/dialog is focused.
- **Reload**: handlers keep the `*keymap.Map` pointers from startup, so a configuration reload swaps bindings in place: `Bundle.ReplaceFrom` pairs every map field (`Bundle.mapFields`; a test checks it covers every `*Map` field) and calls `Map.ReplaceWith`, which swaps the chord table and resets the `ActionBindings` cache; the letter-menu maps are replaced outright.
- Shortcut tables in `config.toml` fail `config.LoadFromPaths` (unknown field). `[jobs]` in `config.toml` is job settings; the jobs-view shortcuts are `[jobs]` in `keybindings.toml`.
- **Dialog OK / Cancel**: `ui.input.dialog-ok` and `ui.input.dialog-cancel` are `[dialog.input]` defaults and the only place their chords are bound. `App.handleKey` resolves them once (`dispatchDialogButton`, `internal/app/dialog_buttons.go`, reading the buttons of `App.activeDialog`); dialog key handlers must not look for them. `F9` stays "edit config" in the Configuration and meta dialogs.
- Namespace restrictions: `jobs.*` only under `[jobs]`; `commands.*` only under `[commands]`; `ui.input.*` only under `[dialog.input]`; `file.rename.open-sanitize`/`open-slugify` only under `[dialog.rename]`; other dialog actions only under their `[dialog.*]` table.
- `pc --config-stub` writes `config.toml` (`config.EncodeDefaultStub`), `keybindings.toml` (`keymap.EncodeDefaultStub`, all tables) and commented `menu.toml`/`meta.toml`/`pools.toml` into `~/.config/pc/` (or a given dir); existing files are kept. New global defaults and overlay defaults appear in the stub automatically.

## Where specific defaults live

- **Jobs**: `jobs.open` and `jobs.answer-blocker` (answering a blocker is a command, not a view switch) are `[main]` so they work from browser and dialogs, and over other primary modals for the blocker quick dialog. Other `jobs.*` (including `jobs.undo`, `jobs.show-results`, `jobs.result-filter`, `jobs.reset-filter`, `jobs.expand`, `jobs.collapse`, `jobs.copy-message` and `jobs.toggle-operations-layout`) live in `DefaultJobsOverlayKeys` (`DefaultKeys: nil`).
- **Commands**: `commands.open` is `[main]`; `commands.close` (plus hardcoded Esc), `commands.terminate` (SIGTERM) and `commands.kill` (SIGKILL) are in `DefaultCommandsOverlayKeys`. Terminate/kill target only rows with `Phase == CommandRunRunning` (else a transient warning). Process handles live in `commandsctrl.Handler`'s private `procs` map (`internal/apphandler/commands/proc.go`: `SetProcess`/`UnregisterProc`/`signalCommandRow`), filled through `cmdrun.RunTracked`'s `onStart` from `runFileExecuteCommand` (`internal/app/run_executable.go`), `runUserMenuCommand` (`user_menu.go`) and `runForEachUnifiedBatch`. Jobs deliberately has no kill: jobs own no signalable subprocess; it only has `jobs.cancel` (`[jobs]`; see `menus.md`). `file.run-for-each` is an ordinary `[main]` action.
- **Terminal panel**: `terminal.toggle-panel` (show/hide only) and `terminal.focus` (opens the panel first if hidden) are `[main]`, and are repeated in `[terminal]` so they still work with focus inside the panel. `terminal.grow` and `terminal.shrink` are `[terminal]` only; `app.drop-to-shell` is `[main]` and repeated in `[terminal]`; only these five ids are allowed there (`AllowedInTerminalOverlay`). `internal/app/input.go` dispatches toggle/focus; `internal/app/terminal_panel.go` uses `App.keys.Terminal` for grow/shrink/PTY input (`subshell.md`).
- **fileindex**: the `fileindex.*` actions are `[main]` (help section `File Index`), dispatched by one `input.go` case into `fileindexctrl.Handler.Dispatch`. All of them are Alt+Shift+letter chords, one modifier for the feature, even for the actions that change data (the free Ctrl letters ran out, and C-a is a common tmux/screen prefix). Their `[fileindex_menu]` letters are the chord letters in lowercase; `fileindex.menu` opens that menu (see `menus.md`, `docs/fileindex.md`).
- **Folder colour**: `panel.folder-color-menu` is `[main]`, dispatched in `input.go` and from the Left/Right pulldown (`activateScopedPanelMenu`); see `menus.md` and `panels.md`.
- **Git menu**: `panel.git-filter-menu` and `git.stage` / `git.unstage` / `git.untrack` are `[main]`, dispatched through the normal action switch (`input.go`); see `menus.md` and `panels.md`.
- **Pin**: `panel.pin-dialog` (plus Navigation-section leader mnemonic `n`) and `panel.pin-toggle` are `[main]`; toggle works from the main panel, Find, History, Bookmarks, Compare and Dedup (`navigation.md`). `pin.view`/`ui.open-primary`/`ui.open-secondary`/`pin.remove`/`pin.remove-all` are `[dialog.pin]` only (`AllowedInPinDialogOverlay`).
- **Find dialogs**: `[dialog.find]` serves Find, the Find in index dialog and the file-list path picker (view, edit and open-in-panel only; `navigation.md`); there is no separate overlay table.
- **Command output**: `command-output.toggle-selection` is `[dialog.command_output]` only (`AllowedInCommandOutputDialogOverlay`); `Bundle.CommandOutputDialog` reaches `commands.Handler` as `Deps.KeysCommandOutputDialog`. The cursor keys themselves (arrows, hjkl via `keymap.RemapViMotionKey`) are fixed, not actions.
- **Rsync**: `file.rsync` is a `[main]` action with no default chord (every free F-key and Ctrl letter nearby is taken); it is reachable from the File menu and the File group of the leader menu. Its dialog reuses the `[dialog.transfer]` destination chords like Extract.
- **Destination shortcuts**: `ui.destination-active` / `ui.destination-inactive` are one action pair with one spec, bound independently in `[dialog.flatten]` and `[dialog.transfer]`.
- **Path picker host shortcut**: on copy/move destination and symlink/hardlink path rows the picker opens with the global `bookmark.open` chords (`App.tryPathPickerHostShortcut`, footer hints read the global map).
