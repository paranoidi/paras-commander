# Theming

UI theme TOML only; preview syntax highlighting (Chroma) is a separate system (`preview.md`). Add-a-key procedure: `recipes/add-theme-key.md`.

## Themes tree

- `themes/default.toml` is the only tracked theme. It uses only the 16 ANSI colors: every `[palette]` value is an index 0–15 or `"default"` and no style names a hex color (`themes/embed_test.go`), so it follows the terminal's palette; derived tints belong in imported themes. `themes/embed.go` embeds every `*.toml` at the package root, so themes generated locally into `themes/` are embedded in local builds only; `.gitignore` ignores `/themes/*.toml` except `default.toml` and all of `themes/import/`, so they never reach CI or releases. Disk themes load from the config themes dir; a declared `name` overrides an embedded theme of the same name.
- `themes/import/` (gitignored, local only) holds the importer scripts; `themes/import/src/` holds the source schemes in Alacritty format, which pc cannot load directly. `import_alacritty.py` (stdlib Python) turns them into pc themes; `build.sh [--chroma] [OUT_DIR]` imports every scheme in `src/` (with `--chroma`, only those whose header says `import_chroma.py` made them) into `themes/`, first deleting every previously generated theme there (one per `src/` scheme), and then runs `--check`. `import_alacritty.py --check <generated files>` lists the styles still below target and exits 1 if any; `--selftest` runs the built-in assertions; `--out DIR` redirects output (default `themes/`); `--tune-dir DIR` redirects the tune files. `themes/trash/` is discards; `themes/preview/` is Chroma XML.
- **Chroma import**: `import_chroma.py <style>...` derives an Alacritty scheme into `src/` from a Chroma syntax style in the Go module cache (version from `go.mod`), mapping token colors to ANSI slots (Error→red, String→green, Class→yellow, Function→blue, Keyword→magenta, Builtin→cyan, Comment→bright_black, LineHighlight bg→black; bright variants equal normal; a style without a `Background` is white with black text, as in Pygments). A style with a LineHighlight background also gets `[colors.selection]` (that background, text = foreground). `--all` converts every style not already in `src/` and not in the script's `SKIP` set (monochrome styles and near-duplicates of Alacritty schemes). An existing file is never overwritten without `--force`, and `--force` still refuses a file whose header is not `# Generated by import_chroma.py` (`--all --force` regenerates every Chroma-made scheme and skips the rest).
- **Generation**: the importer uses `default.toml` as its template, parsed line by line because the template is not strict TOML, and swaps only `[palette]`, so a new style key in `default.toml` appears in regenerated themes; regenerate rather than hand-edit. The generated palette keeps the scheme's own 16 ANSI colors unmodified and adds semantic names `fg`, `bg` (primary foreground/background), `surface` (bg mixed 12% toward fg in OKLab), `muted` (fg/bg midpoint nudged to at least 3:1 against `bg` and `surface`), `range_bg` / `range_unselect_bg` (bg mixed 20% toward the scheme's yellow / red) and `cursor_dim` (bg mixed 18% toward fg: the cursor row of inactive, carousel-inactive and blocked panels), plus roles, which exist only where the importer picks something other than a plain ANSI slot: `cursor_bg` / `cursor_fg` (the current item: active cursor rows incl. dedup cursor rows, the selected menu-bar entry, the active dialog button, the selected path-completion item and its match, the hovered footer entry), `header_bg` (panel headers and the menu dropdown fill and frame) and `accent` (shortcut letters, key hints and match highlights: `footer.key`, `menu.bar.accent`, `leader_menu.key`, `dialog.help.key`, `dialog.accent_alt`, `fuzzy.highlight`). `cursor_bg` is the scheme's `[colors.selection] background` unless that is nearer `fg` than `bg` (an inverted selection, then the selection text is ignored too), else bg mixed 35% toward the scheme's blue, pushed toward fg in 5% steps until it has 1.3:1 and an OKLab distance of 0.05 against `bg`; `cursor_fg` is `[colors.selection] text` (`CellForeground` / `CellBackground` count as absent), else fg, replaced by fg, bg, black, bright white or an OKLCH lightness shift until it has 4.5:1 on `cursor_bg` (the cursor row `icon` fields are not repaired, so `cursor_fg` itself must be readable). `accent` is the most chromatic (OKLCH) of the scheme's magenta, blue, cyan and yellow that has 3:1 against `bg`, else magenta; `header_bg` is bg mixed 35% toward `accent`. `default.toml` defines the names as `fg = 7`, `bg = 0`, `surface = 8`, `muted = 8`, `range_bg = 8`, `range_unselect_bg = 1`, `cursor_dim = 0`, `cursor_bg = 6`, `cursor_fg = 0`, `header_bg = 4` and `accent = 5`, and its styles use them for "body text" (`fg`), "dark well" (`bg`), "dialog or chip fill" (`surface`), "dimmed text" (`muted`), "current item" (`cursor_bg` / `cursor_fg`), "header" (`header_bg`) and "accent" (`accent`), so the default theme renders as if it named the xterm colors directly; any new style with one of those meanings must use the semantic name, not `white`, `black`, `bright_black`, `cyan`, `blue` or `magenta`. Header and dropdown text keep their ANSI foregrounds and rely on the repair pass.
- **Contrast repair**: after the palette swap the importer repairs contrast: for each style with an `fg` it finds the effective background (own `bg`, else the sibling `fill`/`track` for `label.on_fill`/`label.on_track`, else the `_CTX` prefix table in the script for dialog, dropdown, tooltip and leader-menu text, else `bg`), and if the contrast is under 4.5 (3.0 for frame/track/thumb/separator/connector/icon/gfx/mark/placeholder/disabled and similar names) it rewrites only the `fg` value: a style with its own `bg` first tries the original, `fg`, `bg`, `black`, `bright_white`, otherwise (or if none works) it moves the OKLCH lightness away from the background, keeping hue and chroma, and writes `#rrggbb`. Styles whose foreground equals their background in the default theme (`menu.progress.remaining`, excluded folder icons) and `cap` styles (`menu.speed.cap` is the pill's own background) are never touched; `icon` fields are not repaired.
- **Hand tuning**: `themes/import/tune/<name>.toml` (a separate directory so `src/*.toml` globs do not see it) holds only the changed lines, in pc theme syntax read line by line: `[palette]` entries replace or add a palette value, and a `key = { ... }` line replaces the line with the same key in the same section, or is appended to it (the section is created at the end when missing), with a warning because the template does not define it. Overrides are applied last and verbatim, after the palette swap and the repair pass: nothing derived from a replaced palette color is recomputed and the repair pass never rewrites a tuned line. Each tuned style line gets a trailing `# tuned` comment; a top-level `tuned = true` becomes a `# tuned` header comment (an unknown top-level key would be rejected by the theme loader, so it is never emitted). `--check` reports tuned styles below target as `tuned` warnings that do not fail the run. `build.sh --watch NAME` builds only `src/NAME.toml`, then polls (0.5 s, no inotify) `src/NAME.toml`, `tune/NAME.toml` (it may appear later), `default.toml` and `import_alacritty.py` and rebuilds that one theme on a change, printing a timestamped line with the repaired count and check result; the theme picker's auto reload (on by default) picks the rebuilt file up while the picker is open, so pc need not restart.
- Every new key needs a runtime fallback in `internal/theme` so imported/user themes without it still render.
- Which TOML fields reach pixels must be checked against resolution in `internal/theme` and use in `internal/ui`. Regression tests for `AccentIconStyle` and dialog title composition: `internal/ui/dialog/internal/draw/`.
- Derived, not keyed: `theme.CutMarkStyle` (listing name cut points, `panels.md`) swaps the cell's own foreground for its counterpart shade (ANSI 0–7 ↔ 8–15, bold ANSI → 0–7 without bold since bold-is-bright terminals already show it bright, RGB moved `cutMarkShade` toward white or black, default foreground toggles bold), so it follows every row style without a theme key.

## Key groups

- **Status**: `[status]` holds one style per job status (`scanning`, `queued`, `running`, `paused`, `decision`, `failed`, `canceling`, `canceled`, `completed`; `Theme.Status*`, looked up by status string with `Theme.StatusStyle` / `StatusStyleOn`). Every job-status color reads it: the menu-bar job strip, the Jobs view icon and status columns and the active Operations row, the file-list queued mark (`status.queued`) and Commands view runs (`running`, `completed`, `failed`). `scanning` (`Theme.StatusScanning`) is also the one work-in-progress style: disk-scan-pending folder icons, the slow-load working icon, the preview-loading icon, the menu-bar and preview spinners and the fileindex `scanning` row state. There are no per-site status keys.
- **Panel**: `[panel.active]`, `[panel.inactive]`, `[panel.blocked]` plus shared subtables `[panel]` (text, hint), `[panel.row]` (directory/file/info/selected/symlink, `tree.connector`, optional `cursor.range`/`cursor.range.selected` for the cursor row during a pending range select, shared by all chrome states; optional `range` and `range.unselect`, background only (the palette names `range_bg` / `range_unselect_bg` in the default theme), for the other rows a pending range covers when it selects and when a right-button drag unselects them, falling back to bright black and maroon; `info` styles size/mtime/permissions/meta), `[panel.row.mark]` (suffix marks: selection_subtree, new(.previous), renamed, no_permission, pinned, range_anchor (optional), other_match(.cursor, optional), job(.read/.move/.delete/.removing; `removing` optional, falls back to `delete`); a job waiting on a decision uses `status.decision`), `[panel.icon]` (`broken_link`, optional: file icon of a symlink whose target does not resolve, falls back to the palette's red), `[panel.icon.folder]` (open, mount, scanning, excluded; no `default`), `[panel.status]` (bottom-border segments: sync, quick_view, selections, selection_size, dotfiles_hidden, gitignore, stash, find_parked (falls back to stash), other_panel), `[panel.git]`, `[panel.fileindex]` (optional: one fg per browse-with-fileindex state except `scanning` and `checking`, which `Theme.PanelFileIndexStyle` takes from `status.scanning`; keys in `internal/theme/panel_fileindex_style.go`), `[panel.scrollbar]` (track, thumb, optional `match` marking fullscreen-preview search matches, falls back to the `fuzzy.highlight.cursor` fg; glyph is `[icons.scrollbar] match`, `Theme.IconScrollbarMatch`, falls back to █), `[panel.usage]`. The `icon` field is allowed only on panel cursor row styles and the disk-usage bar styles (`panel.usage.normal`/`selected`, `panel.{active,inactive}.usage.cursor(.selected)`); values land in `Theme.PanelFileIconFG`. Precedence on a bar cell: the bar's `icon`, then the cursor row's `icon`, then the icon's own color (`panels.md`, Disk usage). The default theme sets it on `panel.usage.normal` and `selected` only, because `panel.inactive.usage.cursor` has a black background. `[panel.dedup]` uses `row.mark.keep_subtree` and `potential` (the potential-duplicate icon, `dedup.potential` under `[icons.dedup]`). File rows use `panel.row.file`; non-listing body copy uses `panel.text` / `panel.blocked.text`. `panel.empty` (optional, falls back to bright black via `Theme.PanelEmptyStyle`) styles the empty-list text of the Jobs, Commands and Messages views (list, Details placeholder, Operations and stdout/stderr panes); the text itself is `[icons] empty` (`Theme.EmptyText`, plain text returned with or without Nerd Font icons, falls back to `[empty]`). It is drawn on the panel content background. `[icons.fileindex_state]` holds the browse-with-fileindex state glyphs (`Theme.IconFileIndexState`, one rune, ASCII letters without Nerd Font icons, fallbacks in `fileIndexStates`; it is `fileindex_state`, not `fileindex`, because `[icons] fileindex` is already the path-prefix glyph). `[panel.meta]` (`warn`, `critical`) colors meta alert cells; it is optional, with yellow and bold red fallbacks, and themes generated by `themes/import/` rely on those.
- **Menu**: `[menu]` (detail, status, dropdown*; `dropdown` stays dotted because `menu.dropdown` is both leaf and parent), `[menu.bar]`, `[menu.progress]`, `[menu.speed]`. `menu.status` styles the status-command text and optional `menu.status.separator` (fallback grey) the `[icons.menu.status]` `separator` glyph (fallback `·`) between segments (`architecture.md`). `menu.progress.done.gfx.0..9`, `menu.progress.delete.gfx.0..9` (delete jobs) and `menu.progress.remove.gfx.0..9` (a move removing its copied sources) are optional light-bar gradients (`gfx.0` = head); absent means a static done fill, delete falls back to the done gradient and remove falls back to delete, then done. `[menu.speed]` `cap`/`text` and `[icons.menu.speed]` `left`/`right` are optional with fallbacks matching the default theme.
- **Dialog**: `[dialog]` chrome (frame/surface/text/title/accent, optional `accent_alt`: the shortcut letter that needs Alt, falling back to `accent`; optional `text_select`: background-only highlight for selectable text spans, merged under the span's `dialog.option.*` foreground; falls back to the `dialog.surface` background), `[dialog.button]`, `[dialog.input]`, `[dialog.option]`, `[dialog.status]` (`selection_size`), `[dialog.progress]`, `[dialog.massrename]`. `[tooltip]` (optional, both keys): the dialog tooltip box (`text`, fg + bg; fallback `dialog.completion.item`) and its info icon (`info`, foreground only, merged onto the box by `Theme.TooltipInfoStyle`; fallback the `dialog.accent` foreground; the glyph is `[icons.dialog] info`). `[icons.dialog.checkbox]` holds `checked`, `unchecked` and `mixed` (the tri-state marker of a `CellColumns` list). Styling rules (option rows foreground-only, input placeholder pairs): `dialogs.md`.
- **Preview**: `[preview]` `search_icon` (optional, foreground only) colours the F3 preview search bar's leading icon (`[icons.search] icon`); `Theme.PreviewSearchIconStyle` puts its foreground on the bar's own row style, ignoring any `bg`, and returns the row style unchanged when the key is absent. The find dialog's `dialog.search_icon` is not used there.
- **Jobs**: `[jobs]` `row` (jobs list row text), optional `row.hover` (the Jobs, Commands, Messages, Compare and Duplicates list row under the mouse pointer, and the background of a dialog list row under it, as `row` is their row base: background and plain text under the status colors; falls back to white on grey), `[jobs.detail]` `label`/`text`/`plot` (Details panel: the `Label:` prefix, other text, and throughput chart rows), `[jobs.progress]` (plus `[jobs.progress.inactive]` for paused/canceled rows and optional `[jobs.progress.completed]` `fill` for completed rows (always a full bar, so it also styles the percentage text; falls back to the active fill background with the active `label.on_fill`), chosen by `Theme.JobsProgressStyles`), `[jobs.operations]` `success`/`failed`/`skipped` (optional; Operations pane result icons and the Details `Files:` counts, `Theme.JobsOperationStyle`/`JobsOperationOn` keyed by `theme.JobsOperationSuccess`/`Failed`/`Skipped`, falling back to `status.completed`/`failed`/`paused`) with glyphs `[icons.jobs.operations]` `success`/`failed`/`skipped`/`source_deleted` (`Theme.IconJobsOperation`, falling back to `[icons.jobs.list]` `completed`/`failed` and built-in skipped / source deleted glyphs; one cell wide). `source_deleted` is icon-only (`theme.JobsOperationSourceDeleted`, chosen by `ui.JobOperation.IconKey` for a row with `oplog.Record.SourceDeleted`); the row keeps the skipped style. `[icons.dialog] missing` is the trailing mark on missing History/bookmark/Pin rows; `[icons.dialog] zoxide` / `history` prefix History rows by source — zoxide vs panel history (`Theme.IconDialogZoxide` / `Theme.IconDialogHistory`, `z` / `h` without Nerd Font icons, colored `dialog.option.active` on the cursor row, else `dialog.option.inactive`). `[icons.dialog] depth` marks the indexing depth in the Find / Jump title and leads the max-depth input on the query row (`Theme.IconDialogDepth`; the word `Depth` without Nerd Font icons). `[icons.dialog] criteria` leads the Find dialog's advanced-criteria summary on the separator above the results (`Theme.IconDialogCriteria`; `Criteria:` without Nerd Font icons). `[icons.filelist]` holds row-suffix glyphs (`selection_subtree`, `new`, `renamed`, `other_match`, `range_anchor`, `no_permission`, `job`, `move`, `delete`, `move_removing` (a move source being deleted after its copy), `preview_loading`); the queued suffix glyph is `[icons.jobs.list] queued` (`Theme.IconFilelistQueued`), colored by `status.queued`. `[icons.jobs.list] sources_collapsed` / `sources_expanded` is the expander appended to a multi-source job's Queue Type (`Theme.IconJobsListSources`). `[icons] fileindex` (`Theme.IconFileIndex`, default nf-md-database, none without Nerd Font icons) replaces `fileindex` in displayed `fileindex://` paths. `[icons.commands] command` is the Commands-view row command-line glyph (`Theme.IconCommandsCommand`; `$` when Nerd Font icons are off).
- **Compare**: `[compare]` `hashing` (pending disk icon while a worker reads a file), `equal` (`=` icon), `content_diff` (`≠` icon); missing `equal`/`content_diff` fall back to the row style. `[icons.compare]` holds the status glyphs (`equal`, `relocated`, `primary_only`, `secondary_only`, `content_diff`, `pending`, `error`) plus `name_left` / `name_right` (`→` / `←`), which replace `relocated` on a row with a per-row merge name choice (`Theme.IconCompareNameLeft`/`Right`).
- **Message**: `[message]` `info`/`warn`/`error` style the toast banner; optional `success` (falls back to black on green) styles `MessageUrgencySuccess` toasts, which the banner and Messages log prefix with `[icons.message] success` (`Theme.IconMessageSuccess`, none without Nerd Font icons); optional `sweep` (falls back to black on bright white) styles the leading-edge cell while a new warn, error or success toast sweeps in.
- **Footer**: `[footer]` `key`/`label`/`label.shift` (required) and optional `hover` (the entry under the mouse pointer; falls back to black on cyan) and `hover.active` (its part a click presses: key and main hint, or the Shift word; falls back to bright white on cyan).
- **Terminal**: `terminal.text` styles the embedded terminal panel (`internal/ui/terminal_panel_render.go`). It is a required root (`styleSectionRoots`/`requiredStyleKeys`); `Theme.TerminalTextStyle()` falls back to `panel.text`. There are no separator keys.

## Theme picker dialog

Typing fuzzy-filters the themes; navigating live-previews the highlighted theme once motion settles; Enter applies and persists `theme` to XDG `config.toml`; Esc restores the previous theme; the auto reload toggle (`theme.toggle-auto-reload`, on at open) re-previews the highlighted theme when its file changes on disk, and the preview pages cycle with `theme.next-preview` / `theme.prev-preview` (wrapping; the picker opens on page 1; failures surface as a status message or message dialog).

- **Spec**: `ThemeDialogView` (`internal/ui/dialog/theme_dialog_render.go`) is a `dlg` dialog (`dialogs.md`, Lists): a `ThemeFilter` input (search icon) driving a radio-marked `ThemeList` (the cursor row's radio is lit, fuzzy matches highlighted), next to a reserved preview pane (`themePreviewRows` tall); on a short screen the list and the pane shrink together (`dlg.FitSpec`). `App.syncThemeDialogRanks` ranks `Choices` labels into `ThemeDialogState.Ranked` / `MatchRanges` (`filterlist.SyncRanks`); `Selected` indexes `Ranked` and `ListScroll` follows it (`EnsureThemeListScroll`). Each list move (`dlg.EventListMove`) or query edit arms `App.themePreviewDebounce` (`[ui].key_repeat_debounce_ms`; 0 previews at once), whose `themePreviewFlushPayload` resolves and applies the theme, so held arrow keys load only the theme they stop on. Enter in the filter or OK applies, Cancel / Esc restore. `ThemeDialogState.Focus` is `ThemeFilter`, `dlg.OK` or `dlg.Cancel`.
- **Preview pane**: `drawThemePreview` paints the sample inputs, checkboxes and buttons (page 1 only; the pane has no horizontal rules) in the previewed theme, plus a sample tooltip attached to the first active input (placed and painted by `dlg.PaintTooltipFor`, the helper the engine's focused-widget tooltip uses, drawn last so it may overlay the rows below) (the Unselected checkbox draws its mnemonic in `dialog.accent_alt`, the Selected one in `dialog.accent`), the vertical rule and its frame tees after `dlg.Draw`. A page's rect is the whole right column inside the frame: `themePreviewCtx.y` is the first content row, `maxY` the button separator (a short terminal cuts the page off there), `left` the cell after the vertical rule and `width` up to the right border; any margin is the page's own choice.
- **Width and rows**: the dialog asks for `listWidth + 10 + 60` columns (`previewWidthMin`) and, being unclamped, shrinks to the terminal; `themePreviewRows()` is the pane height the dialog asks for: the tallest preview page's rows (`themePreviewPageRows()`), so cycling pages never resizes the dialog. Everything past the outer separator is cut off, so a short terminal shows only the first samples.
- **Preview pages**: `ThemeDialogState.Page` (0-based) picks the page painted into the pane. `themePreviewPages` (`theme_dialog_render.go`) is the ordered list of `themePreviewPage{rows, appBG, paint}` (`appBG` makes `drawThemePreview` fill the whole page rect with the Jobs view's content background, `PanelActiveSurface`'s background as `auxPanelContentBG` returns it, before painting; false keeps the dialog surface); the page count (`ThemePreviewPageCount`, used by the cycle actions and the footer's "Preview n/N") and the pane height are derived from it. **To add a page, append one entry**: its `rows`, `appBG` and a `paint(*themePreviewCtx)` (geometry in the ctx; set `activeInput` to get the sample tooltip). Page 1 (`paintThemeInputPage`) is the sample inputs with the tooltip under the active one, two checkboxes and the sample buttons row (Selected, Unselected and the destructive Delete, drawn with the focused-destructive style through `draw.DrawDialogButton`; Delete is left out when the pane cannot hold all three). Page 2 (`paintThemeAppPage`, `appBG`) is the app samples as one area on the Jobs view's content background (the job rows and progress labels use it too), a menu bar sample (`ThemeAppMenuRows`), one row per job status (`ThemeAppJobRows`) and three progress bars (`ThemeAppProgressRows`), with a blank row between sections (`themeAppSectionGaps`). Package `dialog` cannot import `ui`, so `DrawThemeDialog` takes `ThemeAppSamples` (three `ThemeSamplePainter`s) and `ui.themeAppSamples` (`theme_preview_samples.go`) supplies them: `drawMenuBar` + `drawPulldownMenu` (called with a synthetic `Layout` whose `Footer.Y` is the pane's cut-off row) on two `menu.Definition`s, `drawJobsListJobRow` for each `jobs.Status` fed fixed `JobEntry` snapshots (running and queued carry a `QueueETA`, running a `DisplaySpeedBPS`; the helper decides what each status shows) drawn at the fixed clock `themeSampleNow`, and `drawJobsProgressBar` with `Theme.JobsProgressStyles` for the active (running), inactive (paused) and completed variants. Job rows need `themeSampleJobWidth` columns and are skipped on a narrower pane. Page 3 (`paintThemePanelPage`, `appBG`, `ThemePanelRows` tall) is a whole file panel from `ThemeAppSamples.Panel`: `ui.drawThemeSamplePanel` (`theme_preview_panel.go`) runs the real `drawPanel` on a fixed `panel.State` (entries under a non-existent `/srv/meadow`, fixed mtimes, no disk access, no clock) with `themeSamplePanelDiskPainter` as the `DiskUsagePainter`, so frame, header, git column, icons, size/date columns, disk usage bars and the row marks are the app's own. It shows the `..` row, folders (a disk usage bar, one still scanning, one excluded), a symlink and a broken one, files of several types (one executable), selected rows, the cursor on a selected row, pinned, new and renamed marks, queued and running (move, delete) job marks, no-permission, and git modified / new / ignored cells. The panel is closed early on a short pane (its height is `min(maxY-y, ThemePanelRows)`). Not shown: a running copy mark, the tree layout and carousel, find/index states, and meta columns, which need live app state.
- **Auto reload**: `ThemeDialogState.AutoReload` (on when the dialog opens) runs `App.themeWatch` (`theme_watch.go`) only while the dialog is open: one goroutine with a `themeWatchInterval` ticker, stopped by `stopThemeWatch` on toggle-off, close, apply and cancel. `themeWatcher.check` stats the highlighted theme's file (resolved once per highlighted theme with `theme.UserThemePath`; embedded themes have none, so are not polled) and posts `themeFileChangedPayload` when its modification time or size differs from the last revision seen, once per distinct revision (so a broken save reports its error once). The event loop answers with `previewThemeAtSelection`, the same path the toggle takes when it turns on. `App.setThemeWatchName` keeps the goroutine on the highlighted theme; tests replace the stat through `App.themeWatchStat`.
