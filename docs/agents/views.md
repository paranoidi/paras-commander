# Auxiliary views

Messages, Compare, Dedup and Help. Jobs and Commands views: [jobs.md](jobs.md), [commands.md](commands.md). Menu/leader-menu wiring: [menus.md](menus.md). User docs: `docs/find-duplicates.md`. Pin/job trailing marks on rows: [panels.md](panels.md), "Pinned suffix mark".

## Messages view

- `messages.open` (Alt+M) is a global default in `DefaultActionSpecs` (`[main]`); `messages.close` (Left, plus hardcoded Esc) lives in `DefaultMessagesOverlayKeys` (`[messages]`); `messages.clear` (F8 in the overlay) empties `Model.MessageLog` and the banner. Only `messages.*` ids are allowed under `[messages]` (`AllowedInMessagesOverlay`/`validateMessagesOverlayKeys`); the overlay resolves before globals while `ViewMessages` is focused.
- `setTransientMessage` prepends wrapped lines to `Model.MessageLog` (newest first), split on spaces to the Messages text-column width (`ui.MessageLogWrapColsForLayout`, same width as `drawMessagesView`; `ui.MessageLogWrapRunes` fallback). The first line of each toast carries a local `hh:mm:ss`; continuation lines don't, and Up/Down move by logical message (`ui.AdjacentMessageLogIndex`). The banner shows the first wrapped line unless a shorter override is supplied (job failures: `jobFailureBannerDetail`/`ops.Error`). Retention: `[ui].message_log_max_entries`.

## Compare view

- `panel.compare-panels` (Command menu `p`, Alt+V) opens `ViewCompare`. Overlay `[compare]` actions: `compare.close` (Esc), `compare.cycle-filter` (F3, Category dialog), `compare.reset-filter` (S-F3), `compare.refresh` (M-r), `compare.merge` (F5), `compare.toggle-empty` (M-e), `compare.filter-dialog` (M-f; the panel Filter dialog targeting basenames via `CompareViewState.NameFilter`/`NameFilterLabel`, cleared by reset). The Category dialog uses pending selection like the sort dialog. Layout/labels: `keymap.MenuBindingLabel` orders multi-binding actions stably.
- Engine `internal/compare`; handler `internal/apphandler/compare`; render `internal/ui/compare_view_render.go`; config `[compare]` (`docs/config.md`). Local roots only.
- Classes: Equal, Relocated, Primary only / Secondary only, Content diff. Hashing is SHA-256 and **size-prefiltered** (`hashJobsNeeded`): same-path pairs of unequal size are content diffs without opening either file; unpaired files hash only when their size appears among unpaired files on the other side; those not needed are `HashDone` immediately. Jobs run smallest first. Pending rows use the normal style, in-flight rows (`Hashing`) use `compare.hashing`; the bottom-border legend says Pending/Hashing rather than the provisional kind.
- The worker loop reclassifies on every completion; see [technical-debt.md](technical-debt.md).
- `IgnoreEmpty` (default true on open) is a display-only filter (`FilteredRows`, no rescan) hiding zero-byte rows from list, merge selection and navigation; the end label appends `N empty hidden`. Paths show only differing suffixes when roots share a prefix (`primitive.StripCommonPathPrefix` after `PathWithHomeTilde`). List height is `ui.PanelListRows` on the merged rect (same chrome accounting as the file list and dedup).
- Left/Right choose the column; Insert (`panel.select-toggle`) adds that column's path to the panel's `SelectedPaths`. Job and pin marks resolve and paint per side (each column has its own absolute path).
- **Merge** (F5): Left/Right destination (Alt+L / Alt+R), optional delete of duplicates, shared-prefix display via `FormatCompareMergePaths` (`internal/ui/dialog/compare_merge_paths.go`); uses job copy/delete queues then `compare.refresh`.
- **Open/close contract**: `Handler.Open` applies `diskusage.ListingVolumeGate` from the primary panel when `[compare].stay_on_volume_default` is true. `OpenPaths(primary, secondary, showHidden, onClose)` (dedup's entry) has no aux-view guard or volume gate. Enter navigates the browser and closes Compare (`DiscardReturn` drops the return hook so a dedup detour doesn't rescan). `Refresh` replays the stored roots/gate and never fires `onClose`; `Close` tears down then fires `onClose` once. Failed validation (`TreesOverlap`, zero path) returns false and leaves the caller untouched.

## Dedup view

Handler `internal/apphandler/dedup`; engine `internal/compare` (`DedupSnapshot`); tree model `internal/ui/dedup_view_types.go` over `internal/treeflat`; render `internal/ui/dedup_view_render.go` (`drawDedupTreePane`); rows `Model.DedupList` (main) and `Model.DedupCopiesList`. `openRoot` applies the same `[compare].stay_on_volume_default` gate from the active panel. Config `[dedup]` (`hash_confirm_bytes`, `file_progress_bytes`, `chunk_bytes`): `docs/config.md`.

- **Scan**: `panel.find-duplicates` opens `DedupProgressDialog` (`internal/ui/dialog/dedup_progress_dialog_render.go`) through walking, byte-gate confirm (OK/Cancel) and hashing. The bar uses `dialog.progress.*` theme keys carried by **cell backgrounds** (no block icons); label keys are foreground-only and `Theme.DialogProgressLabelOnBar` merges them onto the bar cell at render. Fill is byte-based (`HashedBytes/HashBytesTotal`; early-bail files are charged in full so it only jumps forward) and the label names the tracked file's directory (largest in-progress candidate, stable). A per-file bar row is always reserved during hashing (no mid-scan resize) and drawn only above `file_progress_bytes`. Walk count updates are rate-limited.
- **Hashing** is chunked with early bail-out: same-size candidates compare `chunk_bytes` at a time, splitting the partition by prefix digest and dropping uniques without reading the rest; survivors reach EOF so `DedupGroup.Hash` stays the true SHA-256. Group order has one definition, `compare.DedupGroupBySize` (shared by `groupByHash` and the wasted sort).
- **Twin panes**: main pane (primary rect) shows the results tree; the Copies pane (secondary rect) shows where the selected file's other copies live (selected file excluded). Rows: `ui.DedupRowsFromSnapshot(snap, view)` / `ui.DedupCopyRows(snap, selRow, collapsed)`. Connectors from `[icons.tree]` colored by `panel.row.tree.connector`; directory rows use `[icons.folders]` tinted by the row `lineStyle` (not `panel.icon.folder.*`); group headers use `[icons.tree]` expand/collapse. `treeflat.Row` carries `LastChild` and `AncestorHasNext`. Node IDs are stable strings (`g:<hash>`, absolute path, `d:<rel>`) so collapse state and cursor survive rebuilds, sort and mode switches (`Handler.resyncPreservingCursor`).
- **Panes and focus**: each pane owns a `ui.DedupPane` (`Selected`/`ListScroll`/`Collapsed`). Tab (`panel.switch`) toggles `DedupViewState.FocusCopies`; `Handler.SwitchPane` refuses an empty copies pane and focus drops when it empties. Movement goes through `Handler.MoveSelection`/`SelectEdge` on the focused pane; moving the main cursor rebuilds copies (`syncCopies`). Tree keys, marking and Enter all act on the focused pane's row; the unfocused pane uses the inactive cursor style.
- **Dirs browse panel** (`internal/app/dedup_browse.go`): `ui.DedupSecondaryRects` splits the secondary column into Copies and a real file-list panel (`Model.DedupPanel`, synthetic ID `ui.DedupBrowsePanel`, sized via `ui.PanelIDCount`, built with `panel.NewSideListing` and the quick-view async listing/git machinery). `reconcileDedupPanel` (from `reconcileAfterEvent`) retargets it to the directory of whichever pane row changed last (`dedup.Handler.PaneTarget`, fingerprints in `dedupBrowseFP`, focused pane wins ties) and re-syncs only on target change, so pane switches don't reload and manual navigation survives until the next tree cursor move. Leaving the view or Dirs mode clears it and bumps load generations. `FocusPanel` routes keys to `handleDedupPanelKey`; `FocusCopies` still names the source pane; tab order is `dedup.Handler.SwitchPane`; F3 from the panel returns to dedup.
- **Tree modes**: `dedup.toggle-tree` (Ctrl+T, leader `g`) switches the main pane between **directory tree** (default; duplicate-bearing dirs, files as leaves with `size xN`, no group dimming) and **groups tree** (one node per content group whose first file is the expandable header; the cursor's group is highlighted, others dimmed by `GroupIdx`). Marks are keyed by absolute path and survive switches. Top-right label: `View: Dirs` or `Sort: Path`/`Sort: Wasted`.
- **Cursor-sibling hint**: every other file row sharing the cursor's `GroupIdx` paints with the general `panel.hint` style (below cursor/kept/marked precedence). In dirs mode a collapsed directory whose subtree holds a sibling also paints it (`ui.dedupGroupDirSet` -> `dedupPaneParams.HintDirs`); once expanded, the hint moves to the file rows. `panel.hint` is reusable for other cursor-relationship highlights.
- **Columns**: right-anchored Count and Size, widths minimal for headers and values. Directory rows show duplicate count and reclaimable bytes (`dedupDirNodes`, keep-one-survivor rule); file rows with `ShowSize` show copy count and size (`formatByteSizeListed`).
- **Tree navigation**: `dedup.toggle-node` (Right/Alt+Right), `dedup.collapse` (Left/Alt+Left; collapses or jumps to parent; Esc closes the view), `dedup.collapse-all`/`expand-all` (Alt+Ctrl+Left/Right; leaders `C`/`a`). Each pane keeps its own collapsed set. Each mode starts all-collapsed the first time its results show (`DirsCollapsePending`/`GroupsCollapsePending`, `DedupPane.SetCollapsed` over `DedupExpandableIDs`); Copies starts expanded. Expanding auto-descends single-subdirectory chains inside one key event (`autoDescendSingleDir`); a node with more than one child or a file child stops it.
- **Marking** (Insert, `panel.select-toggle`; no-op on directory rows): **Marks operate on snapshot groups, not visible rows** (critical): `ToggleGroupMark`, the mark-under helpers, `MarkedFiles`/`MarkedPaths` and the delete dialog iterate `ui.DedupActiveGroups(snap, ignoreEmpty)`, so files in collapsed nodes are still marked and deleted. Never derive mark sets from `model.DedupList`. A fully marked group uses `panel.dedup.row.all_marked` / `panel.dedup.row.cursor.all_marked` (`ui.DedupGroupFullyMarked`). Directories containing marks get the subtree indicator (`ui.dedupMarkedDirSet` -> `MarkedDirs`).
  - `dedup.mark-redundant` (Ctrl+K "keep uniques") and `dedup.mark-duplicates` (Ctrl+D) share `dedupMarkUnder(groups, dirAbs, keepOneWhenIsolated)`; the directory is the selected file's parent, or on a dirs-mode directory row that directory (`selectedDirAbs`), matched as a path prefix. Keep-uniques (`ui.DedupRedundantUnder`): a group with a copy outside is fully marked inside; an entirely-inside group keeps its first copy. Mark-duplicates (`ui.DedupDuplicatesUnder`): marks inside copies only when a copy survives outside; isolated groups untouched. Both only mark; **Delete marked** (`file.delete`) confirms.
  - `dedup.mark-group` (Ctrl+G) toggles every copy in the row's group (all if any unmarked, none if fully marked; works on collapsed headers; `ToggleGroupMark`). Bound only in `[dedup]`, which resolves before globals, so it shadows global `C-g`. `panel.clear-selection` (Ctrl+U) clears marks via `Handler.ClearMarks` using the global binding.
- **Sort and empties**: `dedup.toggle-sort` (Ctrl+S) toggles groups order Path / Wasted (not the directory tree); `dedup.toggle-empty` (Alt+E) hides/shows zero-byte groups (hidden by default; count in the title). Toggling collapses only newly appearing nodes. Both are display recomputes, no rescan.
- **Delete flow**: confirming Yes dry-runs `Handler.EmptyDirsAfterDelete` -> `ops.PreviewEmptyDirsUnder` (`internal/ops/flatten.go`, non-mutating mirror of `RemoveEmptyDirsUnder`) over the marked files' parents. If directories would be emptied, `DrawDedupEmptyDirsConfirmDialog` (`dialog.DedupEmptyDirsConfirmState`, capped list) asks to remove them, **defaulting to Yes** (an intentional exception to the safe-default rule; empty dirs are low-risk). Yes sets `Job.DeleteRemoveEmptyDirs`; `jobbridge` runs `ops.RemoveEmptyDirsUnder` after the delete. Regular panel deletes never set it. Key handling lives in `internal/app/dedup_view.go`; see [file-operations.md](file-operations.md) for the dangling-dirs sibling.
- **Compare from dedup** (`dedup.compare`, Ctrl+Alt+C, shadowing the global overlay-only `panel.compare-panels` chord): primary = parent of the main pane's selected file; secondary = directory under the Copies cursor. Requires a file in the main pane. Uses `compare.Handler.OpenPaths` with a return hook calling `Handler.ReopenPreservingState`: Esc / `compare.close` / the toggle chord return to dedup, rescan, and restore marks/keeps/collapse/cursor for still-present paths. Enter in Compare goes to the browser without bouncing back.
- **Enter** navigates the browser to the focused row's file directory (selecting it) or into the directory row, and closes the view.

## Help dialog

- Lists configurable action bindings (not menu mnemonics), filtered with the shared search engine. Context-aware for every `ui.ViewMode` via F1 or `?`. `?` is a plain rune, so `handleGlobalKeyIntercepts` (`internal/app/input.go`) lets it through when a modal is open so text fields receive a literal `?`; F1 is consumed as a no-op there. F1 while the pulldown menu is open closes it and opens the underlying view's help (`openHelpDialog`); there is no menu-scoped list.
- **Visibility source of truth**: `ActionSpec.Views` (`keymap.HelpViews` bitmask) on `keymap.DefaultActionSpecs()` (`internal/keymap/specs.go`). A new action MUST set `Views` or it appears in no F1 help. Zero `Views` is deliberate for dialog-overlay-only shortcuts (Find, Bookmark, Flatten destinations, history both-panels, `dialog.input.*`, `app.show-help`); their own footers document them. `helpkeys.ActionRunnableInView` (`internal/app/helpkeys/helpkeys.go`) derives both visibility and Enter-activation from the mask.
- `App.helpContextFor(vm)` (`internal/app/help.go`) returns `{title, activate}` per view; Browser's title is `Help`, others `Help - <View>`. `effectiveKeyStringsForView` uses the view-scoped keymaps and overlay defaults so overlay-only actions show real bindings in their view.
- `activate` runs on Enter for a row; `nil` means `dispatchActionLikeKeyboardShortcut`. Views whose primary cursor movement is hardcoded to raw arrows need a bespoke `activateXHelpAction` (`activateDedupHelpAction`, `activateJobsHelpAction`, `activateCommandsHelpAction`, `activateMessagesHelpAction`, `activateCompareHelpAction`), which delegates to the same exported movement helpers as the view's own key handler (`jobs.Handler.MoveSelection`/`SelectEdge`, `moveCommandsSelection`/`selectCommandsEdge`, `moveMessagesSelection`/`selectMessagesEdge`, `moveCompareSelection`/`selectCompareEdge`) so there is one definition of Up/Down/PgUp/PgDn/Home/End per view.
- **Rank vs highlight**: ranking uses a terminal-agnostic corpus (`Keys`, `Section`, `Title`, action id, keywords); `MatchRanges` are computed against the padded `FormatHelpRow` line (`ComputeHelpDialogListMetrics`) so highlights match what is painted.
- **Section headers stay visible while filtering**: `BuildHelpVisualRows` (`internal/ui/dialog/help_dialog_render.go`) inserts a non-selectable header before every run of same-section rows in `Ranked` order, so a header can repeat when matches aren't adjacent. No blank spacer above any header.
