# Commands

The Commands view, command-output dialog, run-for-each dialog and batch backend live in `internal/apphandler/commands` (`commandsctrl.Handler`, `App.commandsCtrl`, host in `internal/app/commands_host.go`). The dialog handler reaches it via `dialogctrl.Deps.Commands` (see [file-operations.md](file-operations.md)). `App.commandsMu` and `App.commandsCtx` stay App-owned and are passed in `Deps`: `commandsMu` is the lock the preview subsystem also uses (render snapshots the whole model struct, so all background model mutations share one lock); `commandsCtx` is the app-lifetime cancel context shared with preview subprocesses. Terminal strip details in [subshell.md](subshell.md).

## Process execution

- `cmdrun.Run` / `RunTracked` is the single captured-run path for Commands, user menu, run-for-each and meta `[[entry]]` commands (`internal/apphandler/meta` `runCommand`; meta keeps trimmed-stdout display and `runFailure`). Each stream is capped at `MaxStreamBytes` with a truncation suffix, `WaitDelay` bounds `Wait` so orphaned grandchildren can't hold pipes, the child gets a new session (`Setsid`), and cancel SIGKILLs the process group (`Kill(-pid)`).
- Live output: `RunTracked` takes an optional `*cmdrun.Live` (caller-owned, mutex-guarded `CappedWriter`s); `nil` keeps the capture private. Captured callers (user menu, run-for-each non-PTY, Enter on an executable) pass one and start `Handler.StreamLive`, which every 100ms (fixed) patches the row's `Stdout`/`Stderr` (stderr through `cmdrun.StripNoise`) when either grew and posts `WakePayload.OutputDialogLive`. Call its `stop()` right after `RunTracked` returns and before the final completion patch; it waits for the goroutine so a late tick can't overwrite the final output.
- Lines with shell operators (`>>`, `|`) or menu `shell = true` run via `sh -c`; otherwise POSIX argv parsing via `go-shellwords`. Macros expand per item via `cmdrun.BuildInvocation` (`internal/cmdmacro`, `usermenu.MacroContext`); path and name values are POSIX-single-quoted (`cmdmacro.QuoteShellArg`/`ExpandCommandLine`) so expansion is safe inside `sh -c`.

## Enter on a runnable file

`nav.open` on a local regular file with `+x` and ELF/shebang content (`localfs.PathLooksRunnable`) runs it when `run_executables_on_enter` is true: `argv = [path]`, `Dir` = active panel cwd, appending a `CommandRunKindFileExecute` row (`internal/app/run_executable.go`). `panels.execute_rules` (`config.PanelsConfig.ExecuteRules`, first match via `entrymatch.EvalWhenAny`, same predicate language as `[[preview.commands]]` and `meta.toml`) picks the mode: no match switches to `ViewCommands` and waits; `background = true` (the built-in rule matches `*.AppImage`) keeps `ViewMode`, tracks the row for later inspection/kill, and toasts only on launch failure, non-zero exit, or stderr (`backgroundRunNotify` in `internal/app/user_menu.go`, shared with user-menu `Background`). Foreground launch failures land in the stderr pane (`CommandStderrDisplay`/`ErrorMsg`). Other files follow `open_files_externally`. `file.edit` is unchanged. Remote panels never execute locally.

## Run for each

- Default mode: the command must contain `%f` (absolute path of the item) and `Dir` is the active panel directory. "Run in each selected directory" (Alt+R, `FileDialogState.RunForEachInDirs`) instead sets `RunForEachBatchSpec.PerEntryWorkDir`; the selection must then be directories only (validated up front, same red error line as an invalid command) and `%f` becomes optional. `BuildRunForEachItem(requireF)` gates the check: the dialog passes `!RunForEachInDirs`; the user-menu `run_for_each` path always passes `true`.
- The Command field live-validates per keystroke (`RecomputeRunForEachValidation`) and shows a red error or a `-> <expanded command>` preview (`RunForEachPreview`, first selected item) in one shared reserved row.
- **Work pool** radios (when pools are configured) sit below the directory/PTY checkboxes. Focus-row arithmetic (`runForEachExtraFocusRows`) lives in both `internal/ui/dialog/file_dialog_render.go` and `internal/apphandler/dialog/file_input.go` and must stay in sync.
- A pooled batch stays `Pending` through `workPools.Acquire` (cancellable) and becomes `Running` immediately before start. Failed batches toast a summary and open Commands.
- **History** (`file.run-for-each.history`, `[dialog.run_for_each]`, main screen): fuzzy picker over the in-memory, session-only list of run command lines (most recent first, deduplicated, capped, recorded in `ExecuteRunForEach` once validation passes). Structurally the same picker as mass-rename pattern history (`mass_rename_pattern.go`) keyed on strings, without `file.mass-rename.delete-pattern`. Files: `run_for_each_history_*.go`, `internal/apphandler/dialog/run_for_each_history.go`.

### Interactive PTY mode

`RunForEachBatchSpec.PTY` (dialog checkbox, Alt+T; `menu.toml` `pty = true`) runs each entry on a live pseudo-TTY via `subshell.StartArgv` (independent `*Subshell`/`*PanelFeed` per entry; see [subshell.md](subshell.md)) so tools that open `/dev/tty` (e.g. `chezmoi`) work. Falls back silently to capture on non-Linux or PTY start failure.

- **Terminal-panel lease**: one foreground PTY batch owns the bottom terminal panel at a time (`ptyForeground` + `ptyPanelOwner`); a second waits. `OwnsTerminalPanel()` is the batch-level lease (held through pool waits and gaps). `ActivePTYSession()` is only the owner's current process. Background PTY batches still use a real PTY but never take the lease. While a batch owns the panel, the terminal panel's toggle/focus/open entry points (`toggleTerminalPanelVisible` for `terminal.toggle-panel`, `toggleTerminalPanelFocus` for `terminal.focus`, `openTerminalPanel`) warn and refuse; a persistent shell view is replaced for the duration and the panel is left hidden afterward (the shell process is untouched).
- Foreground batches show the same panel strip `terminal.focus` uses (`ui.Model.TerminalPanel`, `drawTerminalPanel`): the show wake switches to the browser and opens the panel before the entry loop, each entry installs a `subshell.PanelDrawer` as `TerminalPanel.Drawer`, and the panel closes when the batch ends. `ViewMode`/`TerminalPanel` changes ride typed `WakePayload` fields (`TerminalPanelShow`/`Hide`/`Drawer`/`ClearDrawer`) applied in `ApplyWake` on the event loop.
- Resize (`resizeTerminalFeedToLayout`, `internal/app/terminal_panel.go`) resizes the run's feed first, then the persistent feed. Live sessions are tracked per Commands row (`ptySessions`) so terminate/kill reach background PTYs; `commands.terminate` / `commands.kill` call `Subshell.Close` (SIGHUP, then SIGKILL).
- The Commands view never renders a live session: Stdout is populated from the emulator's final frame (`PanelFeed.SnapshotText`, no scrollback) when the entry exits; exit code comes from `Subshell.ExitCode`; Stderr stays empty (one merged stream). Key routing is `handleTerminalPanelKey`, generic over `TerminalPanel.Drawer`.
- Known risk, not PTY-specific: `PoolName` + `PTY` can hold a pool slot indefinitely if the command waits on input nobody answers.

## Work pools

`pools.toml` (`[[pools]]`: `name`, `max_parallel`, clamped 1-64; path via `[pools]` in `config.toml`), packages `internal/pools` + `internal/workpool`, loaded into `App.workPools` at startup. User-menu default and `background` entries may set `pool = "name"` to wait for a slot before Running; unknown names fail at user-menu load with a critical message (checked recursively). Copy/move jobs do not use pools yet. `pools.RefreshDocumentation` exists for a future pools-edit shortcut.

## User menu (`app.user-menu`)

Loads `menu.toml` per `[user_menu]` (`internal/usermenu`: resolve order, trusted-owner skip, `Decode` path-based table walker, `FilterVisible`/`EvalWhen`, macros). Opens the shared bottom leader-menu strip (`LeaderMenuState.UserMenu`; see [menus.md](menus.md)), not a modal.

- **Format**: entries are uniquely named TOML tables (`[pwd]`, `[tools.disk_use]`), not array-of-tables; display order is file order. A table with nested child tables instead of `command` is a **submenu** (mutually exclusive with `command`/`run_for_each`/`pool`/`toast`/`interactive`/`detach`/`background`/`dialog`/`pty`) and nests arbitrarily. The old `[[entry]]` syntax is rejected with a migration error.
- **Load errors** are critical messages (`usermenu.ShortLoadError`): unknown fields, non-single-letter `key`, bad `when`, `run_for_each` without `%f`, `pty` without `run_for_each`, more than one `default = true` per level, unknown `pool`. A duplicate `key` within one level is not fatal: it goes to `MenuFile.Warnings`, the later entry falls back to an auto letter, and a warning toast shows every time a level is displayed.
- **Keys**: a plain letter runs the entry (or opens the submenu, pushing `App.userMenuStack` in `openUserMenuLevel`); `usermenu.back` pops a level; Esc closes the whole strip; F9 opens `menu.toml` in `$EDITOR` and reloads. `app.user-menu-edit` always opens the file (`usermenu.RefreshDocumentation` refreshes the comment header first; user entries are preserved via `internal/configdoc`). A missing file gets a commented stub; an empty one warns.
- **Entry modes**: `interactive = true` suspends the TUI (`cmdrun.RunInteractive`); `detach = true` starts a background process (`cmdrun.StartDetached`); `background = true` captures silently, notifies on failure/stderr, refreshes the active panel; default captures via `cmdrun.Run`, opens Commands and appends a `CommandRunKindUserMenu` row. `dialog = true` appends a row like any run (`runUserMenuCommand`) and opens the output dialog running (`commandsctrl.OpenRunningOutputDialog`, `CommandOutputDialogState.RunID`) with **Background** (Esc/Alt+B, run continues) and **Cancel** (Alt+C, kills, row Canceled). Completion posts one `WakePayload` with the background fields plus `OpenOutputDialog`; `ApplyWake` fills the dialog only if still open, running and `RunID` matches. `OutputDialogResult` appends `--- stderr ---` whenever stderr is non-empty, even at exit 0. Body lines come from one builder (`outputDialogLines`): `ApplyWake` applies `OutputDialogLive` to a matching Running dialog, so partial output shows while the run continues, and the title carries the Running/Queued status. Scroll keys (Up/Down/PgUp/PgDn/Home/End) work in both states; `CommandOutputDialogState.Follow` (true on open) keeps the tail visible and is cleared by scrolling off the bottom and set again on reaching it. The final result replaces the dialog but keeps its `Scroll`/`Follow` (cleared and scrolled to the path cursor when the result has `Paths`).

  **Path picking** (finished dialog only): `OutputDialogResult(…, workDir)` runs `detectOutputPaths` (`output_paths.go`) in the run's background goroutine and stores `Paths []OutputPathMatch` (line, cell span of the ANSI-stripped line, absolute path), `PathCursor` and `WorkDir` on the state. Per line the whole trimmed line is tried first, then, at each whitespace token, the longest run of up to `maxPathTokens` (6) consecutive tokens down to the single token (quotes/brackets/trailing `,;` trimmed, `:<digits>…` suffix cut; first existing candidate wins and scanning resumes after it); per-call cache of existing/missing paths so only uncached lstats count toward the cap; relative candidates resolve against `workDir` and count when `os.Lstat` succeeds; the `--- stderr ---` separator is skipped; total lstat calls are capped (`maxOutputPathStats`). `HandleOutputDialogKey` (not Running) remaps hjkl and, when `Paths` is non-empty, `handlePathKey` moves the cursor: Down/Up jump to the first match of the next/previous line with matches, Right/Left step through matches in flat order, and `command-output.toggle-selection` calls `Host.ActivePanel().TogglePathSelection` then advances (conflict removal shows a warn transient message). `handleGroupSelectionKey` resolves the global `panel.select-group` / `panel.unselect-group` / `panel.invert-selection` keys through `Deps.Keys`: invert toggles every unique detected path in the active panel ("Inverted N"); select/unselect call `Host.OpenOutputGroupSelect`, which opens the group-select dialog (`GroupSelectState.Context == "output"`) on top of the output dialog (input routing in `App.inputMode`, draw order at the end of `ui.Render`). Its matches come from `App.outputGroupMatches`: deduped `Paths` filtered by Files/Dirs only (`OutputPathMatch.IsDir`, captured from the detection `Lstat`) and `find.NewPathMatcher` (types, pattern, Match full path), counting only paths whose selection state would flip; apply uses `BulkAddSelections` (with the detected `IsDir`, no re-stat) / `TogglePathSelection`. `Model.GroupSelectOverOutput` is the single check for that stacking in input and render. `ensurePathVisible` keeps the cursor line on screen and clears `Follow`. PgUp/PgDn/Home/End scroll as before; without matches Up/Down scroll. `DrawCommandOutputDialog` restyles match spans with `DialogOptionInactive` / `DialogOptionActive` and the `Selected` variants, using the active panel's `IsSelectedPath`.
- **Selection clearing**: a command clears the tags it consumed, at launch on the UI goroutine (`clearConsumedSelection`): a template with `%t` clears the active panel, `%T` the other panel, and a command using neither leaves both alone. `interactive` and `detach` clear only after the run succeeded or started, so a failed launch keeps the tags. `run_for_each` (and the Run-for-each dialog) clear the active panel in `StartRunForEachBatch` after validation, since the batch iterates the selection. Finish wakes never clear selections.
- **Visibility and patterns**: `when = [...]` (OR) and `run_for_each = ["files","dirs"]` (per-item skips) per leaf; a submenu's own `when` is evaluated and it vanishes when all children are filtered. `shell_patterns` (glob vs regex for `when`) cascades file -> submenu -> leaf. `toast = "..."` fires after success (suppressed on error; replaces the default "Started ..." for `detach`), delivered via `WakePayload.NotifyLog/NotifyBanner`.
- Implementation files: `internal/app/user_menu.go`, `dialog_config_edit.go`, `leader_menu.go`. Command menu **User menu** (`X`) dispatches the same action.

## Drop to shell (`app.drop-to-shell`)

With `[shell].persistent` (Linux) toggles the persistent subshell ([subshell.md](subshell.md)). Falls back to a one-shot shell on non-Linux, when `[shell].command` is set, or when the PTY fails to start: `screen.Suspend`/`Resume` via `App.withTerminalReleased` (same as `file.edit`; never `Fini`/`Init`), runs `$SHELL` with cwd = the active local panel dir. `[shell].sync_cwd_on_return` navigates the panel to the shell cwd afterward (both modes). One-shot is blocked on remote panels; both are blocked while modal dialogs are open (`Model.ModalDialogOpen`). Non-zero exit is ignored; launch/suspend/resume failures are status errors. Code: `internal/app/drop_to_shell.go`, `internal/subshell`, `internal/shell`. `app.shell-insert-paths` is covered in [subshell.md](subshell.md).

## Commands view (`ViewCommands`)

- Jobs-like split: run list (phase / exit markers) plus Stdout / Stderr panes, wrapped to pane width. Tab / Shift+Tab cycle panes (`CommandsViewState.FocusPane`, 0/1/2); Esc closes. List chrome reuses `jobs.*` theme entries (`commands_view_render.go`, `wrap_words.go`). Each run row is one line plus one line per macro: line 1 is `UserCommandLine`, the command as written (`[icons.commands] command` glyph, `$` without Nerd Font icons; a leading shell word from `commandDisplayWrappers` (sh, bash, zsh, fish, …) and its flags stripped by `commandDisplayLine`), then `CommandRunEntry.Macros` rendered as `%x <value>` (`commandMacroLine`; `%t`/`%T` show the first path plus `(+N more)`). `Macros` comes from `cmdmacro.MacroDisplayValues` (distinct macros in template order, `%f`/`%F` joined with their panel dir) for user-menu and run-for-each rows; run-for-each always adds the iterated item as `%f` when the template omits it (directory mode); Enter-on-executable rows have none. Rows are variable height: `CommandsViewState.ListScroll` is an entry index and `EnsureSelectionVisible(entries, rows)` / `commandsMaxListScroll` budget lines via `commandsEntryLines` (`commands_view_state.go`).
- **Type-to-jump filter** (list pane only): an unbound plain printable rune in `Handler.HandleViewKey` (after leader letters, Alt menu, and action dispatch) opens `CommandsViewState.Filter` (`quickfilter.Filter`, options from `Host.FilterOptions`), shown as `> query` in the list title (`drawQuickFilterTitle`). `internal/apphandler/commands/filter.go` mirrors the Dedup handler methods; every selection change goes through `setSelection`. Match text is `ui.CommandsFilterLabel`: `CommandsFilterSegments` (the displayed command line, then each macro's displayed first value with the home dir as `~`) joined with `" "`; `drawCommandsListPanel` splits `Filter.Ranges` back per segment (`splitSegmentRanges`) and highlights with `fuzzy.*` styles on the command line or macro line that matched, skipped on truncated lines. `App.handleCommandsViewKey` runs before `HandleViewKey` (so Esc, vi motion and h/j/k/l go to an open filter first): retained keys go through `handleListFilterKey` (shared with Dedup), any other bound key calls `CancelFilter` and runs normally; a second Esc closes the view. `CloseView` resets the filter with the rest of `CommandsViewState`.
- `ui.IsAuxiliaryView` includes `ViewCommands`, so the permission bar, path picker, history picker and help treat it like the jobs screen (`internal/app/app_input.go`).
- Quit confirmation counts in-flight command batches like unfinished jobs (`openQuitConfirm`/`QuitConfirmState`).

## Commands view output panes

- Stdout/Stderr panes follow the tail by default (`CommandsViewState.StdoutDetached`/`StderrDetached` false; `ui.StreamScroll` draws a followed pane at the bottom). `scrollPane` handles Up/Down/PgUp/PgDn/Home/End; scrolling off the bottom detaches, reaching the bottom (Down/PgDn/End) follows again. Changing the selected row re-follows both panes.
- Max scroll for key handling is `ui.CommandsStreamMaxScroll`, built on `CommandsStreamPanels`. Wrapped ANSI lines are memoized in a single-entry cache keyed on (row ID, stdout/stderr length, ErrorMsg, text width), one copy per base style; a running row re-wraps once per output change (at most 10/s).
