# Navigation

History, pins, latched sync, recursive find, bookmarks, path-picker rows, remote (SFTP) paths and the `fileindex://` scheme. See [panels.md](panels.md) for panel state and suffix marks, [preview.md](preview.md) for quick view, [keybindings.md](keybindings.md) for binding rules.

## Directory history

- `App.navigatePanelToDirectory(panelID, path, selectedName)` centralizes `NavigateTo` with `panelViewportRows`; bookmarks (`activateBookmarkSelection`), and the history picker (`activateHistorySelection`) use it. `panel.open-dir-in-other`, `panel.open-dir-in-other-focus` and `panel.open-active-path-in-other` go through `App.openPathInInactivePanel`, which is a no-op when the inactive panel already shows the target path, so its cursor stays put.
- Each panel keeps `History` (most recent first) and `HistoryIndex`. Normal navigation (`NavigateTo`, `nav.open`, Parent, bookmarks, selected-strip open, history picker) records; back/forward move only the pointer and `Load` without re-recording. Every distinct visit is kept (MRU, cap 200); only the abandoned forward branch is dropped when navigating after going back.
- `HistoryForward`/`HistoryBackward` return `(moved, warning, err)`. Local candidates are pre-checked with `panel.DirectoryExists` and skipped if gone; `sftp://` entries are not pre-checked. `warning` is set whenever entries were skipped; `nav.forward`/`nav.backward` (`internal/app/panels.go`) surface it as a warning toast.
- `nav.open` on a directory calls `panel.State.Enter`, which also follows a symlink resolving to a directory (`localfs.Entry.ResolvesToDir`: one `os.Stat`, only on this keypress, never during listing/paint) and navigates into the symlink path. Non-directory and broken symlinks fall through to file handling (runnable execution: [commands.md](commands.md); else `xdg-open` per `open_files_externally`). Remote panels never execute locally.
- **Highlight memory**: leaving a directory saves the highlighted entry (name, row, absolute path); re-entry by history, pickers, find jump, dedup/compare, SFTP or Enter restores and centers it. Parent selects the exited directory. After chdir, scroll math uses the live row count `panel.State.FileListViewportRows` (wired from `App.panelViewportRows`/`ui.FileListViewportRows`), so a selected-strip layout change doesn't leave a stale viewport. Snapshots prune with history (cap 200). Tree mode also restores expansion, re-fetching contents fresh; the absolute path disambiguates nested rows (see [panels.md](panels.md)).
- **Keys**: `nav.forward`, `nav.backward` and `panel.history-dialog`. `nav.forward`/`nav.backward` run in the file list and the dedup browse panel (`App.stepPanelHistory`, shared by `internal/app/panels.go` and `handleDedupPanelKey`); Compare, Jobs and the dedup trees keep no history and ignore them, so their raw Left/Right handling requires an unmodified key. Browse-panel reloads that follow the tree cursor use `LoadWithViewport`, which records no visit: only navigation inside the panel builds its history. C-h arrives as Backspace in many terminals and collides with `nav.parent`.
- **History dialog**: targets the active panel (`panel.history-dialog`) or the panel of Left/Right -> History. Fuzzy filter via `search.Parse`/`Rank` (respects `Filter.CaseInsensitive`); the target panel's current directory (`HistoryDialogState.CurrentPath`) is left out of every list (history, merged, zoxide) by `rebuildHistoryDialogPaths`, and the first row starts selected. Enter/OK navigates; Esc/Cancel closes. `panel.history-both-panels` (`[dialog.history]`) toggles target-only vs merged passive-then-active (`panel.MergeNavigationHistories`). No history shows "No directory history yet" and does not open. Opening draws at once at a fixed size: the **Include zoxide** checkbox row is always present (disabled while `ZoxideAvailable` is false). `openHistoryDialog` sets `Loading` and runs `zoxide.List` (`internal/zoxide`: `zoxide query --list` when the binary is on `PATH`; db at `$_ZO_DATA_DIR/db.zo` or `~/.local/share/zoxide/db.zo`) followed by `dialogctrl.PathsMissing` over the target, merged and zoxide paths on one goroutine, posting one `historyOpenPayload`; `App.applyHistoryOpen` (guarded by `App.historyOpenGen`, bumped on open and close) applies it in a single rebuild. It stores `HistoryDialogState.Zoxide` and, only when zoxide is installed, sets `ZoxideAvailable`, which enables the **Include zoxide** checkbox under the query (`IncludeZoxide`, starts from `[history].zoxide`; `dialog.HistoryZoxideMnemonic` toggles it; from the query it leaves focus there, from elsewhere it focuses the checkbox). The dialog is a `dlg` spec (`HistoryDialogView`, `App.historyView`, `App.handleHistoryDialogKey`): `HistoryDialogState.Focus` is `HistoryFilter` (empty = the query, which also drives the path list `HistoryList`), `HistoryZoxide` (when enabled), `dlg.OK` or `dlg.Cancel`; Tab/Backtab step query -> checkbox -> button strip, Up/Down/PgUp/PgDn/C-Home/C-End in the query move the list, Space/Enter on the checkbox toggle it, Enter in the query or on OK opens the row. `rebuildHistoryDialogPaths` (also used by `panel.history-both-panels`) appends the zoxide directories not already in the history, in score order, and records `ZoxideFrom`; every row starts with a source prefix: `[icons.dialog] zoxide` for those rows, `[icons.dialog] history` for panel history (the list row `Icon`, painted in the option-row foreground). Marks (pinned / job / missing) follow the row text (`MarksAfterText`). List height: `dialog.HistoryDialogListRows` (render and `App.historyDialogListRows`); an overflowing list draws the list scrollbar on the right border in the `PanelScrollbar` style (the Pin and Bookmarks / path picker dialogs do the same). `internal/app` `TestMain` points `_ZO_DATA_DIR` at an empty dir. Missing rows render `dialog.option.invalid` via `HistoryDialogState.PathMissing` (`internal/ui/dialog/state_picker_history_meta_help.go`), filled from `MissingByPath`, which accumulates every scan result (`App.mergeHistoryMissing`) so a rebuild keeps known missing rows styled. A rebuild of `Paths` outside `Loading` starts `dialogctrl.StartPathsMissingScan` (off-thread `Lstat`, `sftp://` skipped) for the paths not yet in `MissingByPath`, applied by `App.applyHistoryDialogMissing` from `PathsMissingPayload`, guarded by `App.historyMissingGen`. Cursor highlight beats invalid styling, so missing rows also carry a trailing `RowMarks.Missing` icon (`[icons.dialog] missing`), same in the path picker and Pin dialog.

Render: `internal/ui/dialog/pin_dialog_render.go`; logic: `internal/apphandler/pin/dialog.go`.
- Menu-bar badge: `drawMenuBarPinBadge` (`internal/ui/menu_bar_pin.go`) at the start of the jobs-strip gap (shrinks the jobs strip; hidden at zero). Row icon: `[icons] pin` with `panel.row.mark.pinned`; see [panels.md](panels.md).

## Latched panel sync

- `panel.toggle-sync` latches the active panel as driver; cursor moves on the driver mirror the highlighted directory into the other panel. Only one driver; toggling on the other panel transfers the role. `panel.switch` doesn't change the driver, and the non-driver panel's moves aren't synced. A non-directory cursor is a no-op. Quick view and sync are mutually exclusive. `panel.open-dir-in-other` / `panel.open-dir-in-other-focus` / `panel.open-active-path-in-other` disable sync when they navigate the inactive panel.
- Sync uses `panel.State.Load` (not `NavigateTo`), so the follower's history is untouched.
- Reconciled once per loop in `App.reconcileAfterEvent()` (except while a debounced follower load is pending), so any code path that changes the highlighted directory triggers it without call-site wiring.
- Indicator: ` Sync -> ` / ` <- Sync ` on the bottom End edge via `panel.status.sync`; hidden when chrome is blocked.
- **Debounce**: `[ui].key_repeat_debounce_ms` coalesces repeated `nav.up/down/page-up/page-down/top/bottom` file-list steps; deferred work (follower load, quick view, carousel child preview, fullscreen-preview style-picker re-highlight) runs once after the quiet gap or immediately on any other key/resize/toggle. `0` restores per-event behavior. Selected-strip navigation isn't debounced. The jobs view's Operations pane paces its spill-file reads with the same value ([jobs.md](jobs.md), Operations pane). Paint coalescing (`shouldDeferNavPaint`, see `architecture.md`) is separate from this debounce: it only skips paints while events are already queued, so it adds no latency when the loop keeps up.
- `[ui].image_preview_debounce_ms` replaces it for quick view and carousel side preview when the target is an image/media file (`localfs.IsMediaPath`), since those decode and re-emit sixel/Kitty payloads. `preview.Handler.previewDebounceDelay` is the only selection point (`quickViewWantFile`, `carouselFilePreviewWantPath`; directory carousel listings keep the key-repeat delay). `key_repeat_debounce_ms <= 0` still short-circuits everything. `file.view` fullscreen and `find.view` are never debounced.
- Options -> Calibrate Debounce (`app.open-menu` -> Options -> D): two digit-only inputs (`DebounceCalibrateView`, edited by `handleDebounceCalibrateInputKey`), OK / Calibrate (M-l) / Cancel. Calibrate times 8 repeat-interval samples on the first field (initial press-to-repeat ignored; early release fails), average + 10 ms margin. OK writes both keys in one `[ui]` patch.

## Find (recursive, panel)

**Twins.** Find and Find in index (below) are twins: when you change a feature, option, `[dialog.find]` overlay action or key behaviour in one, make the matching change in the other whenever it is meaningful for that data source. Intentionally absent from Find in index: Stay on current volume and gitignore handling (the index is not a walk), fuzzy ranking (it has the Pattern and Boolean query modes instead; `find.cycle-match-mode` steps those), the advanced criteria (the index keeps no times, owners or modes; `find.toggle-advanced` / `find.reset-advanced` are swallowed there) and the indexing progress in the title.

**UI / coordinator separation (do not regress).** Find indexing runs on a dedicated **scan coordinator goroutine** plus **walk workers**; the main thread only touches `FindDialogState`, updated from **`scan.Event`** payloads via `findctrl.Handler.PollUpdates`. The coordinator owns the authoritative corpus in `internal/scan`; the dialog keeps a **UI mirror** (`FindDialogState.Entries`, `IndexedCount`, `RankDisplayLines`, rank caches) fed **only** by events.

- Do not call `scan.Coordinator` lookup APIs (`EntryAt`, `Snapshot`, ...) from the UI thread, render, or synchronous rank/select helpers. Do not block the main thread on coordinator command channels (`<-done` in `SetIncludeHidden`, `Restart`, `NarrowSelection`, ...).
- Push incremental UI state on events: `BatchAdded` appends to `Entries`; `ReplacedEntries` replaces after narrow/strip/finish; `MatchResult` supplies `Ranked`/`RankDisplayLines`/`FullRanked`.
- Run fuzzy match on a **snapshot copy** in the coordinator/match worker (brief index lock, then work off-copy); a read lock across a full match stalls walk ingestion.
- Rows paint from `RankDisplayLines` (filter active) else `FindEntryAt` -> `Entries`; with an empty filter, rows show walk-order preview capped by `find_max_results`.
- Map: coordinator and walks `internal/scan/coordinator.go`; event wiring `internal/apphandler/find/coordinator_handler.go`; state `internal/ui/dialog/state_picker_history_meta_help.go`; wake via `WakePayload`/`RankWakePayload` in `internal/app/app.go` `Run()`.

Behavior:
- `panel.find-dialog` (active panel; Left/Right -> Find uses that panel) roots at the target panel path. The walk is breadth-first; directory reads within a level run concurrently under `fswalk.Adaptive` (`[adaptive_io]`) and results are consumed in level order (`rootWalk.runBFS`, `internal/scan/walk.go`: all depth-1 entries, then depth-2, ..., flushing the batch at the end of every level so shallow results show at once; `rootWalk.Progress()` exposes the level depth and dirs read/total, `scan.Event` carries `Depth`/`LevelDone`/`LevelTotal` (max-depth aggregate across roots) into `FindDialogState`, and `findDialogTitle` renders `<[icons.dialog] depth> N · P%` plus the scanning icon) and stats nothing (`Size` 0, `Meta` nil) unless the advanced criteria need metadata (see Advanced criteria). `PathMeta` (`lookupFindPathMeta`) answers from `Entries` only; marked-file sizes fill in a generation-keyed background pass (`scheduleFindMarkedFileSizes`) applied via `RankWakePayload`; directory totals come from the disk-usage engine. `IndexFinished` does not bulk-replace the mirror. Title and list repaints share one throttle that loosens with index size (batches and include-hidden expansion alike). Matching is on paths relative to the root in the advanced match mode (fuzzy is the same `internal/search` subset as the quick filter).
- **No matches**: the query input takes the error style (`FindDialogState.NoMatches`: non-blank query, `IndexDone` and not `Indexing`, no `RankPending`, empty `Ranked`) only once the result can no longer grow, so a running walk never shows a false "no match". Twin: `IndexFindDialogState.NoMatches` (finished query, not `Searching`, no `Err`).
- **Max depth**: `FindDialogState.MaxDepth` (committed, 0 = unlimited, starts unlimited each open) and `DepthInput` (edit buffer, one digit 1-9) back an input on the query row (`dialog.FindDepth`; width `findDialogDepthFieldWidth` (depth icon + three input cells) plus `findDialogDepthGap`; tooltip `findDepthTooltip`, which shares its syntax lines `findDepthSyntax` with Find in index's depth input; the query grows into the rest of the row, and `Handler.queryWidth` reads the query's scroll width from the placed spec, `dlg.InputTextWidth`). Entry depth is the number of `/`-separated segments of `RelLine`; `StartOpts.MaxDepth` is relative to `DisplayRoot`, and walks rooted below it (selection roots, hidden-expanded dirs) get `MaxDepth` minus their own depth (`session.walkMaxDepth`) and are skipped when nothing is left. `rootWalk.runBFS` stops before a level past its atomic limit; `ingestBatch`/`ingestHiddenBatch` drop deeper entries from in-flight batches. `Handler.commitFindDepth` runs on a digit, 0, Backspace or Delete (each also returns focus to the query), on leaving the field (Tab/Backtab/Up/Down/Left) and on Enter (which returns focus to the query): a tighter limit calls `Coordinator.SetMaxDepth` (lowers running walks, prunes the index via `ReplaceEntries` + `IndexReplaced`, as `narrowSelection` does); a looser or cleared limit calls `restartFindIndexer`. Focus is a `dlg.ID` and the widgets come from `dialog.FindDialogView` (`dialogs.md`): query, depth, the Advanced checkbox, Only dirs, Only files, Include hidden, Stay on volume, optional selections, the advanced section when expanded, OK, Cancel; jump mode leaves the Advanced checkbox and the two radios out of the spec, so no focus move can reach them.
- **Stay on current volume** (default on, M-v): honors the `disk_usage_descend_into_mount_points` rule; toggling restarts the walk.
- **Include hidden** (default off, M-i): the first walk skips dotnames but records skipped directory and file paths (location only); enabling splices pending files in batches and walks pending directories without a re-index. Hidden-subtree walks are concurrency-capped by index size so `$HOME` can't spawn hundreds. Disabling strips them but keeps the pending list. Independent of panel ShowHidden.
- **Only directories** (M-n) / **Only files** (M-y): radio pair filtering the ranked list without re-walking. Row-1 options move with Left/Right. `ui.input.forward-word` stays text editing in the filter.
- **Match mode and advanced criteria** (`internal/findcrit`, pure; handler `internal/apphandler/find/advanced.go`; state `dialog.FindAdvancedState` in `FindDialogState.Advanced`, view `findAdvancedRows` in `internal/ui/dialog/find_advanced.go`). `findcrit.Mode` (Fuzzy / Glob / Regex) compiles the query once per match pass (`findcrit.Compile` -> `Matcher`, run by `runMatchInPlace`): fuzzy ranks by score; glob and regex keep walk order. Glob without wildcards wraps `*q*` (Find in index's Pattern convention) and compiles to a shell `panel.GroupMatcher` on the basename, or with a `/` to `panel.NewGroupMatcherFullPath` on the whole relative path (`*` crossing `/`). `Handler.validateQuery` sets `FindDialogState.QueryInvalid` (input error style) on a query that does not compile; the match pass returns nothing for it. Case: `[filter] case_insensitive` unless Case sensitive. `findcrit.Criteria` (age bounds on mtime / ctime / atime, size, Empty, Symlinks / Broken / Executables as alternatives, `[filter.types]` groups via `dialog.FilterTypesRegexp`, owner, Not mine) is applied inside the match workers (the `keep` filter of `runMatchInPlace`, with Only dirs / Only files) on `Entry.subject()`; an active criterion makes the filter non-empty (`Handler.findFilterEmpty`), so an empty query with criteria goes through the match worker instead of the walk-order mirror path. `Criteria.NeedsStat` picks `StartOpts.Stat` (`findcrit.StatMeta` lstats, on the `readLevel` workers via `statChildren`, every child `runBFS` will index (excluded and hidden ones are skipped; the hidden expansion stats those itself) -> `Entry.Meta`/`Size`; `StatMetaEmptyDirs` also opens each directory for `Meta.EmptyDir`); `Entry.Broken` comes from the symlink target stat `buildEntry` already does. `StartOpts.Exclude` (`findcrit.Excludes`) is checked before visibility in `runBFS` (neither indexed, recorded as skipped hidden, nor descended); hidden expansion goes through `session.enrichHidden` (exclude, lstat, symlink typing of spliced dot-files) and skips excluded hidden dirs. `commitAdvanced` re-parses the section (`parseAdvanced`, flags fields that do not parse: `FindAdvInput.Invalid`; owner via `localfs.LookupUser`) and restarts the index when `NeedsStat` exceeds `Handler.indexStat` or the excludes differ from `indexExclude` (both recorded by `startFindIndexer`), else re-ranks. Checkboxes and radios commit at once; text inputs (`editAdvField`, live `validateAdvField`; each carries its `findAdvTooltips` text as `Item.Tooltip`, drawn on the row below the focused input) commit on Enter and when focus leaves them (`advEditing` + `commitLeftAdvField`, run after every key and click). `find.toggle-advanced` (`ToggleAdvanced`; expanding focuses the selected Match radio, the section's first row, which turns the results inert; collapsing moves focus inside the section to the query), `find.cycle-match-mode`, `find.reset-advanced`; jump mode swallows all three. The section survives close (`Handler.savedAdvanced`, restored and parsed by `openDialog` before the walk starts). Collapsed, `FindAdvancedState.Summary` labels the separator above the list (`[icons.dialog] criteria`); `FindDialogMetrics` takes the state so list scroll math sees the expanded rows. The open section takes its rows from the result list (the list wants its closed height less the section, at least one row, and fitting shrinks both alike), so the frame keeps its size; when the frame does change, `App.paintFindDialogOverlay` (`App.paintOverlay`) compares the area `ui.PaintFindDialog` returns with the last one (`App.overlays`) and declines, so the caller's full render repaints what the old frame covered. While focus is in the section (`FindDialogState.AdvancedFocused`, the `find:adv-` ID prefix) the list is `Inert` (disabled style, no cursor row) and `PaintFindDialogRowIcon` draws the devicons disabled (blocked-chrome colours). The Advanced checkbox highlights `FindDialogState.AdvancedMnemonic`, the letter of the Alt+letter chord bound to `find.toggle-advanced` (`dialog.FindAdvancedMnemonic`, set by `openDialog` from `[dialog.find]`; none when the chord's letter is not in the label). The section's options carry letters (`findAdvMnemonics`) with `dlg.Item.MnemonicOutsideInputs`, so the engine neither draws nor honours them while focus is in a text input and they never shadow text keys; off an input a plain letter works like its Alt+letter for every option of the dialog (the engine's plain-letter stage).
- **Search only from selected directories** (shown only when directories are selected; default on, M-s): nested roots pruned. Unchecking widens incrementally (keeps hits, skips indexed subtrees); re-checking filters to scope and cancels out-of-scope walks. Each selected root's walk ignores gitignore even if the root is ignored; gitignore resumes once the walk widens. M-s never moves focus off the filter.
- **Marking**: `panel.select-toggle` uses `panel.ClearSelectionConflicts` (descendant/ancestor removal; **Removed conflicting selections** toast). Bulk operations use the `Entries` mirror and `panel.ApplySelectionAdds` (no per-mark coordinator calls): `find.select-all` (full filtered corpus, beyond `find_max_results`), `find.select-group`/`find.unselect-group`, `find.unselect-all`. Marked results show a selection-size indicator on the separator (`FindDialogState.MarkedSelectionSizeLabel`, `Theme.DialogIndicatorSelectionSizeStyle`; file sizes from the index, directories via `reconcileFindDialogSelectionSizeScans` on the disk-usage engine).
- `find.view` opens the highlighted file in the fullscreen viewer and hides Find behind it (a directory shows "View: not a file"). Hiding sets `FindDialogState.Open = false` with `Handler.hiddenForView`; `Handler.live()` (open or hidden) is the gate of the background work (ranking, rank wakes, marked file sizes, indexer restart), so a walk still running keeps landing, and `App.renderFindDialogUpdate` skips repaints while hidden (`HiddenForView`). Closing the viewer calls `preview.Host.FilePreviewFullscreenClosed()` -> `findCtrl.ReopenAfterPreviewClose()`, which reopens Find with its query, cursor, results and marks, invalidates the marked-size label and re-clamps the scroll (`EnsureFindListScroll`). If the viewer fails to open, Find is shown again at once. `CloseDialog` (and opening Find anew) drops the hidden state. `find.edit` (`Handler.EditSelected` -> `Host.EditFile` -> `App.editFileAt`, the edit entry `file.edit` also uses) runs the external editor on the highlighted file and keeps Find open with its results and marks; a directory shows "Edit: not a file". Footer (`findDialogMarkingFooterKeys`): `find.unselect-all` / `find.unselect-group` are the Shift-alternative "Unselect" word of `find.select-all` / `find.select-group` (`appendSelectFooterKey`) while bound to the Shift variant of the select key, else entries of their own. `find.select-parent-dirs` (footer from `findDialogOverlayFooterKeys`, `internal/app/input.go`) replaces the target selection with the unique parent directories of marked results (or the cursor row's parent); `panel.State.ParentDirsExcludingSelf` (`internal/panel/selection_parent_dirs.go`, `pathloc`-based) drops the panel's own cwd, showing "Already in the containing directory" when nothing remains; the merge is `BulkAddSelections`. See [panels.md](panels.md) for the shared selection primitives.
- **Park**: in `find.Handler.HandleDialogKey`, a key whose main-keymap action is the dialog's opener (`IsParkKey`: `panel.jump-dialog` in jump mode, else `panel.find-dialog` or `fileindex.find`) calls `Park` (`FindDialogState.Open=false`, `Parked=true`). `live()` includes `Parked`, so the walk, ranking and size lookups go on; `Hidden()` (parked or `hiddenForView`) makes `App.renderFindDialogUpdate` skip repaints. `openDialog` on the parked `PanelID`, `RootPath` and jump mode calls `RestoreParked` (clears `Parked`, `show()`, shared with `ReopenAfterPreviewClose`); any other open sets `Model.FindRelocate` (`dialog.FindRelocateState`, `PrimaryModalFindRelocate`) instead, and `App.answerFindRelocate` calls `RestoreParked` or `OpenFresh` (closes the parked one, opens on the asking panel); Cancel leaves it parked. `ui.Model.FindParkedOn` drives the panel's parked-find bottom indicator (see [panels.md](panels.md)). Twin: Find in index parks in `HandleFindKey` with the same `IsParkKey` (`IndexFindDialogState.Parked`; `HandleFind` still applies results while parked) and `openFindDialog` restores (`RestoreParkedFind`) or asks the same question with `FindRelocateState.Index` set (`OpenFreshFind`).
- **OK/Enter**: marked rows merge into the target selection; otherwise navigate (directory -> path, file -> parent with the file selected). `ui.open-primary`/`ui.open-secondary` open the result in a panel **without closing**; because the dialog's fast path (`paintFindDialogOverlay`) never repaints panels, `App.handleKey`'s `InputModeFindDialog` case compares both panel paths before and after and forces a full `render()` when either changed. Esc/Cancel cancels the walk and discards the index.

### Jump to directory (Find in jump mode)

- `panel.jump-dialog` (Left/Right -> "Jump to directory" uses that panel) calls `find.Handler.OpenJumpDialog`, which shares `openDialog` with `OpenDialog` and sets `FindDialogState.JumpMode` and `OnlyDirectories`. `StartOpts.DirsOnly` makes the shared breadth-first walk skip files (never indexed or recorded as skipped hidden). The flag flows through `findStartOpts` -> `session.startWalk`, so the Include hidden replay walks are directories-only too.
- Title "Jump to directory". Hidden/disabled: selection scope option (no `SelectionDirRoots`), Only dirs/files radios (`applyFindToggle` ignores them; Tab/arrow focus steps past the radios), marking (`panel.select-toggle`), select/unselect all and group, `find.select-parent-dirs`, `find.view`, `find.edit` (`RunAction` swallows them) and the marked-selection label. The footer (`findDialogOverlayFooterKeys(keys, jumpMode)`) lists only Open ◄/►. Kept: filter, Include hidden (M-i), Stay on volume (M-v), Enter/OK navigates (always a cd), `ui.open-primary`/`ui.open-secondary`, `panel.pin-toggle`, Esc.

## Bookmarks and path pickers

- Bookmark menu opens the shared `ui.PathPickerState` (title "Bookmarks", purpose navigate) and loads into the active panel. The same modal serves apply-to-field with **separate entry points**: **Bookmarks** (`bookmark.open`, `PathPickerItemsBookmarks`), **History** (`panel.history-dialog` while a path row is focused; `PathPickerItemsHistory`, passive then active, deduped; missing entries kept and dimmed after the async scan), **Pinned** (`panel.pin-dialog`; `PathPickerItemsPinned` = pinned directories only, deduped), **All paths** (`ui.input.path-picker-all`, `*` or `|`, consumed by `TryPathPickerHostShortcut` before the rune is inserted: pinned and history fill synchronously, `applyBookmarkLoad` merges async bookmarks in front and drops duplicates; "No paths" only if empty). Eligibility: `Handler.PathPickerHostFooterEligible` (`path_picker_shortcut.go`). Apply purposes keep OK + Cancel (`ApplyTransferDestination`/`ApplyFlattenDestination`/`ApplyFileDialogField`).
- The picker is a `dlg` spec (`dialog.PathPickerView`, `Handler.PathPickerView`, `Handler.HandlePathPickerKey`): `PathPickerState.Focus` is `PathPickerFilter` (empty = the query, which drives the list `PathPickerList`), `dlg.OK` or `dlg.Cancel`. ## Remote paths (SFTP)

- `pathloc.Parse` accepts `sftp://user@host/path`; `IsLocal()` is false for any non-`file` scheme; `SFTPEndpoint`/`SFTPRemotePath`/`SFTPHostPart` serve the backend and pool. `/~` and `/~/subdir` are client-side home markers (`SFTPRemotePath` uses `~`, expanded to the server path only at list/copy time); explicit `/` is filesystem root.
- **Pool** (`internal/fsbackend/sftp`): keyed by `user@host:port`; idle disconnect (`[sftp].idle_timeout_secs`) is not applied while `pooledConn.inUse()` (`activeOps`/`activeStreams` > 0). `ReadDir`, `Lstat`, mutations and stream-open take an operation lease; a successful open converts it into the `activeStreams` lease under one lock. Transport errors evict that exact pooled client; reads (List/Stat/ReadSymlink/OpenRead) may retry once on a new dial, mutations never replay; context errors aren't transport failures. The handshake uses a conn deadline plus `ctx` abort (close TCP, wait for `NewClientConn` to avoid a goroutine leak). A stalled `ReadDir` is canceled via `ReadDirContext`, then by closing the session. Timeouts and `known_hosts_file`: `[sftp]` in `docs/config.md`.
- **Auth order** (OpenSSH-style): `IdentityFile` from the matching `ssh_config` stanza (lookup by URI alias and resolved `HostName`; `%h`/`%r`/`%d` expanded), then ssh-agent (probed with `List`/`Signers`: `SSH_AUTH_SOCK`, stanza `IdentityAgent`, newest `/tmp/ssh-*/agent.*`, `~/.ssh/agent.sock`, `/run/user/$UID/keyring/ssh` last because stale keyring sockets are skipped; signers keep the Unix connection open until the handshake ends; a dead agent is skipped), then default `~/.ssh/id_*` only when the stanza has no `IdentityFile` and not `IdentitiesOnly yes`. A password dialog follows only after a pubkey-only handshake fails (TCP redial). Encrypted on-disk keys are skipped (use the agent).
- **Prompts**: host-key and password waits are serialized per App (`promptSem`), id-tagged, completed only by the owner, and `select` on the dial context so cancel posts a dismiss through the open-payload path. The password prompt is a `dlg` file dialog (`FileDialogSFTPPassword`: a `Password for user@host:` label and one input, OK / Cancel); OK and Enter answer the waiter, and Esc / M-c / `CloseFileDialog` call `Host.CancelSFTPPassword`. Host-key dialog: Accept (session), Save (append OpenSSH-normalized host, including non-22 ports, and reload the verifier in-process), Reject (M-a / M-s / M-r).
- **Connect dialog**: `remote.sftp-link` (Left/Right -> SFTP..., menu `T`) lists `Host` entries from `[sftp].ssh_config_file`, else `SSH_CONFIG`, else `~/.ssh/config` (`Include` globs expanded) with the shared fuzzy filter, plus a manual Location. Enter on a host fills `sftp://.../~`. The dialog is a `dlg` spec (`dialog.SFTPConnectView`, `dialogs.md`): the filter input (`SFTPFilter`) drives the host list (`SFTPHosts`, a driven list), so Up/Down/PgUp/PgDn and C-Home/C-End move the host cursor while the filter keeps focus, Tab goes to `SFTPLocation` and then the OK / Cancel strip, and `syncSFTPConnectDialogRanks` re-ranks on every filter edit. With no matching host Down moves focus on to the location. The host list shows `SFTPConnectListRows` rows (3 to 12, by terminal height). Dialing merges all stanzas for the alias (first-wins per keyword): `HostName`, `User`, `Port`, `IdentityFile`. `Host`/`Match host` wildcards match at connect time; `!` negations stay on the stanza and `MatchesHost`/`MatchesEndpoint` reject on any negated hit; space-separated patterns only (no comma `Match host`). Two `Host *` stanzas with different exclusions stay distinct. Panel URIs keep the alias; resolution happens at connect. `startSFTPConnect` stamps a per-panel generation and `applySFTPConnect` drops stale payloads, so a slow connect A can't overwrite B (panels connect independently). Failed dials append an `ssh config`/`matched=N` hint.
- **Remote panel**: list/enter/parent/refresh work; volume, disk usage and gitignore are disabled. Listings run in a goroutine and apply via `remotePanelLoadPayload` so `ReadDir` never blocks `PollEvent`; `[sftp].list_timeout_secs` bounds them and stale results drop when navigation moved on.
- **Remote transfers**: `file.copy`/`file.move` queue background jobs for local<->remote and remote<->remote (same host). `ops` streams through `fsbackend.OpenRead`/`OpenWrite` when backends differ; local<->local keeps `localfs.CopyFile`/FICLONE. Disk-space blockers run only for local destinations; CoW is off when any path is remote. Remote mkdir/rename/delete use the backend; chmod/chown/symlink/hardlink are blocked. Foreground remote mkdir/rename (plan + execute) and transfer/extract/flatten destination probes (`Stat`/`Mkdir`/`Rename`/flatten `List`/`CollectFlattenSources`) run on a worker and apply via generation-tagged `dialogctrl.RemoteFileOpPayload` (`handleEarlyInterruptPayload` -> `ApplyRemoteFileOp`) so an expired connection's password dialog can be delivered. Batch chmod/chown plan on the caller then run via `RemoteFileOpAttr`. Destination validation accepts `sftp://` (backend `Stat`, already off-thread). Remote symlinks in copy plans are skipped. `fsbackend.Backend.OpenRead` returns an `io.ReadSeekCloser` (SFTP: the remote file inside the stream-lease wrapper), so offset reads such as find-duplicates chunk hashing seek instead of downloading the prefix.

## The fileindex:// scheme

- `pathloc.SchemeFileIndex`: `fileindex://` followed by a cleaned absolute host path (`fileindex:///` is the index root; `Parse` rejects a relative one). `Base`, `Parent`, `HasPrefix` and `Join` use the file-scheme rules on that host path (no host part); `FileIndex(host)` builds one and `IndexHostPath` returns the host path, which may no longer exist on disk. `FilePath` refuses it, and a `fileindex://` path never shares a tree with the host path it names (`TreesOverlap`). `IsLocal()` is false, so every "not on the local host" branch applies: git column, gitignore, folder colours, volume probes, elevation and every write stay off. Disk usage is the exception: `HasSubtreeSizes()` is true and directory totals come from the index (panels.md, Disk usage, sized paths). Features that only hand a real path to an external tool (external editor, run-executable, drop to shell, send paths to shell, the embedded terminal) use `Path.HostPath()` (file:// itself, fileindex:// its host path, SFTP none) and `hostPathOf` (`app/panel_targets.go`) for entry paths; directory cases (`localActivePanelDir`, drop to shell) use `existingHostDir`, the nearest existing ancestor. `syncPanelFromSubshellCwd` stays gated on `IsLocal()`, so a fileindex panel never follows the shell cwd back.
- `pathloc.HasURIPrefix` (`sftp://` or `fileindex://`) is the one test for "a typed URI, parse it as given": `pathpick.ResolveDestination`/`TypedDoesNotExist`, `dialogctrl.PathEntryMissing`, `ops.resolveChild` and `TransferDialogState.DereferenceUnsupported` use it. `StartPathsMissingScan` still skips only `sftp://` (dialing SSH from a background scan).
- Listing, stat, rename and remove go through the registered backend like SFTP (`fsbackend.Default()`; `fileindex.Backend`, `internal/fileindex/backend.go`): `List` is `ListDir` on the `DirByPath` id (subdirs with no size or mtime, then files with their indexed size and mtime; the index root lists empty when nothing is indexed), `Stat` uses `DirByPath` or the parent listing, `OpenRead` opens the real file (`ErrNotOnDisk` when it is gone), `Rename` is fileindex's `Move` (moves or merges), `Remove` deletes the instance (and its file row when no other instance uses it; the directory row stays) or calls `RemoveTree` (the directory, everything under it, and ancestors left empty), `ReadSymlink` fails. `fileindex.browse` (`apphandler/fileindex.Handler.Browse`) resolves the panel directory with `fileindex.IndexLocation` and stats it through the registry on a goroutine before navigating (on a `fileindex://` panel it calls `Reveal`, so it toggles); `fileindex.reveal` stats the cursor entry's host path and navigates to its parent with it highlighted; on a panel with `WithIndex` set it turns the overlay off instead (`Handler.setBrowseWith`, shared with `fileindex.browse-with`). `ops.sameRenameRoot` asks the backend (`fsbackend.RenameRooter`, always true for fileindex, same host for SFTP) so two `fileindex://` paths take the backend `Rename` fast path (index-only move); `fsbackend.TreeRemover` lets `removePathRecursive`/`deletePathRecursive` remove a directory in one call. Mkdir, symlink and writes return `fsbackend.ErrReadOnly`. The backend's `Rename`, `Remove` and `RemoveTree` change the index only, never the disk (`Backend.List` shows indexed files only, so nothing that removes or carries along real files may be driven by it); a `fileindex://` panel is index-only, see Operations on fileindex:// paths below. Mass rename refuses non-local panels.
- **Browse with fileindex** (`fileindex.browse-with`, `Handler.BrowseWith`): toggles `panel.State.WithIndex` on the active panel and reloads it (`Host.ReloadPanel`); on a `fileindex://` panel it runs `reveal(true)`, so `NavigatePayload.WithIndex` sets the flag before the navigation; SFTP is refused by `localOrIndex`. `WithIndex` persists across navigation and `ApplyListing` clears it for a non-local listing; `App.wireIndexOverlay` seeds it on both panels from `[fileindex].start_browse_with` before the startup listings load. The overlay is `fileindex.Index.Overlay` (`internal/fileindex/overlay.go`), installed as `State.IndexOverlay` by `App.wireIndexOverlay` (`internal/app/index_overlay.go`); `ListingRefreshSnapshot` copies it into `ListingRefreshSnapshot.IndexOverlay` only while `WithIndex` is set and `fetchListingAt` calls it after a successful local list, on the fetch goroutine (so every listing path, tree children and carousel included, gets it; `panel` does not import `fileindex`). It sets `Entry.IndexStatus` from `entryStatuses` (the same function the `fileindex.status` column uses, with the `scan.Rules` from `scanSettings`) plus `tagged` from `EntryTags`, and appends ghost rows (`fileEntry`/`dirEntry`, `fileindex://` Loc, `IndexStatus` `missing`) for index-only names that an `Lstat` confirms are absent (hidden and git-ignored entries are not in the listing but exist on disk); a failed overlay leaves the plain listing. `scanning` is never stored: the renderer derives it from the row's task-job mark. `differs` comes from `Index.DirDrift`, which is `driftWalk` stopped at the first difference (see Report differences below for the walk), two passes share `State.requestIndexDrift` (candidates: indexed, tagged or `unchecked` directories; flat layout only; both call `State.ScheduleIndexDrift`). The automatic pass (`scheduleIndexDrift`, end of `ApplyListingPrefetched`) checks every candidate to `State.IndexAutoDriftDepth`, which `wireIndexOverlay` sets from `FileIndexConfig.AutoDriftDepth()` (the one mapping of `[fileindex].browser_scan_max_depth`: -1 unlimited becomes 0, 0 off becomes -1, N stays N; `DirDrift`'s `maxDepth` is directory levels below the subdir, 0 unlimited). The explicit pass `State.RequestIndexDrift(names...)` is unlimited and is called by `panel.dir-size` (`App.scanCursorDirSize`), the whole-panel disk usage scan (`App.startDiskUsageScanForPanel`) and the selection-size scan (`reconcileSelectionSizeScans`, which asks once per name per path and listing epoch: `selectionDriftAsked`). It runs on its own goroutine under one context per panel directory (`indexDriftState`: requests for the same directory share the context so walks for different subdirs run side by side, a request for another directory cancels the old one; nothing cancels it on navigation, `applyIndexDrift` drops results whose `Path` is not the request's `dir` or when `WithIndex` is off), `DirDrift` returns a status per subdir (`differs` when `driftWalk` yields any difference, else `unchecked` when a deeper directory exists beyond the depth, else `indexed`), delivered as `indexDriftPayload` through `asyncWakes(a).indexDrift` and applied by `State.ApplyIndexDrift` (`differs` replaces indexed, tagged and unchecked; `unchecked` replaces indexed only; `indexed` clears unchecked). The selection dedupe set tracks explicit requests only, so the automatic pass never blocks them. `entryStatuses` precedence for a file: not in the index (`excluded`/`new`), size or mtime differs (`changed`), not hashed (`unhashed`, `db.Recorded.Hashed`), else `indexed`; a symlink (`localfs.EntrySymlink`, also what an Lstat of an index-panel row gives) is judged by `os.Stat` of its target: a regular file takes that switch with the target's size and mtime, a failed stat gives `missing` when the index recorded the name and no status otherwise, a directory or other target gives none; the overlay's `tagged` upgrades only `indexed`, so `unhashed` wins over tags. `driftWalk` compares with `Recorded.Same` (size and mtime), so unhashed files never make a directory `differs`. Hash-dependent consumers see only hashed rows: `DedupFiles` skips entries with an empty `Content`, the hash and copies columns inner-join `file`, and `SubtreeSize` sums `instance.size`. `unchecked` has an icon in `[icons.fileindex_state]` and a style in `[panel.fileindex]` (`fileIndexStates`). `Index.OnChange` posts `indexChangedPayload`, which runs `App.refreshIndexViews` (`reloadIndexPanels` for every `WithIndex` panel and every `fileindex://` panel, whose listing is the index and follows what jobs change on disk only through the sink, then both panels' meta columns; a tag edit runs it too through `Host.RefreshMetaColumns`). Ghost rows: delete routes per path by scheme (a local path is deleted from disk, a ghost row's `fileindex://` path goes to the fileindex backend; a mixed selection works) and the delete dialog note is `deleteNote`; `State.GhostSources` / `panel.GhostRefusal` (string check, no I/O) refuse the copy/move dialog, `OpenFilePreviewFullscreen` and `resolveLocalEditFilePath`.
- **Other copies** (`fileindex.other-copies`, `internal/apphandler/fileindex/copies.go`): `Handler.Copies` refuses SFTP (`localOrIndex`) and directories, resolves the cursor entry with `hostPath`, and after `withIndex` runs `fileindex.Index.OtherCopies` on a goroutine (`FileInfo`: not found = `CopiesNotIndexed`, not `Hashed` = `CopiesNotHashed`, else `FindByHash(sha256)` plus `FindByHash(NoExifJPEG)` when the file has one, as the Copies column counts; sorted, self excluded). `CopiesPayload` is applied by `HandleCopies` only while the view is the browser, no modal is open (`Model.ModalDialogOpen`), and the active panel and its cursor entry path are unchanged. Messages: error via `SetErrorMessage`, "Not in the index: name", "Not fully hashed yet: name", "No other copies of name" (info); otherwise `Host.OpenFilePicker` -> `dialog.Handler.OpenFilePicker` (the one opener of the file-list picker, also used by the differences report) opens the shared path picker with `PathPickerPurposeNavigateFile` and `PathPickerState.IndexPanel` (items are host file paths; `Source` fills the source column, empty here). `activatePathPickerSelection` -> `host.ShowInPanel` navigates the active panel to the file's directory (`pathloc.ForPanel`, falling back to the `fileindex://` directory when the real one is gone; `fileindex.Handler.navigateTo` shares it) with the file highlighted; a failure shows "Show file" and keeps the picker open. This purpose keeps OK + Cancel, has no missing-path scan, no typed-path validation (`ArmPathPickerValidateTimer`) and no completion dropdown (`resyncPathPickerCompletion`): the query only filters the listed paths. Bookmark-only shortcuts (`bookmarkDialogOpen`) do not apply. `TryFilePickerShortcut` (`internal/apphandler/dialog/file_picker.go`) gives this purpose Find's list actions, for the differences report too: `find.view`, `find.edit`, `ui.open-primary` and `ui.open-secondary` from `[dialog.find]` (`Deps.KeysFindDialog`; there is no overlay table of its own), `panel.select-toggle` (except plain space, which is filter text) and `panel.pin-toggle` from the global map. Marks live in `PathPickerState.Marked` (host paths, counted in the buttons label); OK with marks runs `applyFilePickerMarks`, adding them to the active panel's selection, instead of showing the cursor file. Pins and selections use `pathloc.ForPanel` (`fileindex://` when `IndexPanel`, so the renderer wraps the row-marks resolver in `withFileIndexPaths`). View and edit act on the real host path and refuse `PathMissing` rows; view hides the picker (`filePickerHiddenForView`) and `previewHost.FilePreviewFullscreenClosed` -> `ReopenFilePickerAfterPreviewClose` restores it. Open-in-panel keeps the picker open and leaves the active panel alone. The footer advertises view, edit and open-in-panel (`pathPickerMetaFooterKeys`).
- **Operations on fileindex:// paths** (ADR 0027): a `fileindex://` panel changes the index only; the disk is not touched. Paths are never translated for it: `ExecuteDeletePaths` and `ExecuteRename` hand a `fileindex://` path to the backend (`Remove`, `RemoveTree`, `Rename`), which has no host path, so there is no elevation and no `fschange` report; `Index.changed()` refreshes the panels showing the index. A move inside the index is a record rename. Copy out to a real directory reads through the backend (indexed files only). `indexTransferRefusal` (`AddTransferJob`, wording `ops.IndexReadOnlyRefusal` / `ops.IndexMoveOutRefusal`, the one source, also used by the extract dialog) refuses a copy or move into the index from outside, a copy inside the index and a move out of it; `AddTransferJob` returns false then and the transfer dialog stays open. `ops.ValidateFlattenTarget` refuses a `fileindex://` root or destination (`ops.FlattenIndexRefusal`) for `confirmFlatten` and `ExecuteFlatten`. `ExecuteExtract` refuses a `fileindex://` destination and translates the archive sources with `Path.Local()`, as they are only read; `EnqueueExtractJob` translates sources the same way. `ops.SelfTargetCount` translates what it is given, so copying an index entry onto its own file is caught. Cleanup skips `fileindex://`: `RemoveEmptyDirsUnder` and `DanglingDirsAfter` drop `fileindex://` roots (`skipIndexPaths`) and `removeDirIfEmpty` returns "not removed" for a `fileindex://` directory (the backend's `Remove` drops the whole index tree, and its listing hides unindexed files). Mkdir and symlink stay refused. The one operation that takes `fileindex://` paths to the disk is the dedup view's delete (`Job.DeleteOnDisk`, `ops.OnDiskPaths` / `ops.OnDisk`, an `Lstat`: an entry on disk is deleted there, one gone only loses its record; `PreviewEmptyDirsUnder` translates the same way). The fullscreen preview and compare view delete a `fileindex://` path from the index only, like the panel.
- **Index sink** (`fileindex.Index.Apply`, `internal/fileindex/follow.go`): `Job.FollowIndex` is set at enqueue by `panel.FollowsIndex(activePanel, paths...)` (the active panel has `WithIndex` or a `fileindex://` path, or any source is `fileindex://`); `State.EnqueueUndo` and `Job.RetryClone` copy it. `jobbridge.TransferFunc(..., fsSink, indexSink)` reports to `fschange.Multi(fsSink, indexSink)` for a following job and to `fsSink` alone otherwise. The dialog handler's `fsCtx` does the same for the active panel (`Deps.FileIndex`; renames, mass rename, the elevated retry). Only changes made on the disk reach the sink (a Browse-with panel's local operations, a dedup delete of files on disk); a change the backend makes to the index itself is not reported. `Apply` only appends a clone of the batch and starts the one drain goroutine if none runs; the drain skips everything while `openQuietly` finds the index unavailable (never prompting or creating a database), applies each batch in order under `Index.writeMu` (shared with the backend's own index writes) and calls `OnChange` once per pass that changed a record, then waits `applyPause` so a job's small changes join one pass instead of reloading the panels once each. `OnChange` reaches `App.refreshIndexViews`, which reloads the panels showing the index and re-runs only their fileindex meta columns (see Invalidation in `panels.md`). `Removed` removes the tree or instance the index holds (the index decides which; `IsDir` only picks the lookup tried first); `Renamed` drops a record at the target, then `db.Move` (a directory onto an indexed directory merges there); a batch whose renames chain (a mass rename swap) goes through temporary record names. Paths are resolved as `db.Resolve` does for their directory and keep their name, so a path that no longer exists maps to its record. Paths the index does not know, `Created` and `Dirty` are ignored. A busy database (a scan committing) is retried (`busyRetries`, `busyBackoff`). `Index.Close` waits for a drain in flight (`WaitApplied`). New files, copies and extracted files are not added: a scan does that.
- **Report differences** (`fileindex.report-differences`, `internal/apphandler/fileindex/differences.go`): `Handler.ReportDifferences` (refuses SFTP via `localOrIndex`) targets the cursor entry when it is a directory other than `..` (a ghost directory included), else the panel directory, `hostPath`s it and queues `Index.DifferencesTask` (lease `fileindex.DifferencesLease`, apart from the scan lease) as a task job whose source is that directory; `queueTask` runs inside `withIndex`. The task resolves the path with `IndexPath`, runs `driftWalk` unlimited, reports walked files as progress, sorts by path and calls its `done` callback however it ends (an `ErrNotIndexed` ends the job normally). `driftWalk(ctx, d, rules, root, maxDepth, onFile, yield)` (`internal/fileindex/overlay.go`) is the one comparison behind both the icon and the report: walked files are `new` (no record) or `changed` (`Recorded.Same` false); once the walk finished (not when `yield` stopped it) every recorded file within the depth that it did not visit is `Stat`ed and is `missing` only when the error is not-exist, `ENOTDIR` or `ELOOP`, so records below an excluded or unreadable directory are no difference; the depth-limited walk seeds its visited set with the root's directory key; `deeper` says a directory below the depth was skipped. `ReportDifferences` queues through `addTask` (no toast) and a `time.AfterFunc(config.DifferencesFastWindow)` posts `DifferencesQueuedPayload`; `HandleDifferencesQueued` toasts `fileindex differences queued` (info) unless the shared `Resolved` bool (UI goroutine only, set first thing by `HandleDifferences`) says the result is already handled or `Host.TaskUnfinished(p.Task)` says the report's job is finished or gone (canceled while it waited for the lease, so nothing resolves it). `DifferencesPayload` (carrying `Started`, the job's `*jobs.Task` and `Resolved`) reaches `HandleDifferences`, which returns silently for a canceled report and otherwise always shows `No differences` (success urgency) / `NAME is not in the index` / the error (the task sets `Task.ReportsOwnOutcome`, so the job queue's own toasts do not replace the result), whatever the view or dialog. With differences it sets `Task.Results` (label `N differences`, `Show` = `Host.OpenFilePicker` with `PathPickerItem{Source: state, Path, PathMissing: state == missing}`, title `Differences under NAME (N)`, `IndexPanel` when started from a `fileindex://` panel) and calls `Host.SyncJobsList` (the payload can land after the job's terminal event); then it calls `Show` when the result came less than `config.DifferencesFastWindow` after the request and `stillBrowsing` holds (the guards of `HandleCopies`), else toasts `N differences under NAME: see Jobs view` (success) and the result waits on the job (`jobs.show-results`). Results are never dropped.
- **Manual test data**: `test-cases/gen-fileindex-drift.sh [dir]` (default `fi-testdata/`) builds a tree and an isolated index covering each directory state, the differences report and operations from both panel kinds; its header lists the expected states and it prints the launch command. Keep the output untracked but not gitignored, and use names the repo's `.gitignore` does not match (pc's gitignore filter would hide them).
- **Display**: `primitive.PathWithHomeTilde` never cleans a URI (it would collapse `//`); it shows it as is, or swaps a registered prefix (`primitive.SetPathDisplayPrefixes`) and shortens the rest as a host path. `App.setStyles` (startup, theme switch, Nerd Font toggle) registers `pathloc.FileIndexPrefix` -> `Theme.IconFileIndex()` + `://` when icons are on, nothing otherwise. `ui.PanelTitlePath` keeps a URI's scheme (and SFTP host) whole when abbreviating.
- The rename and delete dialogs show `FileDialogState.Note` (`renameIndexNote`, `deleteIndexNote` and `deleteGhostNote` in `internal/apphandler/dialog/file_ops.go`, the one source of the wording; a warn-styled label under the name field, above the delete summary) on a `fileindex://` panel, where the entry shown comes from the index and the dialog says that only the index changes and files on disk are not touched. The dedup view builds its own delete dialog (`App.openDedupDeleteDialog`) and never uses `deleteNote`.

### Find in index

`panel.find-dialog` and `panel.jump-dialog` on a `fileindex://` panel open the Find in index dialog instead of Find. `fileindex.find` is the second entry: it opens the same dialog from a local or `fileindex://` panel (`Handler.Dispatch` -> `OpenFindDialog(ActivePanel, false)`; SFTP is refused by `localOrIndex`). The root is `hostPath` of the panel path, so a local panel works; `IndexFindDialogState.FromIndexPanel` records the origin scheme. From a `fileindex://` panel results navigate and select as `fileindex://` paths; from a local panel they use plain host paths (`Handler.panelPath`), and navigation falls back to the `fileindex://` path when the real directory is gone. `App.openFindDialog` (`internal/app/fileindex_host.go`) is the one entry (key dispatch and the menu both call it) and routes on `Path.Scheme()`; Find would otherwise walk the local disk with the URI as a path. **Twin of Find**: keep the two in step (see the twins rule under Find); absent here: Stay on current volume, gitignore, fuzzy ranking (replaced by Pattern / Boolean), indexing progress.

- State `dialog.IndexFindDialogState` (`ui.Model.IndexFindDialog`), view `dialog.IndexFindDialogView` (dlg engine), handler `internal/apphandler/fileindex/find.go`, input mode `InputModeIndexFindDialog`, `App.activeDialog` case. The query input drives the result list; Pattern / Boolean radios (hidden in jump mode), Only directories / Only files (Only directories is disabled in Boolean mode), Include hidden, the depth input (one digit 1-9, 0 or empty unlimited, committed like Find's; its tooltip is `findDepthSyntax` plus a filter-only line) and, when the panel had selected directories, Search only from selected directories. Jump mode shows only the query, depth and Include hidden, and forces Pattern + directories only.
- Query (`fileindex.Index.Find`, `internal/fileindex/find.go`): Pattern is the library's case-insensitive basename glob (`FindByName`; a query with no `*` or `?` is wrapped as `*query*`), Boolean is FTS5 (`FindByWords`, files only, a syntax error is shown in the dialog). Depth, hidden and the selected-directory scope (`FindQuery.Roots`, results merged and deduplicated) are applied in `Find` before the cap at `[ui.find].max_results`; the title shows `N+` when truncated. The library has no LIMIT, so results are capped after the query (`ponytail:` comment). Debounced by `[ui.find].query_debounce_ms` on a goroutine (`time.AfterFunc`); `FindPayload.Gen` guards against stale results (`HandleFind`), `Gen` keeps counting across dialogs. Radio / checkbox / depth changes query immediately; an empty query clears the list.
- Results carry host paths. Marks are keyed by host path (`Marked`, `MarkedDirs`, `MarkedSizes`) and OK with marks adds `pathloc.FileIndex(path).String()` selections to the panel (`BulkAddSelections`, same toasts as Find); without marks OK/Enter navigates the panel (a directory itself, a file's parent with the file highlighted). The button separator shows `N items (size)` (`MarkedLabel`; directories add no bytes, a `ponytail:` comment).
- Keys: `dlg.HandleKey`, then the shared `[dialog.find]` overlay (`a.keys.FindDialog`, no table of its own): `find.view` (the real file in the fullscreen viewer, the dialog hidden behind it and reopened as it was when the viewer closes: `findHiddenForView`, `ReopenFindAfterPreviewClose`; a query result in flight still lands; a directory says "View: not a file"), `find.edit` (`editCursor`: the real file in the external editor, dialog kept open; a directory says "Edit: not a file"), `find.select-all`, `find.unselect-all`, `find.select-group` / `find.unselect-group` (the group dialog in context `index-find`; `findctrl.NewPathMatcher` matches, counted and applied synchronously over the capped result list), `find.select-parent-dirs` (`ParentDirsExcludingSelf` + `SelectDirs`), `ui.open-primary` / `ui.open-secondary` (navigate without closing), `panel.select-toggle` (mark and advance) and `panel.pin-toggle` (pins the `fileindex://` path, dialog stays open). In jump mode marking, select, group, parent dirs, view and edit are swallowed; pin and open stay. The footer is `findDialogOverlayFooterKeys`.
- Row devicons are `ListRow.Icon` text; pin / job marks come from the same `rowMarksResolver` as Find, keyed by the `fileindex://` path.
