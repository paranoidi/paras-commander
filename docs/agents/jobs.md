# Jobs

Background jobs live in `internal/jobs`; the transfer glue is `internal/jobbridge`; file operations are `internal/ops`. User-facing behavior: `docs/jobs.md`, `docs/background-scan-throttle.md`. Defaults for every `[jobs]` / `[operations]` key named here live in `internal/config/builtin.go` and `docs/config.md`.

## Job lifecycle and locking

- `jobs.State.mu` (`internal/jobs/state.go`) is the sole lock for lifecycle fields (`Status`, `FinishedAt`) and the ownership buckets (`active`, `waitingBlocker`, `pendingDequeued`, `finished`). Lock order: `State.mu`, then `Queue.mu` (pointer slice). `*Unlocked` queue helpers (`dequeueRunnableUnlocked`, `pauseQueuedJobUnlocked`, ...) require `State.mu`; exported `Queue` methods take `Queue.mu` themselves. `AllJobs()` / `MenuBarStripStatuses()` copy lifecycle fields under both locks and deduplicate by job ID (first bucket wins), because buckets overlap during blocker transitions.
- States: scanning, queued, paused, running, waiting-decision, completed, failed, canceled.
- **Transfer lease**: `transferLease` serializes copy/move/flatten/extract, one at a time. `Job.holdsTransferLease(other)` (`internal/jobs/job.go`) is true for all of those; a delete takes the lease only when its source roots overlap `other`'s sources or destination (`pathloc.TreesOverlap`, ancestors included). Disjoint deletes run concurrently with each other and with the lease holder.
- `State.active` is a set of running jobs. `leaseHolderUnlocked` returns the one lease holder; `ActiveJob()` and `SampleActiveJobThroughput` read it, so they keep reporting the transfer while deletes run. `cancelRun` is a `map[jobID]CancelFunc`. Each `runJob` context derives from `s.workerCtx` and is registered in `cancelRun` before the lease wait; after acquiring the lease (and once before waiting) `runJob` returns without flipping status if the job is finished or its context is done. `workerShutdown` joins goroutines via `s.jobWg` and skips blocking lifecycle emits when the worker is stopped.
- `pendingDequeued` holds jobs removed from the FIFO by `dequeueJob` but not yet in `active`, so `AllJobs()` never drops entries when several jobs are queued or resumed at once. Entering a blocker removes the job from `active`/`pendingDequeued` and any stray FIFO row.
- **Cancel** cancels the scan producer from every `CancelJob` branch (active, pending-dequeue, waiting-decision, queued, scanning) and from `workerShutdown`: a producer blocked sending into a full `PlanCh` outlives `scanning`, and would leak forever on a paused huge job. Blocker **Cancel** returns `jobs.ErrUserCanceled` so the job ends `canceled`, not `failed`.
- **Retry**: `State.RetryJob(id)` requeues a `StatusFailed` job under the same ID via `Job.RetryClone()` (only enqueue-time spec fields carry over; progress, `PlanCh`, `Error`, timestamps, `PendingBlocker` start zero) through the normal `AddJob` path. `jobs.resume` (Ctrl+R) dispatches to `ResumeJob` for paused and `RetryJob` for failed jobs (`resumeOrRetrySelectedJob`). `Handler.SelectedJobStatus()` is the single source for the footer relabel (`menu.FunctionKeysJobsView`) and the leader-menu relabel (`openViewLeaderMenu`).
- **Error text**: `ops.RootFirstErrorText(err)` (`internal/ops/source.go`) renders `"<root cause>: <outer context>"` and is the single formatter for `Job.Error` and the `EventFailed` `Error` field. `Event.Err` (raw) is unaffected.
- Quit: `F10` confirms when jobs are active, paused, or waiting, or a run-for-each batch or captured user-menu run is in flight (`commandsBatchesInflight`; interactive/detached entries do not count). `app.quit-immediate` (Shift+F10) skips the dialog but still stops the worker. `jobs.cancel` (Ctrl+C) is a `[jobs]` overlay key and only acts while the jobs view is focused.

## Scan (planning) and totals

- Only `TypeCopy` pre-scans (`Job.NeedsPreScan()`); move and flatten enter queued/paused directly. A copy leaves `scanning` as soon as the first plan item is known, so bytes move while the walks continue.
- `jobbridge.ScanFunc()` runs **two independent walks** (both `ops.BuildPlanStreamCtx`):
  - **Delivery walk** feeds `Job.PlanCh` through a bounded relay; the executor consumes it via `ops.ExecuteCopyUsingPlanChan` (same `executeCopyIter` loop as the slice path).
  - **Counting walk** tallies `files`/`dirs`/`totalBytes` and discards items.
  - They are separate because the relay blocks for as long as the executor spends on one item (e.g. a huge file) and totals tallied on that path would freeze. Totals emit via `EventScanTotals` at `[jobs].scan_progress_min_interval_ms`.
- `Job.PlanComplete` flips true when both walks finish. `PlanProducer.Err()` reflects only the delivery walk; a counting-only failure never affects the outcome. The counting walk runs with `OnWarning`/`OnPath` cleared (`countOpts`) so nothing is double-reported and `runJobScan`'s `lastProgress` has one writer. `Job.TotalsComplete` (counting walk done) is what the jobs view uses for the `(scanning...)` suffix, not `PlanComplete`.
- **Mid-stream enumeration errors** can land after real work happened. `runJobScan` (`internal/jobs/scan.go`) calls `finishScanFailed`/`finishScanCanceled` only if the job never left `scanning` (`alreadyFlipped`). Otherwise it just sets `PlanComplete` and final totals, and the executor ends the job `failed` via `job.PlanErr()` with completed work kept. This avoids two writers racing on `job.Status`.
- **Scan throttle** (`internal/jobbridge/scan_throttle.go`, `newAdaptiveThrottleYield`): both walks yield cooperatively (`[jobs].scan_yield_interval_ms` every `scan_yield_every_n` entries), never via OS nice. The counting walk additionally runs a duty-cycle probe, only while the job's own EMA transfer rate (`ETABytesPerSec`, exposed as `ScanWalkHooks.ThroughputBPS`) is positive: it pauses the walk for a short window and compares throughput before vs. during. A significant rise grows an injected per-yield pause (`dutyPauseMS`, capped); no rise decays it toward zero. Evidence-based, no disk-type detection: on SSD/NVMe/network the pause never helps and stays at zero. Constants are `DefaultScanThrottle*` in `internal/config/builtin.go`; `[jobs].scan_disable_adaptive_throttle` turns the probe off.
- **Disk-usage feed**: a clean single-source, local, non-dereferencing copy publishes the counting walk's byte total to `State.sourceSizeSink` (`SetSourceSizeSink`, wired to `diskusage.Engine.SetSize` in `internal/app/app.go`). Move/flatten and dereferencing or multi-source copies never feed it (stale or out of scope).
- **Plan fallback**: `ops.BuildCopyPlanWithTotals` (full `[]PlanItem`, consumed by `ExecuteCopyUsingPlan`) is the synchronous fallback `jobbridge.TransferFunc` uses only when `Job.PlanCh == nil`.
- `Job.Warnings` collects non-fatal plan issues (symlink-dereference fallbacks), appended under `State`'s lock from the producer's `OnWarning`. Only a non-empty `Error` fails a job, never `Warnings`. The Details pane renders `Warnings (N):` after `Error:` (`detailStaticLines`, `internal/ui/jobs_view_render.go`).

## Disk space

- Enqueue never walks or checks space (F5/dialog queue immediately; a pre-enqueue walk would block the UI thread). `ops.EnsureDiskSpace` runs at run time.
- The whole-payload upfront check runs only on the synchronous-rebuild fallback (`PlanCh == nil`). Streamed jobs skip it: `TransferFunc` cannot race-free read a still-streaming job's `TotalBytes`/`PlanComplete` (the producer writes them under `State`'s lock). The per-file check is the safety net (mc has no upfront check at all).
- Per-file check applies at or above `[operations].disk_space_check_min_file_bytes` (`0` = every file).

## Blockers

- File-exists conflicts and insufficient disk space share one mechanism: `jobs.EventJobBlockerRequest` + `jobs.BlockerDetails`. The worker **releases the transfer lease** while waiting so another job can run; `State.SubmitBlockerDecision` / `SubmitConflictDecision` resumes.
- Choices: File exists (overwrite / overwrite all / advanced rules / skip / skip all / cancel), Disk space (retry / abort). When exactly one side is a directory (or a symlink to one; `ops.FileConflictFacts.Mismatch`) the prompt reads `Destination is a directory` / `Destination is a file`, hides Overwrite and Advanced, and offers rename / rename all / skip / skip all / cancel; remembered overwrite-all and rule answers are ignored for it and the user is asked again (see ADR 0011). **Match size** is job-wide and sticky: overwrite when sizes match, silently skip otherwise.
- Surfaces: the jobs-view blocker panel above Details; the quick dialog `jobs.answer-blocker` (Ctrl+Q, `PrimaryModalConflict` slot) which opens the oldest FIFO `waitingBlocker` job and adds **Postpone**; `[jobs].blocker_dialog_next_debounce_ms` auto-opens the next prompt after a real answer. Opening the jobs view (`jobs.open`) while a blocker waits selects the first such job and focuses the blocker panel. The menu bar shows a `status.waiting_input`-styled "N job(s) waiting" label before the permission tail.
- Alt+letter shortcuts match button shortcuts; Alt+R is disk-space Retry on the blocker panel.

## Copy and move execution (`internal/ops`)

- **Move** (`ExecuteMove`; flatten runs `ExecuteFlatten`, see [file-operations.md](file-operations.md)) is a per-top-level-source loop in the style of mc: resolve destination, run the shared `ConflictResolver`, try `RenameFastPathCtx`. A directory onto an existing directory **merges** (`moveOne`/`mergeMoveDir`: no prompt for the directory, children recurse, emptied source removed via `removeDirIfEmpty`); symlinks are never descended (`statEntry` is Lstat-based).
  - Overwrite replaces a non-directory with a non-directory only (`resolveConflict` turns an overwrite on a directory mismatch into skip). Local paths just `rename(2)` onto the destination; SFTP renames the original aside to `.paras-move-stash-N`, restores it if the rename fails or needs the copy fallback, removes it on success (SFTP v3 rename cannot replace).
  - Only a source whose rename cannot be used (cross-device/host) is planned, disk-checked, copied via `executeCopyWithPlan` and removed (`finishMoveCopyPhase`). Earlier renames are never rolled back.
  - Remote stat/rename/stash use the job `ctx` (backends via replaceable `backendFor`); local `os.Rename` is not context-aware.
  - `ops.Options.OnRemoveSources` fires before fallback removal; `jobbridge.TransferFunc` wires it to `EventRemovingSources` -> `Job.RemovingSources`, which drives the menu-bar delete gradient (see [architecture.md](architecture.md)).
  - Move progress counts top-level sources (`EventPlanTotals` `TotalFiles = len(Sources)`, one `DoneFiles` per rename); a copy-fallback source reports per-item progress, so totals can exceed the announced count.
- **Copy details**: directory `chmod`/`chtimes` run after the full plan so children don't clobber parent mtimes; timestamps use real atime on Linux (`localfs.FileTimes`), remote sources use mod time for both. Symlink conflicts use `Lstat` on the destination; skipped symlinks and skipped conflicts do not count toward `DoneFiles`/`DoneBytes`.
- **Symlinks** are recreated as symlinks by default. `Job.DereferenceSymlinks` (`[operations].dereference_symlinks` / Copy dialog checkbox) copies through them like `cp -L`:
  - `localfs.WalkDirRecursiveDeref` `os.Stat`s each link in place; the `PlanItem` keeps the link's own path but is classified as the resolved kind, so the rest of the pipeline needs no special case.
  - Cycle detection uses the ancestor stack of the current recursion path (`os.SameFile`), not a whole-tree visited set, so sibling links to one shared target work; `maxSymlinkDerefDepth` (32) backstops long chains.
  - Anything not safely dereferenceable (broken, permission, cycle, depth cap) is recreated as a plain symlink and recorded in `Job.Warnings`.
  - Local-to-local Copy only: `AddTransferJob` (`internal/apphandler/jobs/handler.go`) decides the field and forces it false for Move; `jobbridge.buildTransferOptions` strips it whenever any endpoint is remote, with CoW, `copy_file_range`, sparse and preallocation.
- **Fast paths** (Linux, local only; remote endpoints disable them): `[operations].cow_file_cloning` tries `ioctl(FICLONE)` in `localfs.CopyFile`, then `[operations].copy_file_range` tries `copy_file_range(2)`, then falls back to `io.CopyBuffer`. One copy buffer (`[operations].copy_buffer_kib`) is allocated per job and passed through `localfs.CopyFile`/`copyFileTransfer`.
- **Durability**: `[operations].sync_after_each_file` fsyncs each destination before close. `[operations].sync_write_behind_mib` bounds the gap on filesystems that accept writes at memory speed (e.g. ZFS): `localfs.CopyFile` wraps `onWritten` and fsyncs every N MiB (`CopyFileOpts.SyncWriteBehindBytes`), reporting progress only after the flush. This keeps reported progress (and therefore the throughput chart, which decays idle columns to zero) honest. A mid-copy fsync error aborts immediately (`abortPartialLocalCopy`), since Linux reports fsync errors once per fd.
- **Progress and cancel**: byte-granular via `localfs.CopyFile`; `ExecuteCopy` throttles `EventProgress` (`[jobs].worker_progress_min_bytes` / `worker_progress_min_interval_ms`). Cancellation is checked per plan item, per buffered read, and per `copy_file_range` syscall (chunk-capped at `DefaultCopyFileRangeChunkMiB`); FICLONE is metadata-only.

## ETA and throughput

- ETA uses EMA-smoothed bytes/s and files/s (`jobs.ApplyProgressETA`); metadata-only steps advance the sample clock so later byte deltas aren't divided by absorbed time. `jobs.FormatETA` blends each rate toward the cumulative average and shows the longer of byte-based and file-based remaining. `jobs.ComputeQueueETAs` is cumulative across unfinished jobs.
- **Displayed speed is sampled on a fixed wall-clock grid, never on progress events.** `jobs.SampleThroughputColumns` (`internal/jobs/throughput_strip.go`) closes each elapsed `[jobs].throughput_chart_column_ms` column, spreads bytes moved over the columns actually elapsed, and feeds the instantaneous rate into one EMA, `DisplaySpeedBPS`. That single value drives both the Queue **Speed** column and the Details chart (one sample per closed column, newest on the right). Idle columns feed zero; a late tick replays all elapsed columns (bounded by strip capacity); a large batched `EventProgress` is spread across the columns it covers.
- The `App` ticker (`internal/app/throughput_chart.go`) fires at column/4 (floor 40 ms) via `throughputChartTickPayload`, so boundaries land on the wall clock; oversampled ticks are no-ops and only a closed column repaints. It runs even when `throughput_chart_enabled` is false, because it also clocks the Speed column. `State.SetThroughputChart` wires column, window and enabled flag at startup; disabled means no strip data in the jobs DTO and no graph.
- Rendering: `jobs.ThroughputChartColumnBuckets` + `internal/ui/throughput_graph.go` (btop-style braille, same 25-char `braille_up` map). Until the first column closes the UI shows "collecting samples".

## Rate limit

- One global `*RateLimiter` (`internal/jobs/ratelimit.go`, hand-rolled token bucket) on `State`: `SetTransferRateLimit(bps)` / `TransferRateLimit()`, `0` = unlimited, session-only (never written to config), applied to all transfers together. `State.Wait(ctx, n)` is passed into `internal/ops` as a plain `ops.RateLimiter` func via `jobbridge.TransferFunc`'s third parameter (set in `internal/app/app.go`), so `ops` never imports `jobs`.
- Throttle point: `ops.Options.RateLimit` in both `onWritten` closures of `copyRegularItem` (`internal/ops/copy.go`). Kernel fast-path copies report their whole size in one call, so they are throttled post hoc.
- Controls (`Handler.TryDispatch`/`adjustRateLimit`, Queue panel focused): `+`/`-` step by `rateLimitStepBPS`. From Unlimited, either key starts at the active job's effective throughput rounded to a step (`rateLimitNoJobStartBPS` when idle). `-` floors at one step and never falls to Unlimited; only `jobs.rate-limit-clear` (Ctrl+U) or the Jobs menu item clears. None appear on the F-key bar.
- Display: the Queue panel's border end-label (`formatRateLimitLabel`, padded per the border-label rule in `dialogs.md`). `internal/app/render.go` refreshes `Model.JobsTransferRateLimitBPS` every frame.

## Jobs view and panel integration

- **Event draining**: job events are drained on key and `jobsWakePayload` only, not spinner/volume/chart interrupts. Progress events in a batch are coalesced to the last sample per job. In the browser, progress neither wakes the UI nor repaints the twin panels; the jobs view repaints. `syncJobsList()` runs while the jobs view is open.
- **Free space** uses async `statfs` (`[jobs].free_space_on_progress_wake`, `free_space_poll_interval_secs`). Panels on the same volume as an active job skip progress/ticker `statfs`; `Job.VolumeDevs` is computed once in `AddJob` (`ComputeVolumeDevs`: one stat per distinct source parent plus destination, not per source, because `AddJob` runs on the UI thread and per-source stats froze the app on network mounts). The suppression check runs inside the async goroutine so the UI thread never stats job paths. Menu-bar spinner: `DrawMenuBarSpinnerOnly` without draining the channel. Browser list paint runs `DiskScanExcluded`/`PendingForPanel` only when disk-usage metering is shown.
- **Layout**: right column is optional blocker panel, Details, Activity. Activity appends at most one line per file (`appendJobActivity`, `internal/apphandler/jobs/handler.go`); `EventFailed` appends `Failed: ...` via `jobbridge.ActivityFailureLabel`. Details ends with Current then the throughput chart and takes only the height it needs. Tab cycles list, blocker (when the selected job waits), Details, Activity.
- **Queue columns**: Type, Status, ETA, Speed fixed; Progress takes the remainder (`jobs.progress.*` styles). Percent uses `DoneBytes/TotalBytes` when `TotalBytes > 0`, else `DoneFiles/TotalFiles` (`jobPercentDone`). Delete jobs show item counts (`jobDetailProgressLine`). Status icons: `Theme.IconJobsList` (`[icons.jobs.list]`). Finished jobs stay per `[jobs]` `show_finished` / `keep_finished`.
- **Enqueue clears selection**: queuing a copy/move (OK or Add paused) clears all tagged selections on the active panel. Opening or canceling the dialog does not. Enqueue does not touch panel listings; `ApplyRefreshes` -> `RefreshBothPanels` reloads them on terminal events.
- **Row suffix indicators** (name column, right to left: job, new-file, renamed, working, subtree-selection). Layout and styling: `internal/panellist` (`RowSuffix`, `EntryDisplayRunes`, `ListingSuffixSpans`). See [panels.md](panels.md) for the working icon and pinned mark.
  - **Job suffix group**, order `<job><queued><operation>` (`panellist.JobSuffix`): job icon colored by role via `Theme.PanelJobMarkStyle` (`panel.row.mark.job` destination, `.job.read` source, `.job.decision` waiting); queued icon only while the matched job is `queued`; operation icon for move/flatten/delete (copy/extract get none). `jobRowSuffix` (`internal/ui/job_row_suffix.go`) is the single resolver for the twin list, carousel (`panelcarousel.JobMarkFunc`) and bottom-border cursor hint. `dialog.RowMarks` dialogs keep only the job icon.
  - **Matching** (`internal/ui/job_path_marks.go`): rows under any job source or per-source resolved destination root match. `newJobPathIndex` resolves destinations from `Job.DestIsDir` plus a plain `Join` fixed at enqueue and **must never Stat** (render-critical). Overlap precedence: type (delete > extract > move > copy), then longest root, destination on ties; finished jobs skipped. Matching is **O(path depth)**: the index holds normalized sources, deduped source parent dirs and resolved destinations, and `longestMatchingRootLen` walks the row path's ancestors. A linear scan once cost ~135k `filepath.Rel` per frame at 3000 sources and froze the UI.
  - `PanelInsideJobWriteTree` (bottom-right `job_write` indicator, `panel_bottom_indicators.go`) first checks the panel against the job's overall `Destination` (O(1) rejection), then the precise subtree. `PanelTouchedByJobs` needs both directions using the same index.
  - `App.syncJobPathMarks()` runs synchronously after `addTransferJob`/`addFlattenJob`/`enqueueDeleteJob`/`enqueueExtractJob` and queue edits, and on start/finish/blocker events (not per progress tick). `Model.JobsList` is rebuilt for the jobs view only.
  - **New-file marks**: after a completed copy/move/flatten, each panel marks immediate children of the destination (top-level sources only, no plan walk), cleared when leaving that directory (`panel.State.NewFileMarksByDir`, `ui.TopLevelDestNamesFromJob`, `apphandler/jobs` on `EventCompleted`). Each new job promotes the prior batch to `panel.row.mark.new.previous`. Theme keys: `[icons.filelist]` `job`/`new`/`selection_subtree`, `panel.row.mark.*`.
  - **Folder icon kind** resolves in `panellist.ResolveFolderIconKind` + `theme.FolderIcon` (priority: excluded, scanning, open, mount, default). The mount kind compares `localfs.Entry.Dev`/`DevValid` (captured at listing) with the panel's `ListingDevice`; paint must never stat per row (a per-row stat on a saturated NAS blocked the UI for seconds). Find/delete dialog lists pass a zero `PanelIconStripContext`, so directories always render default.
