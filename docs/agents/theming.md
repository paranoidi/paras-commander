# Theming

UI theme TOML only; preview syntax highlighting (Chroma) is a separate system (`preview.md`). Add-a-key procedure: `recipes/add-theme-key.md`.

## Themes tree

- `themes/default.toml` is the only tracked theme. It uses only the 16 ANSI colors: every `[palette]` value is an index 0–15 or `"default"`, every `[roles]` value is a `[palette]` name (except `bg = "default"`) and no style names a hex color (`themes/embed_test.go`), so it follows the terminal's palette; derived tints belong in imported themes. `themes/embed.go` embeds every `*.toml` at the package root, so themes generated locally into `themes/` are embedded in local builds only; `.gitignore` ignores `/themes/*.toml` except `default.toml` and all of `themes/import/`, so they never reach CI or releases. `TestEveryEmbeddedThemeLoads` parses every embedded file, so generated themes are loaded wherever they exist. Disk themes load from the config themes dir; a declared `name` overrides an embedded theme of the same name.
- **Inheritance**: every theme is laid over the embedded `themes/default.toml`, so a theme file holds only what it changes. `parse` (`internal/theme/theme.go`) decodes the file into a `source` (the `[palette]` and `[roles]` tables, the flattened `[icons]` leaves and the flattened style specs; `decodeSource` validates the file on its own, so unknown keys, unknown styles and non-role colours stay load errors) and `source.over` merges it onto the cached default source before `build` resolves the result: `[palette]`, `[roles]` and `[icons]` per key; a style by its flattened key (`menu.dropdown` and `menu.dropdown.accent` are separate keys), replacing the inherited entry whole (no field-level merge, so `{ fg = "fg" }` does not inherit `bold`); a gfx trail (`gfxTrails`: `menu.progress.done|delete|remove.gfx.0..9`) the theme defines any index of replaces the whole inherited trail; `name` comes from the theme. Embedded themes, disk themes (`LoadFile`, `LoadDir`, `findUserTheme`, the theme picker's reload) and the test helpers in `testtheme.go` all go through `parse`; `default.toml` itself is merged over itself. `build` requires every key of `styleKeys` (the style schema; the gfx trails are the only styles outside it), so an incomplete `default.toml` fails to load, and `TestDefaultDefinesEverySchemaKey` checks that it defines every style key, one gradient per trail and every icon key (the `IconKey*` constants and the key families built from a status or state name). There are no Go fallback values for styles or icons: `Theme.icon` / `Theme.iconRune` read the merged `[icons]` value (empty only on a hand-built zero `Theme`). Accessors that test a style against its zero value (`PanelBottomIndicator`, `TerminalTextStyle`, `DialogTextSelectStyle`, `PanelEmptyStyle`, ...) remain for zero `Theme`s.
- **Two colour layers**: `[palette]` holds raw colours only: exactly the 16 ANSI names (`black` … `bright_white`; a value is an index 0–255, `"#rrggbb"` or `"default"`; an unknown key is a load error and a missing key keeps the ANSI index of its name). `[roles]` holds the 38 intents (value: a `[palette]` name, `"#rrggbb"` or `"default"`; an unknown key is a load error). `internal/theme/roles.go` (`roleDefs`) is the single source of truth for the role set and each role's default palette name: a role a theme leaves out is inherited from `themes/default.toml`, which lists every role explicitly, and `TestDefaultThemeRolesEqualGoTable` keeps the two equal. A style's `fg`, `bg` and `icon` (including `gfx` entries) may name only a role: a hue, a palette name, hex or `"default"` is a load error (`style "menu.dropdown": fg "yellow" is not a role; use one of ...`). Colour names from outside the theme file (status-command `color`) go through `Theme.ResolveColor`: a role name first, then a palette name, then `#rrggbb` or `default`. Roles by group: backgrounds `bg` (the base background of every cell drawn without a background of its own, applied by `frameScreen` (`architecture.md`); also the dark well: input and list backgrounds, tracks; `themes/default.toml` sets it to `"default"` so the default theme keeps the terminal's own background, and `roleDefs` writes `"default"` where a palette name would go), `surface` (dialog fill, chips, bar tracks, carousel header, speed pill), `header_bg` (panel headers; the active one), `inactive_header_bg` (the inactive panel header), `menu_bg` (menu dropdown fill and frame), `leader_bg` (leader menu fill; `black` in the default theme so the menu stands apart from the panels drawn on the terminal background), `focus_bg` / `focus_fg` (the focused item: open menu-bar title, selected pulldown entry, selected completion entry, hovered footer entry), `button_bg` / `button_focus_bg` (face of an unfocused / the focused dialog button; text on the focused one is `focus_fg`), `file_cursor_bg` / `file_cursor_fg` (cursor row of an active file list: panels and dedup), `file_cursor_dim` (cursor row of an inactive, carousel-inactive or blocked panel), `highlight_bg` (clickable part of the hovered footer entry, disk usage cursor on a selected row, mount mark), `range_bg` / `range_unselect_bg` (pending range select / unselect tints), `inverse_bg` (light boxes: tooltips, info and sweep toasts); text `fg`, `fg_strong` (headers, hints, active input, progress labels), `muted`, `faint` (barely visible text on `bg` / `surface`: disabled options, remaining progress), `info_columns` (file-list info columns: size, mtime, permissions, meta), `ink` (dark text on a coloured fill); structure `accent` (shortcut letters, key hints, match highlights; fuzzy matching never uses a state role), `accent_alt` (dialog shortcut letters that need Alt: `dialog.accent_alt` and the focused buttons' `<state>.accent_alt`), `primary` (active panel frame, info icon, git modified, tagged), `inactive_frame` (inactive panel frame), `directory`, `symlink`, `selected`; states `info`, `success`, `success_strong`, `warning`, `attention`, `danger`, `error`, `special`. A new style picks the role by meaning, not by hue: any new style with one of those meanings uses the role.
- `themes/import/` (gitignored, local only) holds the importer scripts; `themes/import/src/` holds the source schemes in Alacritty format, which pc cannot load directly. `import_alacritty.py` (stdlib Python) turns them into pc themes; `build.sh [--all | --chroma] [OUT_DIR]` imports only the hand-tuned schemes in `src/` (those with a `tune/<name>.toml`; currently the four Catppuccin flavours, whose `src/` files are hand-written from the official palette with a `[colors.named]` table) into `themes/` by default, every scheme with `--all`, or only those whose header says `import_chroma.py` made them with `--chroma`; it overwrites each built theme, leaves other themes' outputs alone (`clear_all.sh` removes every `src/`-generated theme), and then runs `--check`. `import_alacritty.py --check <generated files>` lists the styles still below target and exits 1 if any; `--selftest` runs the built-in assertions; `--out DIR` redirects output (default `themes/`); `--tune-dir DIR` redirects the tune files. `themes/trash/` is discards; `themes/preview/` is Chroma XML.
- **Chroma import**: `import_chroma.py <style>...` derives an Alacritty scheme into `src/` from a Chroma syntax style in the Go module cache (version from `go.mod`), mapping token colors to ANSI slots (Error→red, String→green, Class→yellow, Function→blue, Keyword→magenta, Builtin→cyan, Comment→bright_black, LineHighlight bg→black; bright variants equal normal; a style without a `Background` is white with black text, as in Pygments). A style with a LineHighlight background also gets `[colors.selection]` (that background, text = foreground). `--all` converts every style not already in `src/` and not in the script's `SKIP` set (monochrome styles and near-duplicates of Alacritty schemes). An existing file is never overwritten without `--force`, and `--force` still refuses a file whose header is not `# Generated by import_chroma.py` (`--all --force` regenerates every Chroma-made scheme and skips the rest).
- **Generation**: the importer uses `default.toml` as its template, parsed line by line because the template is not strict TOML, and swaps only `[palette]` and the `[roles]` values, then writes only what differs from the template: `name`, a header comment, `[palette]`, `[roles]` (every role) and the style or icon lines that repair or tuning changed (about 70 lines for a typical theme); everything else is inherited from `default.toml` at load time, so a new key in `default.toml` needs no regeneration. Repair and `--check` evaluate the merged theme (`merge_lines`: the template lines with the generated file's lines laid over them per section and key). The generated `[palette]` is the scheme's own 16 ANSI colors unmodified (a missing bright colour repeats its normal one). The importer never writes a blended colour: every hex it emits is in the scheme's candidate set (`candidate_set`): the 16 ANSI colours, primary foreground/background, the hex `[colors.selection]` background and text, and every hex value of an optional `[colors.named]` table in the source scheme (the scheme's full palette; the four Catppuccin schemes define 26 colours there, other schemes have only the ~18 base colours). Mixes (OKLab) only compute targets, and the role gets the candidate nearest the target in OKLab. A scheme too weak for its candidates is fixed per theme with a tune file, not by blending. `[roles]` keeps the template's palette name for every role the importer has no better value for, and writes a hex candidate for the derived ones: `fg` / `bg` (primary foreground/background), `surface` (target bg mixed 12% toward fg), `muted` (nearest the fg/bg midpoint among candidates with at least 3:1 against `bg` and `surface`, else the best-contrast candidate), `faint` (nearest the bg/muted midpoint), `range_bg` / `range_unselect_bg` (targets bg mixed 20% toward the scheme's yellow / red), `file_cursor_dim` (target bg mixed 18% toward fg, among candidates at least OKLab 0.05 from `file_cursor_bg`), `file_cursor_bg` / `file_cursor_fg` (the same picks as `focus_bg` / `focus_fg`; active panel and dedup cursor rows), `focus_bg` / `focus_fg` (the focused item: the open menu-bar title, the selected pulldown entry, the selected path-completion item and its match, the hovered footer entry), `button_bg` (`bg` itself: the unfocused dialog button face, a well in the dialog surface, distinct from `focus_bg`), `button_focus_bg` (the same pick as `focus_bg`, and a tune file's `focus_bg` carries over to it unless the file sets `button_focus_bg` itself), `accent_alt` (the same pick as `accent`; the Catppuccin tune files set rosewater), `header_bg` (target bg mixed 35% toward `accent`, never the colour `focus_bg` took while another candidate is left, so headers never look like the cursor row; panel headers), `menu_bg` (the same pick as `header_bg`; menu dropdown fill and frame), `leader_bg` (one step darker than `bg`: the nearest candidate that is darker and at least OKLab 0.05 from it, else the nearest distinct one; leader menu fill, apart from the panels drawn on `bg`), `inactive_header_bg` (target bg mixed 35% toward fg, among candidates at least `DISTINCT_BG_DELTA` (OKLab 0.05) from `file_cursor_dim`, so the inactive panel header is a clear step past its cursor row, as `bright_black` is past `black` in the default theme), `accent` and `ink`. The background roles `surface`, `faint`, `range_bg`, `range_unselect_bg`, `file_cursor_dim` and `header_bg` exclude `bg` and every candidate within OKLab distance 0.02 of it so they stay visible, and fall back to `bg` when nothing is left. `focus_bg` is the scheme's `[colors.selection] background` unless that is nearer `fg` than `bg` (an inverted selection, then the selection text is ignored too), else the candidate nearest bg mixed 35% toward the scheme's blue; either way it needs 1.3:1 and an OKLab distance of 0.05 against `bg`, otherwise the nearest candidate that does. `focus_fg` is the first of `[colors.selection] text` (`CellForeground` / `CellBackground` count as absent), fg, bg, black and bright white that has 4.5:1 on `focus_bg`, else the best-contrast candidate. `accent` is the most chromatic (OKLCH) of the scheme's magenta, blue, cyan and yellow slots that has 3:1 against `bg`, else magenta (named colours are not candidates: a red or peach would win; a scheme wanting e.g. Catppuccin mauve sets it in its tune file); `ink` is the candidate with the best worst-case contrast on the scheme's green, yellow, red, white and bright blue (the colours text on a fill is drawn over).
- **Contrast repair**: it works on the merged theme (default plus generated lines). Styles may name only roles, so the repair pass repicks role colours from the candidate set, or swaps which role a style names, never writes a per-style colour and never synthesizes a colour. For each style with an `fg` it finds the effective background role (own `bg`, else the sibling `fill`/`track` for `label.on_fill`/`label.on_track`, else the `_CTX` prefix table in the script for dialog, dropdown, tooltip and leader-menu text, else `bg`) and a target of 4.5:1 (3.0 for frame/track/thumb/separator/connector/icon/gfx/mark/placeholder/disabled and similar names); only styles readable in the default theme take part. Phases: (1) every movable text role is repicked against the background roles `bg`, `surface`, `header_bg`, `inactive_header_bg`, `menu_bg`, `leader_bg`, `focus_bg`, `button_bg`, `button_focus_bg`, `file_cursor_bg`, `file_cursor_dim`, `range_bg` and `range_unselect_bg`, which never move (nor does `ink`, picked to read on the fills, nor `faint`, which is dim by design and exempt from the check): the candidate nearest (OKLab) the role's current colour that has zero shortfall and is in the same hue family (OKLCH hue within 30° and at least half the role's chroma, so a greyed-out version of the hue does not count; or neutral, chroma below 0.04, for a neutral role); when none qualifies the role keeps its colour (a red stays red) and phase 2 swaps the fg of just the styles still below target; (2) a style below 0.9 of its target (`NEAR_MISS`; a near miss keeps its colour and is only reported) gets the first of `fg`, `fg_strong`, `ink`, `focus_fg`, `bg` that reads on its background, written as `fg = "<role>"` in the style line, and a `<x>.accent` style left with the same fg as `<x>` (shortcut letters indistinguishable from their text, e.g. `menu.dropdown.accent`) takes `accent` when that reaches 0.9 of target; (3) `inverse_bg` and `highlight_bg` are repicked by the same rule, over the constraints they take part in as fill or text; (4) styles are swapped again. A moved role is written as hex. Styles whose foreground equals their background in the default theme (`menu.progress.remaining`, excluded folder icons) and `cap`, `start` and `end` styles (the speed pill and dialog button caps: their fg is the neighbouring fill by design) are never touched; `icon` fields are not repaired. `import_alacritty.py --check` reports every style still below target, and every `_DISTINCT_BGS` pair of background roles drawn next to each other (a panel title bar and the cursor row under it: `header_bg` / `file_cursor_bg`, `inactive_header_bg` / `file_cursor_dim`; the active and inactive cursor rows: `file_cursor_bg` / `file_cursor_dim`; the leader menu and the panels under it: `leader_bg` / `bg`) closer than OKLab 0.05 (distance rather than contrast, so a blue bar over a grey row of the same lightness passes), and exits 1 on any; schemes whose candidate set has no colour that reaches the target on a derived or selection background keep failing styles, which are fixed with a tune file rather than by loosening targets.
- **Hand tuning**: `themes/import/tune/<name>.toml` (a separate directory so `src/*.toml` globs do not see it) holds only the changed lines, in pc theme syntax read line by line: `[palette]` and `[roles]` entries replace or add a value there, and a `key = { ... }` line replaces the line with the same key in the same section, or is appended to it (the section is created at the end when missing), with a warning because the template does not define it. `[palette]` and `[roles]` overrides are applied after generation and before the repair pass, which checks styles against them and never moves a tuned role (nothing derived from a replaced colour, such as a snap target, is recomputed); style overrides are applied last and verbatim, so the repair pass never rewrites a tuned line. Each tuned style line gets a trailing `# tuned` comment; a top-level `tuned = true` becomes a `# tuned` header comment (an unknown top-level key would be rejected by the theme loader, so it is never emitted). `--check` reports tuned styles below target as `tuned` warnings that do not fail the run. `build.sh --watch NAME` builds only `src/NAME.toml`, then polls (0.5 s, no inotify) `src/NAME.toml`, `tune/NAME.toml` (it may appear later), `default.toml` and `import_alacritty.py` and rebuilds that one theme on a change, printing a timestamped line with the repaired count and check result; the theme picker's auto reload (on by default) picks the rebuilt file up while the picker is open, so pc need not restart.
- A new key goes into `themes/default.toml` with a role-based value (and into `styleKeys` or the `IconKey*` constants); every other theme inherits it, so no per-theme update and no Go fallback value is needed. A theme sets the key only to differ from the default.
- Which TOML fields reach pixels must be checked against resolution in `internal/theme` and use in `internal/ui`. Regression tests for `AccentIconStyle` and dialog title composition: `internal/ui/dialog/internal/draw/`.
- Derived, not keyed: `theme.CutMarkStyle` (listing name cut points, `panels.md`) swaps the cell's own foreground for its counterpart shade (ANSI 0–7 ↔ 8–15, bold ANSI → 0–7 without bold since bold-is-bright terminals already show it bright, RGB moved `cutMarkShade` toward white or black, default foreground toggles bold), so it follows every row style without a theme key.

## Key groups

- **Status**: `[status]` holds one style per job status (`scanning`, `queued`, `running`, `paused`, `decision`, `failed`, `canceling`, `canceled`, `completed`; `Theme.Status*`, looked up by status string with `Theme.StatusStyle` / `StatusStyleOn`). Every job-status color reads it: the menu-bar job strip, the Jobs view icon and status columns and the active Operations row, the file-list queued mark (`status.queued`) and Commands view runs (`running`, `completed`, `failed`). `scanning` (`Theme.StatusScanning`) is also the one work-in-progress style: disk-scan-pending folder icons, the slow-load working icon, the preview-loading icon, the menu-bar and preview spinners and the fileindex `scanning` row state. There are no per-site status keys.
- **Panel**: `[panel.active]`, `[panel.inactive]`, `[panel.blocked]` plus shared subtables `[panel]` (text, hint), `[panel.row]` (directory/file/info/selected/symlink, `tree.connector`, `cursor.range`/`cursor.range.selected` for the cursor row during a pending range select, shared by all chrome states; `range` and `range.unselect`, background only (the roles `range_bg` / `range_unselect_bg`), for the other rows a pending range covers when it selects and when a right-button drag unselects them; `info` styles size/mtime/permissions/meta off the cursor row; on the cursor row they take the cursor style the row would have unselected (`Theme.PanelListingCursorInfoStyle`, applied by `Theme.PanelListingInfoStyle`), so a selected entry's columns never take the selected colour; a cursor style without `fg` (the inactive panel's dim bar) keeps `info` on the cursor background instead of the entry-type colour, and a meta alert there is the cursor icon colour in bold), `[panel.row.mark]` (suffix marks: selection_subtree, new(.previous), renamed, no_permission, pinned, range_anchor, other_match(.cursor), job(.read/.move/.delete/.removing); a job waiting on a decision uses `status.decision`), `[panel.icon]` (`broken_link`: file icon of a symlink whose target does not resolve), `[panel.icon.folder]` (open, mount, scanning, excluded; no `default`), `[panel.status]` (bottom-border segments: sync, quick_view, selections, selection_size, dotfiles_hidden, gitignore, stash, find_parked, other_panel), `[panel.git]`, `[panel.fileindex]` (one fg per browse-with-fileindex state except `scanning` and `checking`, which `Theme.PanelFileIndexStyle` takes from `status.scanning`; the states are `fileIndexStates` in `internal/theme/panel_fileindex_style.go`), `[panel.scrollbar]` (track, thumb, `match` marking fullscreen-preview search matches; glyph is `[icons.scrollbar] match`, `Theme.IconScrollbarMatch`), `[panel.usage]`. The `icon` field is allowed only on panel cursor row styles (a plain role string; values land in `Theme.PanelFileIconFG`) and the six disk-usage bar styles (`panel.usage.normal`/`selected`, `panel.{active,inactive}.usage.cursor(.selected)`, `barKeyNormal` ... in `internal/theme/disk_usage_style.go`), where it is a table of per-group colors written as dotted keys (`normal = { fg = "fg", bg = "surface", icon.file = "faint", icon.git = "faint" }`, which TOML decodes as `icon = { file = ..., git = ... }`). The groups are the `BarIconGroup` constants (`folder`, `folder_expanded`, `folder_scanning`, `folder_open`, `folder_mount`, `folder_excluded`, `file`, `preview_loading`, `fileindex`, `git`, `suffix`); an unknown group, a string on a bar style, a table on a cursor row style and a non-role colour are load errors (`styleSpec.IconGroups` holds the decoded table, `build` validates it into `Theme.DiskUsageBarIconFG[barKey][group]`). A style overriding a bar style replaces its group table whole, like every other style field (`source.over` has no field-level merge), so a theme restating `panel.usage.normal` lists every group it wants. Lookup is `Theme.DiskUsageBarIconColor(barKey, group)`; `Theme.DiskUsageBarIconKey` returns the bar style key when it lists any group. On a bar cell a listed group colour wins, an unlisted group keeps the colour the icon has off the bar (the cursor row's `icon`, else the icon's own colour; `panels.md`, Disk usage). The default theme lists `file`, `folder_open`, `folder_mount`, `folder_excluded`, `fileindex`, `git` and `suffix` as `faint` on `panel.usage.normal` and `selected` only, because `panel.inactive.usage.cursor` has a black background, and leaves the plain, expanded and scanning folder icons and the preview-loading icon unlisted so they stay readable on the bar. `[panel.dedup]` uses `row.mark.keep_subtree` and `potential` (the potential-duplicate icon, `dedup.potential` under `[icons.dedup]`). File rows use `panel.row.file`; non-listing body copy uses `panel.text` / `panel.blocked.text`. `panel.empty` (a hand-built zero `Theme` gets ANSI bright black from `Theme.PanelEmptyStyle`) styles the empty-list text of the Jobs, Commands and Messages views (list, Details placeholder, Operations and stdout/stderr panes); the text itself is `[icons] empty` (`Theme.EmptyText`, plain text returned with or without Nerd Font icons). It is drawn on the panel content background. `[icons.fileindex_state]` holds the browse-with-fileindex state glyphs (`Theme.IconFileIndexState`, one rune, ASCII letters without Nerd Font icons in `fileIndexStates`; it is `fileindex_state`, not `fileindex`, because `[icons] fileindex` is already the path-prefix glyph). `[panel.meta]` (`warn`, `critical`) colors meta alert cells.
- **Menu**: `[menu]` (detail, status, dropdown*; `dropdown` stays dotted because `menu.dropdown` is both leaf and parent), `[menu.bar]`, `[menu.progress]`, `[menu.speed]`. `menu.status` styles the status-command text and `menu.status.separator` the `[icons.menu.status]` `separator` glyph between segments (`architecture.md`). `menu.progress.done.gfx.0..9`, `menu.progress.delete.gfx.0..9` (delete jobs) and `menu.progress.remove.gfx.0..9` (a move removing its copied sources) are light-bar gradients (`gfx.0` = head); a theme defining any index of a trail replaces the whole inherited trail, and the renderer uses the done gradient for a delete job and the delete (then done) gradient for a removing move when a hand-built `Theme` leaves one empty. `[menu.speed]` `cap`/`text` and `[icons.menu.speed]` `left`/`right` style and cap the speed pill.
- **Dialog**: `[dialog]` chrome (frame/surface/text/title/accent, `accent_alt`: the shortcut letter that needs Alt; `text_select`: background-only highlight for selectable text spans, merged under the span's `dialog.option.*` foreground; `Theme.DialogTextSelectStyle` uses the `dialog.surface` background on a zero `Theme`), `[dialog.button]` (`active` / `inactive` / `active_destructive`, each with `<state>.start` / `<state>.end` cap colors (fg / bg over the state's, non-space cap runes only); `active.accent` / `active_destructive.accent` and their `accent_alt` forms are the focused button's shortcut letter, plain and when it needs Alt (fg and bold; the importer checks them against that button's bg via `_CTX`); the cap strings are `[icons.dialog.button]`), `[dialog.input]`, `[dialog.option]`, `[dialog.status]` (`selection_size`), `[dialog.progress]`, `[dialog.massrename]`. `[tooltip]`: the dialog tooltip box (`text`, fg + bg) and its info icon (`info`, foreground only, merged onto the box by `Theme.TooltipInfoStyle`; the glyph is `[icons.dialog] info`). `[icons.dialog.checkbox]` holds `checked`, `unchecked` and `mixed` (the tri-state marker of a `CellColumns` list). Styling rules (option rows foreground-only, input placeholder pairs): `dialogs.md`.
- **Preview**: `[preview]` `search_icon` (foreground only) colours the F3 preview search bar's leading icon (`[icons.search] icon`, stored under the flattened key `search`); `Theme.PreviewSearchIconStyle` puts its foreground on the bar's own row style, ignoring any `bg`, and returns the row style unchanged on a zero `Theme`. The find dialog's `dialog.search_icon` is not used there.
- **Jobs**: `[jobs]` `row` (jobs list row text), `header` / `header.inactive` (Queue column-header row on the panel background with the Queue pane focused / not; the blocked chrome keeps `panel.blocked.header`), `row.hover` (the Jobs, Commands, Messages, Compare and Duplicates list row under the mouse pointer, and the background of a dialog list row under it, as `row` is their row base: background and plain text under the status colors), `[jobs.detail]` `label`/`text`/`plot` (Details panel: the `Label:` prefix, other text, and throughput chart rows), `[jobs.progress]` (plus `[jobs.progress.inactive]` for paused/canceled rows and `[jobs.progress.completed]` `fill` for completed rows (always a full bar, so it also styles the percentage text), chosen by `Theme.JobsProgressStyles`), `[jobs.operations]` `success`/`failed`/`skipped` (Operations pane result icons and the Details `Files:` counts, `Theme.JobsOperationStyle`/`JobsOperationOn` keyed by `theme.JobsOperationSuccess`/`Failed`/`Skipped`) with glyphs `[icons.jobs.operations]` `success`/`failed`/`skipped`/`source_deleted` (`Theme.IconJobsOperation`; one cell wide). `source_deleted` is icon-only (`theme.JobsOperationSourceDeleted`, chosen by `ui.JobOperation.IconKey` for a row with `oplog.Record.SourceDeleted`); the row keeps the skipped style. `[icons.dialog] missing` is the trailing mark on missing History/bookmark/Pin rows; `[icons.dialog] zoxide` / `history` prefix History rows by source — zoxide vs panel history (`Theme.IconDialogZoxide` / `Theme.IconDialogHistory`, `z` / `h` without Nerd Font icons, colored `dialog.option.active` on the cursor row, else `dialog.option.inactive`). `[icons.dialog] depth` marks the indexing depth in the Find / Jump title and leads the max-depth input on the query row (`Theme.IconDialogDepth`; the word `Depth` without Nerd Font icons). `[icons.dialog.completion]` `create_dir` / `enter` wrap the path completion dropdown's Create directory row (`Theme.IconDialogCompletionCreate`, none without Nerd Font icons; `Theme.IconDialogCompletionEnter`, `(Enter)` without; composed by `createDirRowLabel` at paint, which also widens the box). `[icons.dialog] criteria` leads the Find dialog's advanced-criteria summary on the separator above the results (`Theme.IconDialogCriteria`; `Criteria:` without Nerd Font icons). `[icons.filelist]` holds row-suffix glyphs (`selection_subtree`, `new`, `renamed`, `other_match`, `range_anchor`, `no_permission`, `job`, `move`, `delete`, `move_removing` (a move source being deleted after its copy), `preview_loading`); the queued suffix glyph is `[icons.jobs.list] queued` (`Theme.IconFilelistQueued`), colored by `status.queued`. `[icons.jobs.list] sources_collapsed` / `sources_expanded` is the expander appended to a multi-source job's Queue Type (`Theme.IconJobsListSources`). `[icons] fileindex` (`Theme.IconFileIndex`, default nf-md-database, none without Nerd Font icons) replaces `fileindex` in displayed `fileindex://` paths. `[icons.commands] command` is the Commands-view row command-line glyph (`Theme.IconCommandsCommand`; `$` when Nerd Font icons are off).
- **Compare**: `[compare]` `hashing` (pending disk icon while a worker reads a file), `equal` (`=` icon), `content_diff` (`≠` icon). `[icons.compare]` holds the status glyphs (`equal`, `relocated`, `primary_only`, `secondary_only`, `content_diff`, `pending`, `error`) plus `name_left` / `name_right` (`→` / `←`), which replace `relocated` on a row with a per-row merge name choice (`Theme.IconCompareNameLeft`/`Right`).
- **Message**: `[message]` `info`/`warn`/`error` style the toast banner; `success` styles `MessageUrgencySuccess` toasts, which the banner and Messages log prefix with `[icons.message] success` (`Theme.IconMessageSuccess`, none without Nerd Font icons); `sweep` styles the leading-edge cell while a new warn, error or success toast sweeps in.
- **Footer**: `[footer]` `key`/`label`/`label.shift` and `hover` (the entry under the mouse pointer) and `hover.active` (its part a click presses: key and main hint, or the Shift word; drawn on `highlight_bg` while the rest of the entry is on `focus_bg`, so the two parts differ by background colour in every theme).
- **Terminal**: `terminal.text` styles the embedded terminal panel (`internal/ui/terminal_panel_render.go`). `Theme.TerminalTextStyle()` falls back to `panel.text` on a zero `Theme`. There are no separator keys.

## Theme picker dialog

Typing fuzzy-filters the themes; navigating live-previews the highlighted theme once motion settles; Enter applies and persists `theme` to XDG `config.toml`; Esc restores the previous theme; the auto reload toggle (`theme.toggle-auto-reload`, on at open) re-previews the highlighted theme when its file changes on disk, and the preview pages cycle with `theme.next-preview` / `theme.prev-preview` (wrapping; the picker opens on page 1; failures surface as a status message or message dialog).

- **Spec**: `ThemeDialogView` (`internal/ui/dialog/theme_dialog_render.go`) is a `dlg` dialog (`dialogs.md`, Lists): a `ThemeFilter` input (search icon) driving a radio-marked `ThemeList` (the cursor row's radio is lit, fuzzy matches highlighted), next to a reserved preview pane (`themePreviewRows` tall); on a short screen the list and the pane shrink together (`dlg.FitSpec`). `App.syncThemeDialogRanks` ranks `Choices` labels into `ThemeDialogState.Ranked` / `MatchRanges` (`filterlist.SyncRanks`); `Selected` indexes `Ranked` and `ListScroll` follows it (`EnsureThemeListScroll`). Each list move (`dlg.EventListMove`) or query edit arms `App.themePreviewDebounce` (`[ui].key_repeat_debounce_ms`; 0 previews at once), whose `themePreviewFlushPayload` resolves and applies the theme, so held arrow keys load only the theme they stop on. Enter in the filter or OK applies, Cancel / Esc restore. `ThemeDialogState.Focus` is `ThemeFilter`, `dlg.OK` or `dlg.Cancel`.
- **Preview pane**: `drawThemePreview` paints the sample inputs, checkboxes and two button rows, the second with `Theme.WithAltMnemonics` (page 3 only; the pane has no horizontal rules) in the previewed theme, plus a sample tooltip attached to the first active input (placed and painted by `dlg.PaintTooltipFor`, the helper the engine's focused-widget tooltip uses, drawn last so it may overlay the rows below) (the Unselected checkbox draws its mnemonic in `dialog.accent_alt`, the Selected one in `dialog.accent`), the vertical rule and its frame tees after `dlg.Draw`. A page's rect is the whole right column inside the frame: `themePreviewCtx.y` is the first content row, `maxY` the button separator (a short terminal cuts the page off there), `left` the cell after the vertical rule and `width` up to the right border; any margin is the page's own choice.
- **Width and rows**: the dialog asks for `listWidth + 10 + 60` columns (`previewWidthMin`) and, being unclamped, shrinks to the terminal; `themePreviewRows()` is the pane height the dialog asks for: the tallest preview page's rows (`themePreviewPageRows()`), so cycling pages never resizes the dialog. Everything past the outer separator is cut off, so a short terminal shows only the first samples.
- **Preview pages**: `ThemeDialogState.Page` (0-based) picks the page painted into the pane. `themePreviewPages` (`theme_dialog_render.go`) is the ordered list of `themePreviewPage{rows, appBG, paint}` (`appBG` makes `drawThemePreview` fill the whole page rect with the Jobs view's content background, `PanelActiveSurface`'s background as `auxPanelContentBG` returns it, before painting; false keeps the dialog surface); the page count (`ThemePreviewPageCount`, used by the cycle actions and the footer's "Preview n/N") and the pane height are derived from it. **To add a page, append one entry**: its `rows`, `appBG` and a `paint(*themePreviewCtx)` (geometry in the ctx; set `activeInput` to get the sample tooltip). Page 3 (`paintThemeInputPage`) is the sample inputs with the tooltip under the active one, the path autocomplete sample (an active input with `drawPathCompletionDropdown` open over `themeSampleCompletionItems`, first selected; the dropdown is skipped when it would pass `maxY`), two checkboxes and the sample buttons row (Selected, Unselected and the destructive Delete, drawn with the focused-destructive style through `draw.DrawDialogButton`; Delete is left out when the pane cannot hold all three). Page 2 (`paintThemeAppPage`, `appBG`) is the app samples as one area on the Jobs view's content background (the job rows and progress labels use it too), a menu bar sample (`ThemeAppMenuRows`), the focused Queue column header and one row per job status (`ThemeAppJobRows`), and the unfocused Queue header and three progress bars (`ThemeAppProgressRows`), with a blank row between sections (`themeAppSectionGaps`). Package `dialog` cannot import `ui`, so `DrawThemeDialog` takes `ThemeAppSamples` (three `ThemeSamplePainter`s) and `ui.themeAppSamples` (`theme_preview_samples.go`) supplies them: `drawMenuBar` + `drawPulldownMenu` (called with a synthetic `Layout` whose `Footer.Y` is the pane's cut-off row) on two `menu.Definition`s, `drawJobsListJobRow` for each `jobs.Status` fed fixed `JobEntry` snapshots (running and queued carry a `QueueETA`, running a `DisplaySpeedBPS`; the helper decides what each status shows) drawn at the fixed clock `themeSampleNow`, and `drawJobsProgressBar` with `Theme.JobsProgressStyles` for the active (running), inactive (paused) and completed variants. Job rows need `themeSampleJobWidth` columns and are skipped on a narrower pane. Page 1 (`paintThemePanelPage`, `appBG`, `ThemePanelRows` tall) is a whole file panel from `ThemeAppSamples.Panel`, then below it the last `ThemeInactivePanelRows` rows: the same listing as the inactive panel, scrolled so its cursor sits on an unselected file between the broken link and two selected files (`drawThemeSampleListing` draws both): `ui.drawThemeSamplePanel` (`theme_preview_panel.go`) runs the real `drawPanel` on a fixed `panel.State` (entries under a non-existent `/srv/meadow`, fixed mtimes, no disk access, no clock) with `themeSamplePanelDiskPainter` as the `DiskUsagePainter`, so frame, header, git column, icons, size/date columns, disk usage bars and the row marks are the app's own. It shows the `..` row, folders (a disk usage bar, one still scanning, one excluded), a symlink and a broken one, files of several types (one executable), selected rows, the cursor on a selected row, pinned, new and renamed marks, queued and running (move, delete) job marks, no-permission, and git modified / new / ignored cells. Each panel is closed early on a short pane (its height is clipped to `maxY`). Not shown: a running copy mark, the tree layout and carousel, find/index states, and meta columns, which need live app state.
- **Auto reload**: `ThemeDialogState.AutoReload` (on when the dialog opens) runs `App.themeWatch` (`theme_watch.go`) only while the dialog is open: one goroutine with a `themeWatchInterval` ticker, stopped by `stopThemeWatch` on toggle-off, close, apply and cancel. `themeWatcher.check` stats the highlighted theme's file (resolved once per highlighted theme with `theme.UserThemePath`; embedded themes have none, so are not polled) and posts `themeFileChangedPayload` when its modification time or size differs from the last revision seen, once per distinct revision (so a broken save reports its error once). The event loop answers with `previewThemeAtSelection`, the same path the toggle takes when it turns on. `App.setThemeWatchName` keeps the goroutine on the highlighted theme; tests replace the stat through `App.themeWatchStat`.
